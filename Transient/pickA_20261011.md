## Verdict: the patches were fine; the LINT was wrong

`effective_def_lint.py`'s simulator (`costlist_resolve_check.Sim.apply`) honoured `<success>` only on a
TOP-LEVEL op (the lint's own exemption check). A nested op with no match returned False, so a Sequence whose
inner `PatchOperationRemove ... <success>Always</success>` found nothing (xenotypeSet / useFactionXenotypes /
the urban-ruins label, all absent in source by design) failed the whole Sequence, and FindMod with it.

The engine does the opposite: `Verse.PatchOperation.Apply` (RimSage, decompiled 1.6) applies `success`
(Always -> true, Never -> false, Invert -> !result) to EVERY op, nested included. Both patch files' inner
targets exist in source (Core `AncientSoldier` has `<label>`; VQE-Ancients 3618306875 `VQE_Experiment` has
fixedChild/fixedAdultBackstories + forcedTraits, `VQE_Patient` has backstoryFiltersOverride).

## Fix
`src/RimMandrake/Utils/costlist_resolve_check.py`: `Sim.apply` now wraps `apply_worker` and applies the
success mode, matching the engine. No patch XML changed.
