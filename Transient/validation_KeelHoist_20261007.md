## Defect fixed
- `RM_KeelHoist.Arrive`, drop path: `transit.TryDrop(...)` can return false (nowhere to place the thing) but the thing stays in the owner, while the code still removed its `arriveAt` / `goingUp` / `fromLabel` entries. The lists then run shorter than the owner; on the next tick `i < arriveAt.Count` is false so the orphan "arrives" every tick and `arriveAt.RemoveAt(i)` throws ArgumentOutOfRange inside `Tick`, wedging the whole hoist. Now a failed drop calls `sched.Defer(i, now + 625)` and keeps the entry with its thing.
