## (2) Direct writes to ledger shards

**What existed.** `queue_lint.py` (PreToolUse, Bash + Write/Edit) refuses writes to
`ledger/events.jsonl` and `ledger/events/*.jsonl`, but only these forms: a LITERAL path after
`>`/`>>`, `tee`, `cp`, `mv`, `rm`, `sed -i`, `dd of=`, a python `open(<literal>, 'w'|'a')`, and
Write/Edit. It misses:
- a path held in a variable;
- a `cd` into the events dir;
- `Path(...).open('a')`, `write_text`;
- python heredocs, `sh -c`, `find -exec`, `eval`.

It also does not cover `infrastructure/state/art/events/**` or `code_review/*.jsonl` at all.
`infrastructure/githooks/*` holds only pre-push.

**New hook** `D:\Luke\dev\RimMandrake\.claude\hooks\block_ledger_shard_write.py`, registered on Bash and on
Write|Edit|MultiEdit|NotebookEdit. It reuses `block_transcript_tamper.py`'s analyser (variables,
for-loops, cd, symlinks, globs, nested shells, heredocs, python by `ast`) and protects these paths:
- `ledger/events.jsonl` and `ledger/events/**`;
- `art/events/**`, including `archive/`;
- `code_review/**.jsonl`.

The allow-list, matched by command prefix: `rimflow`, `rimflow/cli.py`, `./game`,
`ledger_sync.py`, `art.py rotate`, `repair_torn_ledger.py`, `code_review_status.py`. A
redirect is still checked whoever runs it, so `rimflow show > shard` is refused. `git` is
not treated as a writer: `git checkout <rev> -- shard` is the sanctioned restore, and the
refusal message says so.

Two places where it is looser than the transcript hook, so that ordinary work is not
refused. Every commit pathspec and census names a ledger path:
- A target that cannot be resolved is refused only if the token itself names a shard, the
  cwd is inside a shard dir, or a `find` over a shard dir feeds it.
- An unknown python value becomes a `*` wildcard, so the literal parts decide.
  `f"…/events/{seat}.jsonl"` is refused; `f"/tmp/union_{name}"` is not.

**Backstop.** Pre-push `ledger_lint.py` runs from `infrastructure/githooks/pre-push` and from
`block_ledger_lint.py`. It refuses NOT_APPEND (a line on origin edited or removed in place),
torn lines and DUP_DIFFERENT, but only for `ledger/events/` and `code_review/`. **A forged line
APPENDED to a shard is the legal shape and passes it, and it does not read `art/events/` at
all.** So the lint catches rewrites and deletions, never a forged append.

## Still open

- **A script FILE that appends to a shard** (`python3 forge.py`), or a path assembled from
  fragments, is invisible to every command-text hook. The same is true of a python heredoc
  whose shard path arrives as `sys.argv`. Closing this would need a check at READ time, a
  signature or session-bound proof on each event, which nothing has.
- **The pre-push lint passes a forged append** and never reads the art ledger. Extending
  `SHARD_DIRS` to `infrastructure/state/art/events` would at least catch art-ledger rewrites.
- **The review-sheet channel** (`enact`/`ingest` reading a `*.decisions.json`) trusts the
  decisions file. An agent that writes one can mint owner rulings with no transcript involved.
  `block_hand_edited_sheet.py` exists for sheets; whether it covers decisions files was not
  measured in this pass.
- **No art-ledger repair tool.** Before, torn or duplicated art events were fixed by hand. The
  new hook refuses that, so the next torn art shard needs one built.
- The pickAQ residuals stand: a launch outside the seat cgroup with a scrubbed environment
  looks like the owner's terminal, and an agent can edit the verifier (visible in git).
