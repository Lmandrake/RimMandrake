## fixes
1. **Cleanup after a FAIL.** `t.bridge_call` is a no-op once a component fails or goes UNMEASURED, so every
   `finally` that put out fires or unlocked weather did nothing at exactly the moment it was needed. Every
   stateful chain now carries `@_teardown(fire=, weather=)`: weather unlock, whole-map extinguish and the
   settings restore go straight to the session.
2. **Fulgurite chain.**
   - The isolation set now goes OFF before the storm, so burn-line and fire-hawk fires cannot read as strikes.
   - The live `fulguriteChance` is read, not 0.35.
   - Fulgurite is counted as summed `stackCount` and refuses a truncated listing, so a merge into an existing stack counts.
   - The sand fraction is taken over non-water cells. RM_FE_ sand counts only when `PyrelandsMechanicsGate.On` reads True.
   - The docstring gives the argument for the bound: strikes are uniform over standable unroofed cells, so sand strikes thin all strikes independently of which strikes lit a fire.
   - The strike floor stays "windows with any fire". A fire-cluster count was tried and dropped, because a burning animal that runs carries one strike's fire across the map.
3. **Restore failure decides the verdict.** Any teardown step that fails now appends a FAIL component, `<chain>/teardown`, and reports it through `_on_finding`. That component exists only when a live run fails to restore. The declared components are unchanged (33).
4. **Failed final reads.**
   - `scorchfruit_spoils`: presence now comes from a complete whole-map `list_things`, and rot from `inspect_string`, separately. If the stack is still present and its read is refused or empty, the result is UNMEASURED. The yid check now runs before the 4.5-day wait.
   - `_fresh_site`: a refused or partial terrain read is UNMEASURED and is not cached.
5. **Lightning breaker.**
   - Each component starts clean (`_independent`). A surprise abort or a non-bland map (runner) still ends the chain.
   - The gate is read live as a difference. `jawa/research_availability` runs with `breakerPyrelandsOnly` forced off and then on.
   - The result is UNMEASURED when vanilla already refuses, or when the project is begun or finished, because the gate exempts progress > 0.
   - The trip component sets `lightningBreakerEnabled` on itself.
   - The same independence fix is applied to `startup_and_def_wiring`, `ullai_and_giant` and `sand_shovel`.
