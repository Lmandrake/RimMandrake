## (A) Transcript tampering (A37): `04c528b9c`

New PreToolUse hook `D:\Luke\dev\RimMandrake\.claude\hooks\block_transcript_tamper.py`,
registered on Bash and on Write|Edit|MultiEdit|NotebookEdit in `.claude/settings.json`.
It refuses any write to `~/.claude/projects/**.jsonl` (and `subagents/*.jsonl`).
Reads are allowed, and so is agent memory under `projects/*/memory/`.

What it covers:
- Shell redirections: `>`, `>>`, `>|`, `&>`.
- File tools: `tee`, `cp`/`install`/`rsync` targets, any `mv`/`ln` operand, `dd of=`,
  `truncate`, `touch`, `sed -i`, `perl -i`, `tar -C`, `unzip -d`.
- Inline python, analysed with `ast`: `open(...,'w'/'a')`, `write_text`, `shutil`,
  `os.rename`, and `subprocess` calls.
- Inline node, perl and ruby, matched by pattern.
- Nested shells: `sh -c`, `eval`, `find -exec`, `xargs`, heredocs.
- Paths written as variables or for-loop values, after a `cd`, through a symlink,
  as `\\wsl.localhost` UNC paths, or as globs.
- A target that cannot be resolved (`$(...)`, `{}`, a runtime python path) is refused
  when the command names the transcript area.

Tests:
- Selftest `selftest_block_transcript_tamper.py`, 66/66. Each of the 32 executable
  attacks was first run for real against a planted transcript in a throwaway
  `CLAUDE_CONFIG_DIR`. All 32 changed it without the hook, and all are refused with it.
- Replayed against 22,569 real historical Bash/Write/Edit calls: **0 refused.**
- As the brief warned, a hook added mid-session does not fire until a new session starts.
  So far it has only been tested by running the script directly.

## (B) Indirection (A36): `4badee467`, `3c41b9a8c`

**The shared module.** The matcher was moved unchanged into
`D:\Luke\dev\RimMandrake\.claude\hooks\owner_said_provenance.py`. The hook imports it
and its 57/57 selftest is unchanged.

**The consumers.** These three now call `verify()` at the point where the quote is used:
- rimflow `_resolve_command_seat`;
- `broadcast.py` (the value of `RIMFLOW_OWNER_SAID`, checked before anything is stamped or sent);
- `apply_blanket_ruling.py` (`--said`).

**Finding the session's transcript**, in this order:
1. The nearest claude ancestor process, then `~/.claude/sessions/<pid>.json`.
2. The seat cgroup (`claude-seat-*`), which `setsid` and `nohup` do not leave.
3. `CLAUDECODE` / `CLAUDE_CODE_SESSION_ID`.

The claude home comes from the password database and from the claude process's own
environ, never from `$HOME` or `$CLAUDE_CONFIG_DIR`. Inside a session, a transcript
that cannot be found is refused.

**Two documented escapes:**
- **Owner at his own terminal.** If none of the three signals is present, the check
  is skipped.
- **Scratch selftest ledgers.** If `RIMFLOW_LEDGER` points outside any
  `infrastructure/state/ledger`, rimflow skips the check. The stamp lands in a
  fixture nobody reads.

**Tests.** Selftest `selftest_owner_said_provenance.py`, 23/23:
- Planted script files are refused at all three consumers: a flag built at runtime
  for rimflow, `os.environ` for broadcast, a runtime `--said` for apply_blanket_ruling.
- An unproven quote is refused.
- A planted `HOME` / `CLAUDE_CONFIG_DIR` is ignored.
- A scrubbed environment is still detected as a session.
- The test seam can only make the check stricter.

Also checked by hand: a real quote from this session's transcript is accepted.
rimflow selftests 17 files all pass, and the hook selftests 20 files all pass.

## Could not close

- **A script FILE that writes the transcript** is invisible to the tamper hook. So is a
  path built from fragments or a base64-decoded command. Nothing in a transcript line
  marks it as harness-written, so a consumer cannot detect a forged line either.
- **A process started outside the seat cgroup with a scrubbed environment**
  (`systemd-run --user`, `at`, cron) looks exactly like the owner's terminal, so the
  check is skipped.
- **An agent can edit the verifier or its callers.** This would show in git.
- **Other places that write `ownerSaid` are not wired:** `modcheck validate`, and the art
  ledger's `install`/`purge`/`enact`. A direct Bash append to a ledger shard bypasses
  rimflow entirely, and this pass did not check whether any hook catches that.
