3. **IMPROVEMENT — Define success around the owner.** Use owner minutes per accepted feature, validated throughput, regression rate, and recovery effort. Script rows, PRs, token cost, and occupied slots are supporting metrics. Keeping every helper busy can worsen the binding constraint.

22. **R1 — Adopt a bounded runner; reject the implied determinism.** Strongest counterargument: today’s proofs required substantial fixture repair, so automation may accelerate unreliable judgments. 23. **R1/E1.1 — The 80% bar does not test trustworthy unattended proof.** It permits dropping the hardest 20% and detecting no false passes. Freeze a representative suite; run repeated clean fixtures, known-bad variants, and injected bridge/process failures. Proposed bar: every case produces a terminal result, zero known-bad variants pass, recovery is bounded, and no unowned process remains. A half-day prototype does not establish production readiness or the claimed 1–2-day total cost.

24. **R1/E1.2 — Two pings prove connectivity, not independence or throughput.** Verify separate server-side port binding, launch tokens, saves, logs, mod deployment directories, and process-targeted shutdown. Steam must actually pass environment variables to the final game process. Run the same workload serially and concurrently, including deployment/restart cycles. Proposed purchase/expansion bar: ≥1.5× completed proofs/hour without reduced reliability or owner usability; record CPU and paging alongside RAM.

25. **R1 — “Second lane doubles throughput” and Steam/DRM concerns need qualification.** Shared CPU, deployment, fixes, and review cap the gain. 26. **R2 — Isolation is sound; “removes publish refusals” is overstated.** Strongest counterargument: clones move conflicts into integration and may create several stale ledger writers. 27. **R2/E2.1 — Zero refusals and sub-ten-minute latency are insufficient.** Exercise overlapping edits, advancing main, interrupted landing, source/DLL mismatches, and competing ledger updates. Require preserved lineage, understandable conflict handling, correct authority, and checks against the resulting combined commit. Selected selftests alone can miss interactions. Measure accepted throughput and integration effort against the shared-clone baseline; exclude mandatory live-test time from an arbitrary latency target.

28. **R2/E2.2 — Five closed-spec PRs test offline execution, not project management.** Three merges could still cost more owner time than local helpers. Use matched task sets, equivalent repository guidance, blind review where practical, and record setup, review, correction, elapsed time, and marginal cost. Count only accepted changes satisfying the same criteria. Add a separate bounded ambiguous task if testing planning quality; five tasks remain a screening trial.

29. **R3 — Replace “default-proceed decisions” with an explicit delegation policy.** Strongest counterargument: a reversible implementation can still consume review time, contaminate dependent work, or steer design. Preauthorize classes of low-cost technical decisions with limits. Do not record an unanswered card as owner approval; preserve the actual delegated authority. “One-tap undo” is a feature to build and test, especially after dependent commits.

30. **R3/E3.1 — Overturn rate tests agreement, not cost or authority.** One disastrous default can pass the ≤10% bar; many harmless disagreements can fail it. Record severity, downstream dependencies, rollback effort, owner review minutes, and unauthorized decisions. Follow the shadow day with a small trial restricted to preauthorized classes. Success should require reduced owner effort without material design rework.

31. **R3/E3.2 — Slot occupancy is the wrong objective.** An idle slot may be correct when live validation or L4 review is saturated. Make eligibility resource-aware and cap unvalidated work. Measure dispatch delay only for genuinely ready work, duplicate claims, accepted output, backlog growth, and owner minutes. Set `N` before the experiment and include a zero-work day. Prefer completion events, with a heartbeat for recovery.

32. **MISSED ARCHITECTURE — A local test service makes vendors interchangeable.** Expose `submit(candidate, fixture, suite)`, `status(job)`, `cancel(job)`, and evidence retrieval. The service alone owns deployment and the game lease; remote agents submit jobs. Use durable job IDs, bounded retries, and fencing so an expired driver cannot resume commands. This preserves one live driver while allowing many producers.

33. **MISSED REUSE — Evaluate GABS before rebuilding lifecycle management.** Current GABS documents launch profiles, per-launch credentials, lifecycle diagnostics, and per-game ownership leases. Determine which parts can replace custom runner plumbing and how its lease interacts with rimflow’s lock. A second independent lock authority could itself introduce races. [GABS documentation](https://github.com/pardeike/GABS).

34. **MISSED ARCHITECTURE — Running-game VM checkpoints are useful within one build.** Standard Hyper-V checkpoints include memory; production checkpoints do not. Benchmark restoring a warmed game/map, reconnecting the bridge, and repeating proofs. Crucial limitation: restoration also restores the old loaded DLLs—copying a new DLL afterward does not update running code. Keep job state outside the checkpoint and rebuild warmed checkpoints per artifact version. [Microsoft checkpoint documentation](https://learn.microsoft.com/en-us/windows-server/virtualization/hyper-v/checkpoints).

35. **MISSED ARCHITECTURE — Versioned saves and warm fixture pools are the cheaper first experiment.** Maintain small, representative maps with explicit preconditions; restore before each destructive proof. Reuse a running build across compatible tests and batch fixes into deployments. Include full-mod-list checks: a minimal-list pass cannot establish full-list compatibility. Measure reset time and fixture drift before adding another game instance.

Record commands, seeds, ticks, and state assertions for replay; replayed responses are only mocks, not fresh evidence about changed code. [HeadlessRim](https://github.com/IlyaChichkov/HeadlessRim).

Compare validated proofs/hour, maintenance, and owner interruptions before buying hardware.
