Agent Harness Review

Your question (about 15:45 PDT): could Devin-like harnesses manage this project better than rimflow plus occasional help, while staying compatible with rimbridge, live testing and loose design? Method: repo reading, sourced web research, three recommendations, a GPT review (41 points), a merge, and a second-fetch validation of 28 claims.

The answer in five lines

  1. Don't buy a product to run the project yet. No tool has a demonstrated integration with a live RimWorld behind a bridge. Our measured bottlenecks are the single live game, writers colliding in one clone, an orchestrator waiting between turns, and your attention. Coding capability is not on that list.
  2. "It can't reach the game" is no longer the reason. Devin (CLI and Local Hands), Cursor self-hosted workers, Copilot on a Windows runner, OpenHands locally, and Codex over Tailscale can all reach a machine we own. What's missing is ours: a test service that alone owns the game and accepts jobs.
  3. R1: build that live-test service and let a machine run the proof belt. Add a second game lane only after a measured experiment.
  4. R2: give each writing helper its own clone and land work through one serial lander. Try an outside agent only on matched offline items.
  5. R3: dispatch on events (Claude Code dynamic workflows, hooks, Channels) and write a delegation policy so your time goes to taste. Then run a one-milestone orchestrator bake-off.

Our setup and pain points

RimWorld runs on Windows and the agents run in WSL2, driving it through the GABP bridge and JawaBench with one live driver at a time. A cold load takes ~15 min on the full list and ~22 s on the minimal list. Proof scripts emit PASS/FAIL/UNMEASURED rows, classified MOD, SITE or HARNESS. There are two Claude seats in separate clones, helpers as subagents, and rimflow holds 528 live items (MEASURED).

The 2026-10-22 belt ran 08:48–14:44 over ~20 proof scripts. The seat reports ~548 rows passed and 8 bugs filed.

  • Serial live resource. Each DLL redeploy means game down, deploy, and a Steam relaunch. Fixers and the belt wait on each other.
  • Shared-clone collisions. ./publish was refused at 08:58 and 09:16 on RM_SheetMath.cs, stranding 11 commits (not lost).
  • Dispatch latency. The log has gaps of 16–28 min (MEASURED). The seat reports idle slots. The cause isn't in the log, so experiment E0 attributes it.
  • Harness churn. Telling MOD from SITE from HARNESS takes judgment. One bug was filed wrongly and dropped.
  • Your attention is the binding constraint. Design is loose, and owner-look items pile up for the evening walk.

Three recommendations

R1

A live-test service that alone owns the game, with a machine-run belt

Changes
A local Python service owns deploy, launch, the bridge lease (tied to rimflow's BRIDGE lock), save fixtures and a job queue: submit → status → evidence. It re-proves on every relevant commit, overnight too. An LLM is woken only for a FAIL, a timeout or invalid evidence. Any agent submits jobs. GABS handles lifecycle if it fits.
Gain
Proofs stop waiting on LLM turns, and an outside product can be tried later without touching the game.
Cost / risk
2–4 days to build. A bad harness judgment repeats faster unless known-bad builds are made to fail.
Fit
Native rimbridge. Design ambiguity stays outside the service.
  • E1.0 · ½ day GABS fit: run one existing proof through GABS. PASS: the rows match a direct run and the lease rule is written down.
  • E1.1 · 1 day Robustness: 6 proofs, 3 known-bad builds, 2 injected faults. PASS: all cases end in a terminal state, 0 known-bad builds pass, no orphan process.
  • E1.2 · ½ day Second instance (separate -savedatafolder and GABP_SERVER_PORT). PASS: ≥1.5× proofs/hour at equal reliability.
R2

One clone per writer, a serial lander, a matched offline trial

Changes
Each writing helper gets its own clone (not a worktree) and pushes a branch. One lander applies branches one at a time, checks the combined commit, and keeps DLL+.srchash pairs together.
Gain
An end to shared-tree push refusals and to one-writer-at-a-time serialisation.
Cost / risk
Conflicts move to landing time and must surface with lineage. More disk.
Fit
Live testing is untouched.
  • E2.1 · 1 day 3 clones plus overlapping edits, an interrupted landing, and a DLL mismatch. PASS: 0 lost commits, every conflict reported, combined selftests green.
  • E2.2 · 1 day 6 offline items split between a local helper and an outside agent, reviewed blind. PASS: outsider acceptance ≥ local and review minutes ≤ local.
R3

Event-driven dispatch and a written delegation policy, then a bake-off

Changes
Work starts on events (dynamic workflows, hooks, Channels), with a heartbeat only for recovery and a cap on unvalidated work. A short list of technical decision classes agents may take alone, logged as --why "delegated: …", never as your approval. A design brief per milestone.
Gain
Your minutes go to taste, and ready work starts within minutes.
Cost / risk
A delegated call can steer design, so start narrow. Channels and workflows are new.
Fit
Works with loose design by asking less, and asking better.
  • E0 · 2 h, first Attribute one belt day's minutes. Check whether this login has scheduled tasks, Projects, Channels and workflows.
  • E3.1 · 1 day Shadow delegation: log the cards we'd have sent and you rate them. PASS: no severe overturn, and ≥ half are delegable.
  • E3.2 · 1 day Event dispatch. PASS: ready-work delay median ≤ 10 min, max ≤ 30 min, within a set token cap.
  • E3.3 · 1 day each After R1: one milestone through a Claude dynamic workflow, Devin (Local Hands + Dynamic Workflows) and Factory Missions. Measure your interventions and accepted results.

What GPT challenged and what changed

GPT made 41 points. We accepted 35, accepted 3 in part, deferred 1 and rejected 2 as stated. The full table is in merge.md.

  • Our "hosted agents can't reach the game" was wrong. Several now run locally. The real gap is our missing test service, which became R1.
  • Default-proceed cards became a delegation policy. An unanswered card is never logged as your approval.
  • Metrics changed. Owner minutes per accepted feature replaced slot occupancy. Experiments now require zero false passes and ≥1.5× throughput.
  • Added: GABS first, fixtures before a second instance, a vendor bake-off, design briefs, and a WIP cap.
  • Rejected: "Cursor explicitly supports Windows workers" (the docs don't say so) and HeadlessRim (3 stars, version unstated).
  • Found by us: Claude Code dynamic workflows, a local built-in equivalent of Devin's Dynamic Workflows.
