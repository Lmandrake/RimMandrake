## Defects
- FIXED (real) Eating slime could LOWER slimification: `Mathf.Min(0.99f, severity + dose)` clamps to 0.99 even when the pawn was already above it (0.995), so a "dose" healed the last half-percent and delayed dissolution. `RM_SlimeLadder.DoseSeverity` never goes below the current value. Fuzz plants the old formula and catches it.
- FIXED (hardening) `SlimeArchiveUtility.Pay` destroyed stacks per cost entry as it went; if CanPay (resource counter) said yes but the unforbidden stacks were short, it took raw slime and then half the components with nothing to show. It now plans every cost first (`RM_SlimeWorld.PayPlan`), pays nothing unless all can be paid, and Begin tells the player. Unmeasured whether the resource counter ever counts forbidden stacks, so this may not be reachable.
- FIXED (latent) `RollStartingMass` could return a zero-weight row when the roll landed exactly on 0 with a leading zero weight (`roll <= 0` after subtracting 0). Zero-weight rows are now skipped; Rand.Value == 0 is measure-zero, so this was never seen.
- NOTE (design, not changed) The antidote refuses at severity exactly 1.0, but the hediff only dissolves at the next 200-tick check after severity reaches 1.0 (maxSeverity), so there is a window of up to 200 ticks in which the patient is at 1.0, alive, and uncurable. Fuzz counts 325 such refusals at scale 25.
- NOTE (design, not changed) Stage 0 wipe-off is a hard `severity < 0.2`; the hediff's own stage 1 starts at 0.2, so "stage 1" already holds (letter text agrees).
- NOTE a pawn rescued from a titanoslime gets +0.15 (capped at 1.0) with no check that it was already at 0.9+: it dissolves at the next check despite being "released alive".
