## Defects fixed
- `JobDriver_RM_CrackSarcophagus` salvage loop: `stackCount = Math.Min(left, row.thingDef.stackLimit)` with `stackLimit` below 1 places nothing and never decreases `left`: an infinite loop that hangs the game on the first crack. Latent (every row shipped today stacks at 1 or more), but one `stackLimit` 0 edit in the XML would freeze the game. `NextSalvageStack` floors the limit at 1; planted in the mutation set (the fuzz's loop guard trips) and the lint checks every shipped row has a limit of at least 1.
- `RM_CompProperties_CoreDose` comment said the dose "falls linearly to 0 at radius"; the code (and the live-measured behaviour) is `1 - d / (radius + 1)`, still 1/(radius+1) = 0.2 at the radius and 0 one cell beyond. Comment corrected, behaviour unchanged (the fuzz pins the formula).

## Observations, not changed
- Gear-held terrain branch is dead: `ProtectionDriveFactor(protection, 0.05, 0)` is `max(0.05, 1 - protection)`, never <= 0, so "gear alone holds the clock" and the slow heal at `-0.1` never run. A warcasket wearer (protection 0.9) in deep water still reaches lethal severity in 8.4 h, perfect gear in 16.7 h; the existing live validation measures exactly this slope, so it reads as the intended "slows the clock". Lint WARN keeps the figures visible.
- `RM_WarcasketJunker` inherits `RM_Warcasket`'s `recipeMaker`: the adjusted warcasket is craftable at the machining table, and any worn to a death and cracked open yields a half-extracted core (650 silver) while the suit is dropped and can be worn again. The core's comment says no recipe makes one. Lint WARN. Owner call (a `generateAllowChance 0` variant reads as "never player-made").
- A suit that was NOT sealed (the setting was off when its wearer died) is still offered for cracking once the setting is on, and yields the salvage (fuzz: 5,492 of 130,122 cracks at scale 40): `SealedSuitOn` tests the def, not the lock.
