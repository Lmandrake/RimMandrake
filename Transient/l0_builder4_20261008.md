## TitanicCreatures
Census: had validation.py (live) only. No kernel, fuzz, mutation set, lint or wired selftest.
Added: `Source/Kernel/RM_TitanicKernel.cs` (tier ladder, force in/out, footprint, sub-linear yield, crush rule/damage, roof rule, T3 pool spoilage/harvest; behaviour-preserving, mod calls it), `Source/SelfTest/TitanicFuzz.cs` (4 families, 8500 seeded cases), `Utils/selftest_titaniccreatures_fuzz.py`, `Utils/mutate_titaniccreatures_fuzz.py` (31 mutants, 31 caught; 4 equivalent mutants documented), `Utils/lint_titaniccreatures_defs.py` + `selftest_titaniccreatures_lint.py` (19 planted, 19 caught).
Bug found by the fuzz and fixed: a T3 titan dealt T1 crush damage (20) to non-building crushables while a T2 dealt 60 (`tier == T2 ? 60 : 20`). Now `tier >= T2`.
Design observations (not changed): with `corpseSiteEnabled` off a T3 corpse butchers at FULL vanilla yield (the curve only covers T1/T2); DefQualifies reads baseBodySize but the tier reads Pawn.BodySize (lifestage factor), so a race with baseBodySize below the T1 floor and an adult lifestage factor above 1 would be tiered by GetTier yet never receive the wake comp. PROVISIONAL: crush 20/60, spoilage 0.15/0.08, tier floors 4/8/20, yield floor 0.15.

## Visibility
Census: net48 example-based selftest (`selftest_colony_visibility.py`, 36 cases, still passes) + live validation.py. No kernel, seeded fuzz, mutation set or lint.
Added: `Source/Kernel/RM_VisibilityKernel.cs` (band ladder, Annex A curve, strength slider, dial clamp, launch reset, tile-memory decay/restore, raid-point scaling), `Source/SelfTest/Fuzz/VisibilityFuzz.cs` (5 families, 13500 cases), wrapper, `mutate_visibility_fuzz.py` (26/26 caught), `lint_visibility_defs.py` + `selftest_visibility_lint.py` (17/17). The lint caught a dead duplicate SimpleCurve left beside the kernel copy; removed.
Bug found and fixed: raid-point scaling clamped to [GlobalPointsMin, 10000] even at factor 1, so the settings text "0x = no effect at all" was false for any raid outside the clamps (e.g. a 25000-point or 20-point raid). Now a factor of exactly 1 is a no-op and the clamp never moves a raid across a bound it was already past.
Design observations: ResetOnLaunch clamps to 5..15, so a launch RAISES a dial below 5 (ruled by the doc text "floor 5, ceiling 15"; kept). Harmony hook parameter names (`engine`, `gravship`) cannot be checked offline; unmeasured.

## Watchers
Census: generic def lint (lint_watchers_defs.py) + live validation.py. No kernel/fuzz/mutation/data lint.
Added: `Source/Kernel/RM_WatcherKernel.cs` (watch-job step state machine, nearest scan, giver/seek-medium/flush gates, hide duration, extension config rules), `Source/SelfTest/WatcherFuzz.cs` (4 families, ~95000 cases incl. exhaustive truth tables), wrapper, `mutate_watchers_fuzz.py` (47/47 caught), data lint extended + `selftest_watchers_lint.py` (19/19).
Findings: the state machine held every invariant (sign iff hidden, hungry emerge ends the job, quiet watcher always finishes). Hardening: ConfigErrors now also rejects wanderChance or emergeWhenFoodBelow outside 0..1 (a threshold above 1 would make a watcher never watch; previously unvalidated, shipped piinnok values are valid). The watch giver keeps its lazy order (roll before the map-wide scan).
PROVISIONAL: maxWatchTicks 2500, boltTicks 1200, wanderChance 0.1, sliders.

## WeatherSuite
Census: live validation.py only. No kernel/fuzz/mutation/lint.
Added: `Source/Kernel/RM_WeatherKernel.cs` (great-circle arc, terminator/nightside band tests, aurora tint channel arithmetic, forecast top-N shares), `Source/SelfTest/WeatherFuzz.cs` (4 families, 10500 cases), wrapper, `mutate_weathersuite_fuzz.py` (21/21 caught, 1 equivalent documented), `lint_weathersuite_defs.py` + `selftest_weathersuite_lint.py` (14/14).
Bug found and fixed: the "maximised" aurora tint could be DARKER than vanilla: the sliders allow saturation up to 1 with brightness down to 0.73, which zeroes low channels (about 24% of the slider range). The kernel now floors every channel at the vanilla aurora's own value; shipped defaults (0.35 / 0.05 / 1.15) are unchanged.
Design observations: the nightside gate asks whether ANY home map is in the dark band, which is sound only because the incident targets the World (the lint pins that). The forecaster's 'last forced weather wins' and the near-copy of WeatherDecider commonality are engine-bound and unmeasured offline. PROVISIONAL: Ash'karr geometry 63..117, tint defaults.

## XML-only mods: AssailantSalvage, HostileFlora, MandrakePatches, Pyrinth, StrandedQuest, Traces
Census: no pure logic anywhere (no C# in any of the six), so a def lint is the right L0 (a kernel/fuzz would test nothing). Existing: validation.py for all six (live), plus `selftest_hostileflora.py`, `selftest_mandrakepatches.py` (unguarded-op static) and `selftest_pyrinth_semantics.py` (kept, still green).
Added: `Utils/lint_xmlonly_defs.py` (common: parse, defName uniqueness incl. cross-mod collisions, ParentName typos, dangling own-prefix refs, own-texture resolution, About scheme, PatchOperation shape and the inert top-level `<Operation MayRequire>` trap; per-mod contracts: Traces filth/spike names, HostileFlora race/kind pair, AssailantSalvage RUT_ + label/hp/size, Pyrinth generator + donor incompatibility + xpath balance, StrandedQuest via the calibrated quest validator + history events, MandrakePatches guarded top-level ops) and `Utils/selftest_xmlonly_lint.py` (51 planted defects, 51 caught across the six mods).
Bugs found and fixed:
 - AssailantSalvage: the two airlock defs (small and large) named doorTopGraphic textures `..._Top` that were never installed (the renders sit in artpipe _artsrc; Large_Top north FAILED), so the game logged missing textures and drew a bad graphic. The two blocks are commented out with the restore instruction; they go back when `art install` lands them.
 - Pyrinth: defNames are the donor's verbatim (DV_*) but About.xml did not declare incompatibleWith det.epochspyrinth, so a load with both active collided silently. Now declared.
Design observations (not changed): AssailantSalvage lives in src/RimMandrake but its packageId is mandrake.rut.assailantsalvage (tier directory vs packageId disagree; deploy maps by folder). MandrakePatches' packageId is mandrake.rm.patches while the folder is MandrakePatches. Traces is still the step-0 spike (two placeholder filth defs, deleted when step 1 lands). Pyrinth About text says the donor is still active in the live list; the test lists (modset_builder) load it without the donor.
