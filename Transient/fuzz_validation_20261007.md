## Survey (done)
Pick: (1) Bazaar price drift+history ring, (2) RustCathedral attitude band/standing/drain/decay, (3) Ninefold satiation/mood/erosion/first-contact queue/front.

## 1. TheBazaar price engine - DONE
- **Why**: pure daily state machine (drift+clamp+nudge, 32-ring with head, save/load repair), never coverable live (needs hundreds of days x buckets); extraction was ~60 lines.
- **Files**: new `src/RimMandrake/TheBazaar/Source/Economy/RM_BazaarKernel.cs` (Verse-free: Clamp, ToUnit, SeedLevel, DriftStep, NudgeBy, RingPush/RingOldestFirst/RingRepair); `RM_BazaarEconomy.cs` now calls it (constants alias the kernel, DriftAll/Nudge/Record/HistoryOldestFirst/PostLoadInit bodies replaced by one call each, same float operation order, Mathf.Clamp -> identical Clamp); csproj +1 Compile line; `Source/SelfTest/{RimMandrakeBazaar.SelfTest.csproj,Program.cs,BazaarFuzz.cs}`; wrapper `src/RimMandrake/Utils/selftest_bazaar_fuzz.py` (picked up by run_selftests.py as `selftest*.py`, stage_build like GSS). DLL rebuilt, uncommitted.
- **Invariants**: multiplier always in [0.25,4]; one-day move <= 10% of old value; nudge in [-0.75,3], never grows or flips sign in a drift, no dust < 0.001; SeedLevel in band; ring Count <= 32, head in range, oldest-first == reference queue of last 32 pushes, newest == latest push; save/load of a well-formed ring preserves order; over-long/garbage-head repair gives Count <= 32 and head in [0,Count); same seed replays to identical digest; settle family (no nudge/no walk) never moves away from or overshoots target and is within 1e-3 after 400 days; 3-year noisy walk stays in band; hash->unit in [0,1] and monotone.
- **Seeds run**: default 3,000 drift + 1,500 settle + 100,011 unit (seeds 1..N), 9 s; also --fuzz-scale 10 (30,000 drift / 15,000 settle / 1,000,011 unit, 25.9M steps, 93 s): 0 failures.
- **Finding (tolerated, not a defect in play)**: `Hash01`'s "[0,1)" is actually [0,1]: float rounding makes the top 64 uint hashes exactly 1.0 (hashes -1, -2, -64 ...). Every consumer is fine with 1.0. Tallied in output.
- **Mutation**: cap `MaxDailyStep*2` -> `drift seed 1: daily move 4->3.24 exceeds 10%...| Nudge Drift`, shrunk to 1-2 actions; ring head `% (HistorySize-1)` -> `drift seed 1: ring oldest-first != last pushes | Drift ReloadLong ReloadLong Record`, 5/5 fail. Both restored (diff vs backup clean).
- **Run**: `python3 src/RimMandrake/Utils/selftest_bazaar_fuzz.py [--fuzz-scale F] [--fuzz-seed N] [--fuzz-only drift|settle|unit]`

## 2. RustCathedral hum-mood (BiomeAttitude) - DONE
- **Why**: slow standing layer + fast irritation layer + hysteresis band + capped drain is exactly the long-horizon state machine a live test can't cover (days of game time, many def shapes).
- **Files**: new `src/RimMandrake/RustCathedral/Source/Hum/RM_AttitudeKernel.cs` (Verse-free: StandingStartValue/StandingAfter, IrritationAfter, Composite, BandFor w/ hysteresis, ClampToCeiling, DroppedBand, DesiredLayers, DecayedIrritation, DrainDelta); `RM_MapComponent_BiomeAttitude.cs` now calls it for every one of those (state and engine calls stay; same float op order; Mathf.Clamp/Max/Pow -> equivalent); `RimMandrake.RustCathedral.Hum.csproj` +1 Compile; `RustCathedral/Source/SelfTest/{RimMandrake.RustCathedral.Attitude.SelfTest.csproj,Program.cs,AttitudeFuzz.cs}`; wrapper `src/RimMandrake/Utils/selftest_rustcathedral_attitude_fuzz.py`. DLL rebuilt, uncommitted.
- **Invariants**: standing always in [-100,100] and == clamp(old+delta); StandingStartValue in range; irritation >= 0, finite, never raised by decay, no dust < 0.05; composite in [0,100]; band in [0,Worst]; band between raw and max(raw,prev); escalation immediate; a fall happens only once composite is `margin` below the previous band's threshold; band is a fixed point at constant composite; displayBand in [0,min(ceiling,band)]; line-cycle drop moves band by 0 or 1 and never touches worst; layers in [0,layerCount], 0 at worst, non-decreasing as band rises; drain never raises standing, one drain <= tick amount and <= day cap, successive drains >= interval apart, window sum >= cap and == bookkeeping `drainedToday`; band monotone in composite for fixed prev; band never rises as standing rises; decay obeys the exponential law (2 steps == 1 double step), one half-life of ticks halves, bigger stage multiplier never decays slower.
- **Seeds run**: default 10,000 seq (9.9M steps) + 20,000 band + 50,000 decay, 8 s; --fuzz-scale 10: 800,000 cases, 148M steps, 75 s, 0 failures. Coverage printed: 36M worst-band checks, 1.6M drains (285k cut by day cap), 327k band falls.
- **Observations (not failures)**: a fall can skip bands (4.6M at scale 10): from band 2, composite 5 lands on 0 not 1, because hysteresis only guards the previous band's line; `StandingAfter(100, int.MaxValue)` wraps to -100 (callers pass small deltas).
- **Mutation**: hold line `- margin` -> `+ margin`: `seq seed 5: fell 3->1 at composite 16.9 before 18.6 below threshold 34.8 | SetIrr AddIrr Check`; standing max 101: `seed 1: standing 101 != clamp(old+328) | Standing`; day-cap clamp removed: `seed 1: day window drained -24, cap -21 | Afk`; swapped hold ternary: `band seed 1: band fell 2->1 as composite rose`; decay squared: `decay seed 1: one half-life left 17.5, expected 35.0`. Equivalent mutant noted: gate `drainedToday <= cap - 3` survives (the budget clamp makes the gate redundant except for lastDrain bookkeeping). All restored, diff clean.
- **Tooling trap found**: `winbuild.stage_build` + dotnet incremental can reuse a stale DLL when the source is restored within ~1 s of the previous build (rsync/drvfs whole-second mtime). A mutation loop must `sleep 4; touch` the file before each run or it reports the previous mutant. Cost me three phantom results; the shipped runs are unaffected (verified after a gap).
- **Run**: `python3 src/RimMandrake/Utils/selftest_rustcathedral_attitude_fuzz.py [--fuzz-scale F] [--fuzz-seed N] [--fuzz-only seq|band|decay]`

## 3. Ninefold satiation engine - DONE
- **Why**: 9-god satiation/mood/erosion vector plus a first-contact scheduler (one introduction a day, FIFO queue) and a loudness "front" with hysteresis; event order matters and the queue/gate interplay is invisible live.
- **Files**: new `src/RimMandrake/Ninefold/Source/RM_NinefoldKernel.cs` (Verse-free, gods as ordinals: AddSatiation, ErodeSatiation, MoodStep, Loudness/LoudnessRank, FrontAfterSwing, TryFirstContact/MarkFired/PopDue, CountViolentDeath); `GameComponent_Ninefold.cs` now calls it in ApplyDelta, rooted erosion, mood walk, loudness rank, front flip, TryFirstContact, FireFirstContact, StepPending, NotifyViolentDeath (letters, clock reads, logging stay in the component); `Ninefold.csproj` +`<Compile Remove="SelfTest\**" />` (this csproj globs every .cs, so without it the fuzz would compile into the mod; the mod build is clean with it); `Source/SelfTest/{RimMandrakeNinefold.SelfTest.csproj,Program.cs,NinefoldFuzz.cs}` (also compiles production `SatiationBand.cs`); wrapper `src/RimMandrake/Utils/selftest_ninefold_fuzz.py`. DLL rebuilt, uncommitted.
- **Invariants**: satiation and mood always in [-100,100]; an event moves only its own god, direction matches sign; hourly walk moves only Ta'Baa's satiation (down); every god is introduced at most once and only after being triggered; introductions >= 1 day apart; queue has no duplicates, no unveiled gods, is FIFO and matches the model; a repeat trigger is a no-op; fire happens only with an empty queue and an open gate; PopDue never holds a due god; liveness (after any sequence, N+2 quiet days drain the queue); Sh'kaar counter fires exactly at 3; rank is a permutation, loudest-first, ordinal tie-break, deterministic; front moves only when reckoned and |raw| >= 15, then equals the loudest, and a violent swing always leaves front == loudest; replay determinism; band boundaries exact (-60/-20/20/60 to their named band) and monotone; mood: a zero step is pure 2% decay, monotone in the roll, amplitude-bounded, and with the walk off any mood decays to ~0 in 600 h.
- **Seeds run**: default 2,000 seq + 100,000 band + 100,000 rank + 20,000 mood (seeds 1..N), 8 s; --fuzz-scale 10: 2.22M cases, 123M steps, 75 s, 0 failures (356k introductions, 153k from the queue, 62k front flips).
- **Mutation**: `PopDue` day gate removed -> `seq seed 1: PopDue popped with nothing due | Trigger Trigger`; front threshold x4 -> `seed 2: a violent swing left the front off the loudest god | Landing Event`; satiation max 101 -> `seed 2: satiation[1] = 101 left [-100,100] | Event x4`; mood pullback sign flipped -> `mood seed 1: a zero step from -50.27 gave -51.27, expected -49.26`; queue guard `pending.Count == 0` dropped -> caught only after I added a "trigger lands after the clock moved, before the component's step" action (`seed 737: fired while something was queued`; the first version of the fuzz missed it, i.e. that guard only matters inside a single tick); SatiationBand `>= 20` -> `> 20` -> `band boundary: BandFor(20) = Neutral, expected Content`. All restored.
- **Run**: `python3 src/RimMandrake/Utils/selftest_ninefold_fuzz.py [--fuzz-scale F] [--fuzz-seed N] [--fuzz-only seq|band|rank|mood]`
