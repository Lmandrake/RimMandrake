### KineticArms - logic mod; had a kernel (RM_KineticMath.cs) + 49 hand-written examples (selftest_kineticarms_kernel.py) + validation.py; MISSING seeded fuzz, mutation set, def lint
- Added `Source/SelfTest/Fuzz/` (6 families, 23k cases: cone vs angle oracle, cone cells vs disc oracle, rotation symmetry of the four facings, whole-bolt invariants, pulse-cannon charge vs a double ledger incl. single-tick vs one-call equivalence, ruins pick vs weighted oracle + edge rolls + RuinsRollFor round trip, looted gate/grenadier/money, unit tables) + `Utils/selftest_kineticarms_fuzz.py`, `Utils/mutate_kineticarms_fuzz.py` (63 mutations), `Utils/lint_kineticarms_defs.py` (generic lint + ka-weapons/carried/forces/cone/kernel/engine data checks) + `Utils/selftest_kineticarms_lint.py` (19 planted breaks).
- BUG FIXED (kernel, DLL rebuilt with .srchash): `RM_KineticMath.RuinsRollFor` documented "-1 if it cannot be picked" but returned a roll for a zero-weight enabled weapon (fell outside [0,1) when the zero-weight weapon was last, or landed on a neighbour's band otherwise) and returned -1 for a weapon PickRuins CAN pick when every weight is zero (uniform fallback). Only the proof tooling calls it, with positive shipped weights, so no shipped behaviour changed.
- Fuzz tolerances learned (not bugs): InCone accepts cos >= cos(half) - 1e-4, i.e. a 0-degree cone accepts +-0.8 degrees and the 180 edge has the same slack; the pulse cannon accumulates 1/R in float per tick, so over ~6000 ticks the charge drifts ~2e-3 from the exact ledger (CanFire's 1e-4 slack covers one tick of it).
- Equivalent mutants dropped from the set (and why): `cone cells scan range floor vs ceil` (cells at |offset| > radius are outside the disc anyway), `ruins gate ignores chance 0` (roll1 >= 0 always), `ruins fall-through returns first` (needs target == total after float rounding; unreachable for roll2 < 1).
