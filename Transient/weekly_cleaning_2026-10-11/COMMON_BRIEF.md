## Rules for every auditor
- You are READ-ONLY on the system. The only file you write is your own report at the path you were given. No git commands that write (no commit/add/stash/reset/checkout). No bridge, no game.
- Create your report as a SKELETON FIRST (headings only), then fill it section by section. You die after 600 s without output, and a file write is output.
- Run every command in the foreground. Never background a command and wait on it.
- Evidence or it didn't happen: every finding cites a path (and line or count). A number about a large artifact is MEASURED by a python script you ran, never estimated by grep -c/wc. Say UNMEASURED when you couldn't measure.
- Distinguish: (a) DELETE (wrong/dead, git is provenance), (b) MERGE (duplicate of X), (c) MOVE (lesson in wrong place, e.g. CLAUDE.md -> docs/lessons), (d) PROMOTE (to a skill, or out of this project to ~/.claude level), (e) KEEP.
- For each proposed action give: target path, action, one-line why, risk (what breaks if wrong).
- Policy facts you must respect: CLAUDE.md is RULES and POINTERS only; durable lessons go in docs read on demand (infrastructure/state/lessons/, design docs, skills). Inaccurate material is deleted, not annotated. Skills are edited only in curation passes (this IS one, but you only propose). Owner rulings quoted verbatim must survive.
- End the report with a "Top 10 actions, ranked by value" table and a "Questions only the owner can answer" list (each a real choice with 2-4 options, not open-ended).
