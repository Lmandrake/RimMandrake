## Defect (verified)
`src/RimMandrake/FlowWorks/Source/Rivers/RM_Weir.cs` `WashCatch()` called `t.DeSpawn()` then
`GenPlace.TryPlaceThing(t, strand, Map, Near)`. The decompiled 1.6 `GenPlace.TryPlaceThing` Near
returns false with the remaining stack left unspawned (it never respawns it), so on a breach the held
catch was orphaned and lost. Checked with RimSage.

## Fix
The old cell is recorded before the despawn. If the placement fails and the thing is not destroyed,
it is `GenSpawn.Spawn` back at that cell. If part of the stack merged into strand stacks first, the
item still counts as moved. You can't place a spawned thing elsewhere without despawning it, so
"place first" is implemented as restore-on-failure: nothing is lost.
