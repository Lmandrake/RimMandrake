## What makes an agent keep going for 8 hours

The published guidance on long-running agents and last night's failures point at the same six things.

1. **State lives on disk, not in the agent's head.** Three files per mod: a checklist of acceptance lines in your words, each with a pass flag; a short progress note; and git. Every session starts by reading them, so a restart loses nothing.
2. **Restarts are the context management.** The agent takes one checklist line, works it, proves it, commits and exits. A simple loop script starts a fresh session for the next line. Nothing depends on a long conversation surviving.
3. **Each line has a proof the agent can run itself.** On the small mod list the game loads in about 36 seconds, so the agent can try something in the game dozens of times a day.
4. **It never waits for you.** Two failed attempts on a line and it parks that line with a written question and moves on. Your questions pile up in one file instead of stopping the work.
5. **Scripts enforce the limits, not the agent.** A dollar cap per line and per day, checked while it runs. The agent may only mark a line passed when its evidence file exists; it may not edit the checklist's wording, the rules or the loop.
6. **One agent per game.** The game is serial, so a second agent only queues behind the first.
