Don’t you have to format a drive as boot and can’t build it after the fact?

## Claude

No, on a modern PC boot isn't something built into the drive when it's formatted. It's a small separate partition holding ordinary files, so it can be added after Windows is copied. This is how Windows gets set up from an image, and `bcdboot` is Microsoft's own tool for that step.

Steve boots through UEFI on a GPT disk, which needs three things:
1. **EFI system partition:** a tiny FAT32 partition that the firmware looks for.
2. **Boot files on it:** the Windows Boot Manager plus a small database (the BCD) saying where Windows lives.
3. **Windows partition:** the one being filled now.

The helper's script sets up the Kingston's partitions first, copies Windows, then writes the boot files and the BCD at the end. It's building the BCD by hand instead of using `bcdboot`, so the motherboard's boot settings stay unchanged while the Samsung is still the working drive.

There's one more step: Windows remembers which disk it lives on, so the script updates that record on the copy. Otherwise Windows on the Kingston could come up looking for its old C: drive.

None of this is tested until the first boot, and that's the real risk. If it won't start, the Samsung is unchanged and goes back in as before, and any boot fault can be repaired without recopying the files.
