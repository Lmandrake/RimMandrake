Is it not useful to do mutmut on evolving code? I'm worried we might need a rule on when to do mutation testing. What is the general advice from the software development community on when to do mutation-type testing in terms of the software dev and maturity cycle?

## Claude

Yes. Mutation testing code that is still changing mostly wastes compute, and we've been doing a lot of it. The industry consensus points the same way.

**What the field generally advises:**
- **It's a late-stage tool, not a constant one.** Mutation testing tells you whether your tests would notice a bug. That is only worth knowing once the code and its tests have settled. While logic is still changing daily, every score goes stale the moment the next commit lands. Our role-launch score today was out of date before the run even finished, because its test arrived after the run started.
- **Spend it on code where a hidden bug is expensive.** Parsers, money, security, and anything that decides or gates: schedulers, evidence checks, permission logic. Skip glue code, UI and one-off scripts.
- **At scale, run it only on what changed.** Google's published practice (Petrović and Ivanković, ICSE-SEIP 2018) mutates only the lines changed in a code review. The Pitest (Java) and Stryker (JavaScript) tools both push "incremental" mode for the same reason.
- **Don't chase a score.** Some surviving mutants behave exactly like the original code ("equivalent mutants"), so 100% is often impossible. The value is in reading why each survivor lived. Teams that set hard percentage bars end up writing tests to the number.
- **Prerequisites first:** decent coverage and a fast, reliable test suite. A slow or flaky suite makes mutation runs both costly and noisy.

**Where we went wrong:** we ran full mutation passes, 1,600–2,300 mutants each, on dispatcher and close-evidence code that changed several times today. We held them to an 85% bar. 3. **Code still changing:** at most a run limited to the changed functions, and only when that file's review is otherwise finished.
4. **The 85% bar:** it applies to full runs only. Every survivor gets one of three outcomes: a new test, "equivalent" with a one-line reason, or "not worth it" with a one-line reason.
