**Design:** each clone keeps one tree under a lock. Before each use it removes leftover files, checks out the commit (git rewrites only files that differ) and resets the refs. It then confirms the tree is exactly the commit. If that fails, it builds a fresh tree and says why. A second user at the same time gets its own temporary tree instead of waiting, because the red re-run path opens trees inside the first one. Per clone fits on disk: 16 kept trees use about 74 GB, and both machines stay well above the 210 GB floor. The pool now keeps the tree when it hands a clone to the next run.
