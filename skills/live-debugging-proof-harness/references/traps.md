# Traps by topic

Lessons folded in from the lessons inbox, by the section of `../SKILL.md` they belong to.

## The anatomy of a proof
- **`modcheck run FlowWorks --item <ID>` REFUSES items whose rows live only in `northstar/gravel_live.py` or `shovels_live.py`** (no `validation.py` chain or `DRIVER_BAR_ROWS` entry names them). The targeted live run for those rows is the script itself with `--only <row ids>`; its result JSON is the evidence.

## Row semantics: PASS, FAIL, UNMEASURED
- **A live re-assert row must FAIL, not UNMEASURED, on any last-reason that only startup writes** (e.g. 'surface placer registered'): seeing it last in a running game proves the FinalizeInit hook never ran. Only reasons a later proof could have written (`proof:`, settings changed) are UNMEASURED.
- **A live proof's exit 1 is a FAIL only if the proof asked the game and got an answer.** Of 73 historical exit-1 runs scored as mod FAILs only 22 were real: 24 could not read (a traceback after the last verdict, read None, NOT REPRODUCED), 22 were harness faults (IndeterminateError, WSL bridge errors, ENOSPC) and 5 ran on the wrong tier or a stale deploy. Read the log tail before you score a strike (`relentless_live.could_not_ask`). A `k=None` beside real values on the same line is a partial read, not a blind one. But never erase an observed violation: a FAIL line or failed assert that reports None keeps its FAIL (the None may be the defect) and the worker classifies it.
- **Put precondition checks (map, biome, save) FIRST in a live proof's first command and exit UNMEASURED, never FAIL.** A proof chained `repro && record` hid a wrong-map run as FAIL: the guard that rejects the wrong map lived in the second step, which never ran after the first exited 1.
- **A live proof of an RM_ standalone behaviour that a RUT/Droidworks campaign patch swaps (FindMod-guarded) must read the RUNNING def state first** (`jawa/get_def` `extra.modExtensions`) and end on 'reload needed: ... lacks <pkg>' (exit 2, a restage) when the swap is live; otherwise a load batched with other items' mods FAILs a sound build. A live-menu/live-toggle proof only measures on a load its own staging ran, so the lane's try-the-running-game shortcuts must skip such items.
- **HugeThings creature inspect strings always contain 'smashes up to N thick' / 'squeezes gaps of N+'.** Match the job text ('smashing through') or every row reads as a breach.
- **A reader of a modcheck results JSON must check `summary.refused` first.** A refused run (e.g. `stale_load`, game up on another mod list) has `chains: []`; reading only `summary.chains` scores it FAIL 'chain not in the run' instead of UNMEASURED (exit 2).
- **A live row that waits for 'none of X left' measures the LAST X, not the first.** `thirst_live` T25 read 'snow never melted in 7,000 ticks' while four staggered snow buckets each melted on time. Follow the subject by ID from the moment it is seen.
- **A level/conservation bar must read exact water (`_water` / ProofPitWater dL), never excavation integer fill.** Integer fill floors part levels: 3 conserved levels spread 1.5+1.5+0 read 2, which looked like a pump losing a level.
- **FlowWorks thirst full runs leak between rows.** A later row's desperate pawns drink an EARLIER row's leftovers (toxic outranks slime in `JobGiver_RM_Drink`'s BetterPick; a leftover player tank is a drink source), and colonists PACK filled bottles, so bottle stock is `RM_BottleStock.Have` (ground + packed), never a ground count. `thirst_live.py` `dry_all`/`quench_all`/`have()` encode this.
- **A FlowWorks cut can hold real liquid at F=0.** A D1 cut off a limited pond read fill 0 on all cells while every one was `RM_Fill_*_Trace` (sub-level film; a dry cut is `RM_Channel_Empty`). Judge 'wet' by fill terrain, not F>=1.
- **`RM_PitDrowning` is not evidence of a pit:** `RM_Swim` adds the same hediff on natural water, and jawas are small (H 0.5 m) so vanilla shallow water is over their heads. Read `flowworks_excavation_report` `excavatedCellCount` first (0 = no pit on the map).
- **On a power net with a battery, vanilla `CompPower` adds 'Grid excess: X W (Y Wd stored)' to a building's inspect string.** A status parser that skips only 'Power needed' reads it as the building's status (Cauldron `works_refines_condensate` false FAIL). Skip that line too.
- **A hose reel touching both a pump and a tank couples to the TANK** (`HosePortRule` ranks by kind first), so the pump is on no network with the reel's Intake end and nothing moves. Read the reel's inspect 'Connected to ...' line before scoring any hose row whose scene has a reel beside two machines.
- **Scenario hose tuples `(rx, rz, x, z, end)` set the free end's LOOK (cap/nozzle via `HoseProbe` `end:`), never its ROLE:** stage Intake/Outflow/Capped with a `calls` entry to `RM_LineProofs.ProofHoseRole`. A reel needs >4 squares of straight lead-out or the lay is refused ('no room for the straight lead-out from the nozzle'). To tell a stale lay from a planner bug, nudge a shape setting through `HoseProbe` (`set:minBendRadius=1.21`) to force every reel to re-lay, capture, then restore it (`set:minBendRadius=1.2`); the same pose means the planner chose it.
- **An intermittent-by-construction behaviour cannot be judged from one snapshot.** A job issued from the `Animal_PreWander` think-tree slot with a FarEnough gate and a short job expiry (shadow-following) is on/off by design: sample >= 9 times, spaced past the job expiry, and judge the counts (`src/RimMandrake/LongShade/prove_gloomcast_follow.py`).
- **A live-proof checker reading a `northstar_driver --out` file must exit 2 (UNMEASURED) when the doc has `refused` set or lacks the rows of its chain.** A row 'FAIL: no component X' from `component_proof.py` meant the driver REFUSED at preflight (e.g. one stuck UNKNOWN-outcome bridge marker poisoning every site step); no chain ran. Read the `refused` field before blaming the mod; an inline python exiting 1 on a refusal books game_fail on a run that measured nothing. Use `prove_rows.py` or a reader with the same 0/1/2 contract.

## Before you trust any run
- **A verify run must first prove the tree it imports contains the sha under test** (`git merge-base --is-ancestor <sha> HEAD` in that clone, recorded in the result). A run failed only because the clone's tree at call time predated the fix by 11 s. `WSLENV NAME/u` does NOT export WSL->Windows (`/u` is Win32->WSL only), so a `/u` entry is not a leak route. Never chain the check with `;` and let its silence go unread: stop if it prints nothing (a proxy test ran on a pre-fix HEAD and recorded a false FAIL that way).
- **Stage-by-stage proof hides the next failure:** each trial relaunch died at a later stage. Prove every arm past several tasks before calling a launch running.
- **Small mod lists test first; the whole huge list is one final verification pass** (owner: "small mod lists should always be the way to test until a final verification pass on the whole huge mod list"). A live proof declares the mods it needs (`live_proofs/<ID>.txt` line `live-mods: ModA, ModB`; proof side `northstar_driver` `cli.py needs-mods --mod X` reads the RUNNING load, exit 0 held / 2 not held) and passes on ANY game that holds them. A whole-list comparison is a separate clause at level GREEN-FULL: `relentless_live` gates it on the full tier (fewer than half of FULL.LATEST running -> UNMEASURED 'final verification waits for the full list', no proof, no ledger note, no restage) and `relentless_game` parks the item in phase `final`; the oldest final stages ONE full-list load for the batch (`final_batch_min` 4 or `final_wait_s` 8h). A full-list check run on another tier exits 2 (UNMEASURED), never 1 (a 23-mod game FAILed `GRAFFITI_NORTHSTAR_GREEN_FULL_1` A1). Never write a full-list equality as an L1/L2 clause.
- **A source-grep check whose regex a method declaration also satisfies passes on nothing.** Pin the call site (the line that invokes the thing), not the name; and when a rule must hold on every display or use path (owner, tremor, scar), assert each path, not only the first.
- **`RM_CompDhoggurSwell.DebugStateReport`'s `swollenArt` is False off-camera even when the `_Swollen` art is installed and draws:** it reads a static set only filled when the body graphic is built (on draw). Do not read `swollenArt=False` as 'art missing'. Owed fix: compute `ContentFinder` existence in the report.
- **`Building_LiquidPump` POUR drains only a tank marked Dump.** A Store `RM_LiquidTank` beside a powered pour-mode pump reads `running=True moved=0` forever. Stage it with ProofTank `'<x,z>;Dump;<LiquidDef>;<units>'`.
- **Count a decision where it is made, not where its effect is next consumed.** A skip counter placed in a path that runs only on an on-screen event (a section-layer regenerate) is blind to off-screen events (GSS `farSkips` never moved for an off-screen dig while the skip worked). A per-build timing read inside a rebuild storm (13.6 ms, an all-reused rebuild) says nothing about a cold planned build (220 ms offline).
- **Live FlowKernel `StepPulse` slices are not bounded by their cell budget, and the offline slice budget does not predict live slice cost.** r12 with 100 rigs on a 325x325 map ran 931 slices, mean 5.4 ms, max 161 ms, against an offline-predicted max of 2.6 ms.
- **A zero-alloc source pin must cover every function on the hot call path and every branch, not just where the stall was seen.** A pin on `RawFind`/`RawFindAt` missed `HosePorts.PumpSideTakes` (new List, ToArray, foreach over `IReadOnlyList` = boxed enumerator) and the `ById` >=2-candidates branch. Add a measured 0 B check with a sanity probe.
- **A proof that stops mid-run (GovernorStop, IndeterminateError) can leave Mod Settings changed** (a thirst proof left `filledBottlesPerColonist=1`; a sheet proof left the shipped-OFF `sheetOverflowEnabled` ON because its finally-restore was refused by an in-flight bridge call). Before handing the game back, run `preflight_flowworks.py live`, read row P-B4 (every FlowWorks setting at shipped defaults), fix what it names by hand and re-read.
- **`northstar_driver/cli.py record_result` crashes** (`ValueError: path is on mount 'D:', start on mount '\\wsl.localhost'`) when `--out` is on D: and the driver runs from a `\\wsl` path. It happens AFTER `--out` is written, so a wrapper reading `--out` still works but the driver exits non-zero and the run is not recorded. `validation_core._wait_playing` speaks the Guarded dialect (`_answer=True`): never hand it a modcheck Session directly (UnknownParameterError); wrap it. Every `load_game` on the minimal list raises VEF `Dialog_NewFactionSpawning` x16: answer with `quiet_site.QuietSite(controls=['modal_broker']).modals()` or the next preflight refuses (no_modal).

## Pre-port save fixtures
- **The FlowWorks hose census `geometryHash` hashes `r.lay`, which (with `layKey`) is NOT scribed:** a census read right after a reload hashes a null lay until the hose re-lays. A save/load proof must compare it on a settled re-read (`V.settle_census`), never pre-tick; a Carrying hose moves between the before-read and the save by design (SL4 judges it).

## Write it so Lightspeed can run it
- **Most owed live criteria cannot be generated from the suite.** Only 25 of 882 owed Relentless live criteria name a suite row id (2.8%), and 222 are cut at 160 chars on the ledger, where `owed()` refuses every proof for them. Re-recording criteria whole (tool `src/RimMandrake/rimflow/lightspeed_wire.py`) unlocks more lines than any matcher can.

## Harness, mock and testq traps
**When a new game or world will not start, read the FIRST exception in `Player.log`, not the loudest.** `rimworld/start_debug_game_ready` and `load_game_ready` work on the full mod list; every visible failure was a cascade from our own content. Three seen: (1) a `BiomeWorker.GetScore` calling `SurfaceTile.Rivers` NREs because the biome is not assigned yet during `WorldGenStep_Terrain` (terrain gen dies on tile 0, then loud `WorldPathGrid`/`WorldGrid.get_Item` out-of-range spam follows): read the raw `potentialRivers`; (2) a drug (non-`None` `drugCategory`) with no `CompProperties_Drug` NREs `DrugPolicy.InitializeIfNeeded` in `Game`'s constructor (`DrugBase` does not supply that comp); (3) a creature ThingDef naming a type from an inactive mod is discarded, and the raceless PawnKindDef it leaves kills `GeneticRim.Core`'s cctor, which stops starting-pawn generation. Harness: `src/RimMandrake/bridgetools/prove_quicktest_world.py`.
**The modal sweep's `jawa/window_list_close` answer "No open window's type name contains X" (`success:false`) is the CLEAN, normal result.** Recording it as an ERROR marks every verdict of the run `unknown`. Likewise `python.exe` cannot run git on a `\\wsl.localhost` checkout, so run identity reads `unknown` and no deploy is proven fresh: run git through `wsl.exe`.
**`scenarios_map.py --build` (even `--only C2`) and `review_map.py --plan` rewrite committed key sheets.** `scenarios_map.py --build` regenerates `northstar/review/scenarios/KEYSHEET.md` + `keysheet.html` for the subset it built: after any non-walk build, restore both with `git show HEAD:<path> > <path>`. `review_map.py --plan` (run to refresh `COVERAGE.md`) rewrites `northstar/review/map/KEYSHEET.md` and `keysheet.html` and once downgraded 4 stations from 'works in game' to 'built, not yet seen': commit only `COVERAGE.md` unless the keysheet change is understood. `scenarios_map.py --river --build` without `--fresh-map` builds on the CURRENT map whatever it is (0 of 8 stations placed and `review/scenarios/map_r_placed.json` rewritten): `jawa/set_current_map` to map R's id first, then restore the tracked `map_r_placed.json` / KEYSHEET the same way.
**`northstar_driver --mock` (generic `MockGame`, transport.py) lacks mod-specific tools and disagrees with its own config.** It has no `jawa/map_zones`, pens, husbandry jobs or `jawa/set_pollution`, so a mod whose chains need them FAILs every `site_ready_*` offline: that FAIL is the mock, not the mod (WeepingStones went PASS=11 FAIL=33 -> PASS=68 with 2 live-only set aside). Fix: the plan's `mock_extension(game, tool, p)` adopts the generic game as the mod's own selftest model (it must return None after adoption, or a model method delegating to `MockGame.handle` recurses), and rows needing a live map go in `MOCK_LIVE_ONLY`, set aside by name when UNMEASURED (a FAIL still fails). For a suite whose pads call `_reset_pad` -> `set_pollution` (Wastes), prove it offline with its own selftest (`src/RimMandrake/Wastes/selftest_wastes.py`). MockGame is built with core-only mods while mock_config writes the plan's EXPECT_MODS, so `jawa/running_mods` and the mock ModsConfig differ and the full-list selftest never exercises a LOADED foreign Graffiti member (compat rows only reach the 'member absent' path offline); owed: explicit mock running ids consistent with mock_config.
**`belt_watchdog` reads WEDGED ('repeating every frame', kill and relaunch) off a FINISHED burst** still in the `Player.log` tail: 100-1021 NREs from a load or section regen that happened once (e.g. Geological Landforms 'Failed to get info for world tile', 159/166 'Exception printing ...' lines), while the bridge answers and `ticksGame` advances. Before killing the game, count the line twice ~20 s apart, call the bridge, and check which 'Loading game'/'Initializing new game' block the burst sits in; a verdict should need the count to grow. The tool should measure only errors after the last 'Loading game from file' line.
**Game health alarm digs.** Each JawaBench session archives its `Player.log` at shutdown to `<LocalLow>/JawaBench/tps/logs/Player_<utc>_<sid8>_<sha>.log` (the live one is overwritten by the next launch); a managed-heap 'growth' breach on a bench session is usually map SIZE (924x924 = 13.7x a 250 map, heap ~3.6 -> 9.6 GB): read growth AFTER the last map change. `game_health_check.py explain --session <sid>` prints both. The archived log carries no stack traces, so `grep -c 'Verse.Log:Error'` reads 0 on a log full of errors, and Mono's `Process.WorkingSet64` read 0 in every full-list TPS context row: count errors from Verse.Log's message queue and read process memory via psapi `GetProcessMemoryInfo` (`JawaBenchSessionHealth.cs`).
**The testq idle-filler (`testq fill`, mods from `TESTQ_FILL_MODS`, default FlowWorks) re-runs the STALEST chains, not the ones missing evidence.** It keeps the lane busy re-greening one mod while mods with a `validation.py` and open items needing the bridge go untested. A filler must rank by evidence gaps (UNMEASURED/NOT_RUN rows, built items owing a live level, FAIL awaiting fix verify) across mods before any stale-green re-run. testq attempts keep no game log: `Player.log` rotates to `-prev` at the next cold start and is overwritten by the one after, so read a `no_game` HARNESS failure within one job (`worker.py` keeps it in `attempts/<id>/Player.log` for `no_game` only; other HARNESS deaths still lose it). A default live-site (`live_site.py --game`) puts a quicktest in front of every clause without its own site, so a build that breaks map generation reads 'site not prepared' (routed as harness, not a mod defect); SteveDesktop-inferred clauses still get no site.
**A modcheck site hold that raises a bridge timeout after a GREEN canary usually means the game stopped answering mid-run, not a noisy site.** Re-ask the canary before spending another chain (one run burned 4 chains x 30 s holds on one dead game).

## Selftests and the runner
- **`selftest_engine_review_leftovers.py` reads FAIL inside a detached helper's systemd unit** ("could not ask the OS whether RimWorld runs ... no tasklist.exe"): the unit's PATH has no Windows dirs, so the same test at HEAD fails there too. Read the first line of its output before blaming a change.
- **Attribute temp-dir size by `du` of the WHOLE dir before blaming a pattern.** The seat TMPDIR's '18G of leaked tmp* entries' was 78 MB of tmp*; the rest was pubclone (8.5G), harness scratch (5G), three `compose_RimMandrake.Biomes_*` dirs leaked by `biomes_compose.py:445` mkdtemp (1.4G) and `defs_copy.sqlite` (0.8G). To find which selftests leak, run each with its own fresh TMPDIR and list what is left (90 of 622 leaked). A new selftest should use `TemporaryDirectory` or the uniform atexit block that points `tempfile.tempdir` and TMPDIR at a private mkdtemp. Also: `/tmp` on WSL is a 32G tmpfs with `nr_inodes=1048576`, so 'disk full' can be inode exhaustion (leaked `selftest_*` mkdtemp dirs, ~19k from mutation runs, hit 100% inodes and Claude Code could not create `/tmp/claude-1001`, ENOSPC). Check `df -i /tmp`, not only `df -h`. Per-test TMPDIR is now removed after each run and `/etc/tmpfiles.d/rm-selftest-reap.conf` reaps on stevedesktop-wsl.
- **`run_selftests.py --only` takes file PATHS** (`src/.../selftest_x.py`), not bare test names; a bare name fails with 'names no such file'. Pass several paths after ONE `--only` (`--only a.py b.py`): repeating the flag silently keeps only the last and reports PASS 1/1, and a comma list is refused. Read the N/N count against the number of files you meant to run.
- **`run_selftests.py` shows only the head and tail of a test's ok lines**, so a failing test's captured output may not name the failing check (`selftest_dispatcher.py` failed once under 4 parallel tests, then passed four reruns; the check name was lost). Rerun the failing test alone and keep its raw output before calling a flake; the runner should print FAIL lines of a failing test. Under parallel load (load average 15, 6 workers) a selftest can CRASH [timeout] or FAIL a timing-sensitive check yet pass alone (arena_ralph_c, arena_tasks at 240 s, arena_judge, run_tmp 'once the users exit'): rerun a CRASH/FAIL directly, capture the full child output, and treat it as a flake until reproduced. A run_selftests red can also be an instrument fault: `selftest_role_launch_decide_mut.py` bakes its temp path into golden output, so it passes alone and reads FAIL (`decide_off_switch_and_window`, `decide_off_switch_on_event_run_is_not_spent`) under the runner, which nests TMPDIR as `selftest_run_<rand>/...` (the `norm()` regex only matches the old shape): read the want/got paths first. A CRASH with `OSError` ENOMEM (Errno 12) happens when sibling tests share `rm-harness.slice` memory (`selftest_tilefeatures_landforms.py` beside `..._landform_geometry.py`), and `selftest_timers_guard.py` (real throwaway timer, 110 s poll, `daemon-reload`) fails once on a busy 8-worker machine and passes on rerun. Rerun the test alone before attributing any of these to the product.
- **A selftest that swaps a function's default by POSITION** (`__defaults__[:-1] + (x,)`) breaks silently when the function grows a trailing keyword (clockgate.verify_pause's new `why=None` became a sleep function and six hazards read 'not paused'). Swap defaults by parameter name. `known_reds`' `first_error` can quote a suite's INTENDED negative-case FAIL line as the alarm title: read the summary line, not the first FAIL.
- **A selftest driving `ops_watch.main(['run','--file-alarms'])` files nothing once the live metronome phase table owns `rm-ops-watch.timer`** (`metronome.owner_of` reads the real table): stub `metronome.owner_of` in the fixture, or the WIRE checks go red with empty results.
- **`selftest_ops_ranges.py` counts every class of every ops_watch range against its own fixtures.** A commit that adds a range to `ops_watch_rules.json` must add a fixture there, or exclude the prefix with a comment naming the selftest that holds its fixtures, in the same commit, or the nightly goes red (e.g. `disk.root_fall_*`). Also, a mint prefix in `ops_watch_rules.json` is only proved by minting it: a prefix with no intent word stopped `rm-ops-watch` at its first crossing while every faked-mint selftest stayed green. `selftest_ops_watch` now mints each shipped name, and a mint failure stays PENDING instead of killing the pass; add a new rule's name there.
- **A stdlib import can load a module `sys.stdlib_module_names` omits** (`zoneinfo` -> `sysconfig` -> `_sysconfigdata__<platform>`). An import-purity check keyed on that set flags it as foreign; judge by the interpreter's stdlib directory instead (selftest_contracts C6).
- **A JSONL reader that catches only ValueError still crashes.** `json.loads` raises RecursionError on deep nesting (100000 levels on py3.14; 50000 decode), a non-UTF-8 byte raises UnicodeDecodeError at file iteration, a valid line that is a list/null crashes the first `.get()`, and a wrong-typed field crashes a comparison (int ts > str). Read lines through `contracts.jsonl.decode`, which never raises (fixtures: `src/RimMandrake/contracts/fixtures/expected.json`, rows marked DISAGREEMENT).
- **An age of ~498311 h from `scratch_reap` is `Tree.newest=0.0`** on a candidate or fixture dir removed between its listing and the `Tree()` walk (age = now/3600, 'epoch-old'), never a real stale dir (fixed in `fixture_age_h`/`base_row`). ops_watch's repeat of an already-open `SCRATCH_DIRTY_END` failed to file ('already exists') instead of reopening the open item.
- **A selftest that hand-builds the dict a builder returns (enact's plan `P`) instead of calling the builder breaks the day the consumer reads a new key,** and a crash (KeyError) is not a FAIL line: two enact selftests crashed for a week and 7 checks after the crash site never ran. When you add a key a consumer reads, `git grep -n '"sheet": ' selftest_*` for hand-built copies, and after any shape change run the whole directory's selftests, not just the one you touched.
- **A mutant restored in the same second can stay in charge via `__pycache__`.** Rewriting a `.py` in place and copying the original back leaves the mutant's .pyc live when the restore is the same size within the same second (pyc checks mtime-seconds + size), so the NEXT run of the original imports the mutant and stays red. Run mutants with `PYTHONDONTWRITEBYTECODE=1` and delete the module's pyc first. And `mutmut` 2.5.1 on Python 3.14: when the OUTER command timeout fires mid-run, it leaves the mutated source file in place and orphaned selftest processes running (one mutant was an infinite loop, k=1 in `_unique`). Run mutmut only in a scratch clone, keep a pristine copy via `git show HEAD:path`, give each mutant its own process-group timeout (`setsid` + `killpg`), and restore plus `git diff --exit-code` after every run.
- **A walled checker has no C# compiler in WSL, so a regex read of C# lets a logic mutant through.** For small Verse-free int math, translate the production `.cs` mechanically to Python (refusing unknown syntax) and execute it, and bind the committed DLL to its `.srchash` `# dll:` line plus the source rows (`selftest_pump_station_ports_compiled.py`).
- **A churn alarm 'unmeasured failed it N times' can be N blind checks of one reach gap, not N bad attempts** (4 UNMEASURED checks all failed to `readlink` host `/proc/<pid>/cwd` for `selftest_scratch_reap_tmp.py`). A reach fix only helps candidates rebased onto it. Before diagnosing, read the item's `attempts.jsonl` ends and its latest check verdict; a blind PASS after the last failure already reads the churn point 0 (`ops_watch.churn_why`).
- **A fake `subprocess.Popen` in a selftest must not report pid 0.** Code that `os.killpg(p.pid, SIGKILL)`s its child (`relentless_live.run_proof`) then kills the test's own process group, which shows as exit 137 with no output. Use a pid no process holds (`2**30`).
- **`selftest_dispatcher.py` takes ~7m44s with 0 failures, longer than `run_selftests.py`'s per-test timeout,** so `run_selftests --only selftest_dispatcher` reports CRASH (timeout) even when green. Run it directly with a 540 s timeout and read its tail, or raise its timeout with a `# selftest-timeout:` tag. It also refuses the literal `"restart"` anywhere in `dispatcher.py`; dispatcher keys and actions for the seat restart are named `seat_restart` / `restart_*` inside `seat_restart.py`.
- **scratch_reap selftests are sensitive to the machine.** Each `scratch_reap.Ctx`/`Live` costs a whole-`/proc` walk (~7 s at 52k paths on load ~15, far more under `run_selftests`' 6 workers): `selftest_scratch_reap_tmp` passed in 122 s alone and CRASHed [timeout] at the 240 s default in a 26-file `--only` batch, so reuse one Ctx (`copy.copy` and set `.now`) and tag `# selftest-timeout: N` for the rest. Fixtures live under `$TMPDIR` (a seat's `~/.seat-tmp/<SEAT>`, a root the real reaper scans) and any stranger's unreadable pid holds every fixture (`Live.blind`), so a run can RED/CRASH with no code at fault; a killed or concurrent selftest leaves undumpable fixtures that make every real run REFUSE (an all-REFUSE: look for `live_elsewhere` first). `main()` retries 3 times in fresh processes and only the parent takes the lock (a child taking it deadlocks); `selftest_scratch_reap_archive_tags.py` stubs the gate and runs under `/tmp`.
- **`DOTNET_LANE` in `run_selftests.py` is a hand list (15+3 names) but ~120 tracked selftests mention dotnet.exe/winbuild/stage_build.** Any that really builds C# beside the lane can CRASH [timeout] under nightly contention while passing alone in seconds (coldstorage: 4 s solo, 240 s timeout at night). Before calling a nightly timeout flaky, check lane membership.
- **Some selftests depend on live state and fail on a clean tree.** `selftest_conductor_closeout.py` reads the live transcript and the real ledger (for quotes), so it fails inside a Claude session holding real owner messages, and exits 1 with 4 FAILs (request check stores verdict and gaps, the wake stops printing a recorded verdict, goodbye hook close-out) on origin/main with the seat-restart change disabled; `selftest_mandrakepatches` 'shipped fixes vs the load-14 dump' needs `checked>=15` but counts only patches whose donor is in the LIVE ModsConfig (5 donors inactive reads 12 and FAILs). `selftest_block_frontier t_base_reader_tolerates_until` also failed on a clean HEAD (a `role_unit` stamp on fixture events).
