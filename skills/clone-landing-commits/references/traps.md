# Traps by topic

Lessons folded in from the lessons inbox, by the section of `../SKILL.md` they belong to.

## Recovery
| after a rewrite of origin/main, `ahead N` is false (stale tracking ref, blobs differ) | prove a push against the mirror, and excuse the rewritten commits by author+committer second; do not treat `ahead N` as work to land |
| `REFUSED: local commit X is NOT on origin/main` for a ledger commit whose every line is already on origin | seat_sync compares blobs, so once origin's shard has more lines the landed commit still reads NOT on origin (and `land.sh` keeps publishing while the clone stays diverged); check the lines by set difference against `git show origin/main:<shard>`, then drop the local copy of the shard and `./sync` |
| `REFUSED: dirty file(s) ... hold other bytes` although each file's worktree bytes equal origin/main | the index still holds your older staged copy (status `MM`), a third version sync will not drop: `git restore --staged -- <those paths>` (index only, never the worktree), then `./sync`; check with `git show origin/main:<p> \| cmp - <p>` |
| `selftest_relentless.py` CRASHes (`ModuleNotFoundError: contracts`, via `role_launch.py`) or `code_review_status.py mark-clean` crashes (`FileNotFoundError contracts/jsonl.py`) in a scratch clone | the default sparse set (Utils, rimflow, infrastructure, skills, .claude) lacks `src/RimMandrake/contracts`, which rimflow imports; nothing is wrong with the code: `git sparse-checkout add src/RimMandrake/contracts` (or pass `--sparse src/RimMandrake/contracts` to `scratch_clone.py clone`) |

## Traps
- **The Relentless blind checker reads `infrastructure/state/code_review` and `infrastructure/state/ledger` from the candidate's PARENT** (`tree_from_parent` in `relentless_rules.json`, `relentless_wall.make_box`). Review marks, or an item filed, in the commit you hand to finish are invisible to it: a clean-check clause reads DIRTY in the box and CLEAN in your clone, and a contract proof that reads an item filed in the same commit says 'has never been filed'. `mark-clean` refuses uncommitted bytes, so the order is: commit the code, commit the marks (and file any follow-up item the proof names) in an EARLIER published commit, then finish on a LATER commit whose parent carries them. A finish commit touching only `infrastructure/state/code_review` is refused; land the mark plus a lesson or test after it. A review-only item's `code_review_status check ... CLEAN` goes red whenever a later item edits its files before the blind check: on a rebase, rerun the check first and review only the delta since the clean mark. Prove it with a replica of the box, not by running `check` in the clone.
- **A rimflow guard test binds the test's exact bytes.** Once a guard test is shown red, grow it by ADDED lines only: editing any existing line (even a docstring) voids the red for the close gate (`repeat_guard.grown_from`), and so does resolving a `./publish` conflict in it by hand. Re-show it red: reverse-apply the item's own code diff (`git diff <fix~1> <fix> -- <code> | git apply -R`, or `git show origin/main:<code>` into place), run `rimflow guard`, restore with `git show HEAD:<f> > <f>`; then finish on a commit that changes something outside the ledger.
- **Helpers that rebuild or install in the seat clone (art install, sheet rebuilds, scratch code mirrored back) leave files byte-identical to origin/main as uncommitted edits, and `./publish` then refuses** ("origin changed a file you have uncommitted edits to").  For each dirty path compare `git hash-object` to `origin/main:<path>` and `git checkout --` only the identical ones; never stash/autostash the seat clone.
- **`tool_schemas.json` is generated:** on a publish/rebase conflict in it take origin's copy (`git show origin/main:<path> > <path>`) and rerun `python3 tool_schemas.py --supplement-only ../../bridgetools/JawaBench.BridgeTools` from `Utils/northstar_driver`; never hand-merge the JSON.
- **A blind `sed` rename (`s/Defunct/Wrecked/`) also rewrites words inside the owner's verbatim quotes.** Exclude quoted text, or check `git show` of the pre-rename commit.
- **In zsh a variable holding a string of paths (`$P`) is not word-split;** use an array when passing several paths to `git` (e.g. building a private-index commit).
