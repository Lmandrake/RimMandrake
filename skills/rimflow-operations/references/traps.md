## 1. Check an account's level (read-only, safe anywhere)
- **Exact `/usage` with no model call.** `claude -p /usage --output-format json --no-session-persistence` (num_turns 0, cost 0) puts the session/week % used and reset lines of the interactive `/usage` in `.result`, for whatever login `CLAUDE_CONFIG_DIR` points at. Pair it with `claude auth status` in the same env to prove which login answered. Never run it against a dormant vault login whose access token is near expiry: Claude Code refreshes and rotates the credential under `claude-account`.
- **`switching_plan.py status` 'The week ahead at R %/h' is the POOL PACING rate** (budget left / hours to deadline: what the plan would like to spend), not the measured burn. Do not quote its times as a forecast. For a switch time, divide pct-to-line by the slope of `week_pct_used` in `/mnt/d/ClaudeWork/rimmandrake/account_usage/series.jsonl` (measured ~2.8%/h when the pacing said 6-7).

## 2. The standard switching plan (rulings and provenance)
- **A switch plan that changes WHICH account the owner sits on must cite his words for each leg.** An agent revision ('use it or lose it', no owner quote) kept the fleet on lukas past a planned switch back to system, which refilled to 100% while lukas burned nothing; and every relaunch must start the seats, or the windows open idle.

## 5. Stand-down / stand-up costs (why switches are not free)
- **`claude-account warm <acct>` is NOT safe on the live login.** `warm_one` only observes a LIVE account while Claude processes run; with none running it runs `claude` on the live login (a refresh of the live credential). A dormant-only warm must first prove the account is live nowhere: `account_usage.poll` checks the switcher's own status and every remote's status and skips any live label.
- **A relaunched Claude window is not a working seat until it gets a first prompt.** The WT seat profiles (`install_wt_seat_profiles.py`) launched `claude` with none, so every boot or account-switch relaunch opened BENCH and FOUNDRY idle until someone typed wake; the fix is `WAKE_PROMPT` as a positional after `--remote-control '<label>'` (measured 2.1.308: not swallowed as the RC name). The live Artist profile had drifted from the installer, so a bare `--apply` rewrites tiles you did not mean to touch: use `--only SEAT,SEAT` and diff live vs `build()` first. A seat restart relaunches in the SAME tile (`seat_loop.sh` execs the killed record's argv) because `launch_fleet` opens a new tab and orphans the old tile; `launch_fleet -Seats <SEAT>` is only the fallback (its path from the systemd-run Dispatcher through WSL interop is UNMEASURED and gets no first prompt). A `/clear`'d idle window reads 'not quiet' and holds.
- **A Dispatcher-started restart over the hard context limit stays held** ('no boundary yet, last record assistant_tool') for as long as the window sits on an unanswered AskUserQuestion card, and `restart_reconcile` then alarms `OPS_RESTART_UNSTICK_*` after `restart_reconcile_held_s`. Read the tail of the seat transcript first: a pending card means it waits on the owner and nothing is broken.

## 6. Throttles and timers
- **`slot_allocator`'s message-count rate fallback counts only THIS machine's assistant messages;** another machine on the same account (SteveDesktop on system) is invisible to it, so the measured %/h reads low until the `account_usage` series has >=4 points over >=1.5 h and the slope takes over.
- **Never stop timers for a cutover without a resume armed in the same command** (`systemd-run --user --on-active=6h systemctl --user start $(cat list)`, or `timers_guard.py pause --hours H --all`): a mass stop of every `rm-*`/`testq-*` timer killed the no-LLM lanes for hours, and every watchdog was inside the stopped glob; it also stops `timer-guard`, so the guard cannot see it. To find who stopped a unit: the system journal's tailscaled 'starting non-pty command' lines carry the full remote command, `journalctl -g 'audit: SSH login'` names the peer, and `Unit now frozen` or a same-second mass 'Stopped rm-*.timer' in the user journal means a hand-run pause; search that day's transcripts for `systemctl --user (stop|freeze)` before suspecting systemd or a WSL boot drop.

## 7. Traps
- **Account handover links (`account_handover.py`) are armed one transient systemd link at a time and are allowances that must end.** After a link fires, check the now-live account has its own onward link (`systemctl --user list-units 'rm-account-handover*'`) or it drains to 0% while the next account in order sits full. A one-time link writes `<from>_to_<to>.done` and then ticks forever as a spent timer, and an armed link with no end outlives the grant it carried: arm with `--until <reset ISO with offset>`, end with `account_handover.py retire --why` (stops `rm-account-handover-<from>.timer`). Its `--dry-run` still appends to the real `log.jsonl`, so a proof grepping that log must require dry_run false.
- **Relentless reach repair.** An UNMEASURED blind check no longer re-checks on a clock and is not cleared by `unhold --offbox` (`relentless_reachfix.py`, rule `reach_repair`): the first blind check blocks the item (wait kind `reach`), the Judge's `--propose` (adapter name or read path) is probed from inside a throwaway Marker wall and applied as a store overlay, then the same sha is checked once. One item per gap class owns the repair and the rest wait on it; a ticket (`reach_classes[].ticket`) is filed only when the probe fails. Do not unhold a reach-blocked item: fix the probe's gap or close its ticket, which triggers one re-probe. Store book: `<store>/reach_gaps.json`.
- **When an escape condition changes, re-check every throttle that guarded the old one.** A 'soft line' DARK that is right while there is nowhere to go (before the other account resets) becomes a trap once a fresh account exists: a DARK fleet barely moves the meter, so a switch gated on reaching the floor never fires and the fresh week idles. Also, a marker deleted on 'status unknown' after a failed switch can strand later recovery: keep it pending until the live account is positively known.
- **A restart in its grace (`pending`) must not fence the Dispatcher's ring/recover for the seat:** if the window dies during the grace, nothing recovers it. Only `claimed`/`killed`/`relaunched` own the seat.
- **Companion-grant renewal is the owner's consent, not an agent call.** The wire grant only warns (`ops_watch` alarm `OPS_GRANT_ASK_*` under 12 h) and `rimflow next` preflights it; do not build auto-renew unless the owner rules it and a new item is filed.

## Units, timers and hooks
- **`daemon-reload` restarts the count of a `systemd-run --on-active` timer** (a 30 s timer with a reload at +20 s fired at +50 s; an `--on-calendar` one fired at +30 s). Selftests and deploys reload often here, so a delay beyond a few minutes needs `--on-calendar`. A transient `--on-active` timer also stays loaded after it fires (`RemainAfterElapse` defaults to yes), so reusing a fixed unit name is refused until it unloads: pass `--timer-property=RemainAfterElapse=no`.
- **Deleting a watched trigger file after judging it spent races its writer** (re-read-then-unlink still loses a replacement). Rename it aside atomically, judge the moved bytes, `os.link` back (never overwrites), and sweep old `.tmp`/`.aside` leftovers or a PathExistsGlob unit re-fires for ever.
- **`StandardOutput=file:<path>` does not truncate, and an `ExecStopPost` shares it.** The file reopens at offset 0, so `rm` it first or you read the previous run's tail, and anything a post command prints overwrites the HEAD of the main command's output (a wrap-up unit printing one line made every role run's result JSON unparseable). Post commands on a `file:` unit must print nothing, or the unit must use `append:`.
- **`INVOCATION_ID` is inherited by every child of a systemd service, agent shells included,** so 'am I inside a systemd unit' must never be inferred from it (a no-systemd fallback reported a unit name that did not exist and `stop` killed nothing). Pass the unit name down explicitly (testq `worker.py` sets `TESTQ_UNIT` via `systemd-run --setenv`) and fall back to the pid when `systemctl stop` fails.
- **Never start a private `systemd --user` (or dbus) from a seat's Bash.** It enables the memory controller in `subtree_control` of the seat's `claude-code-bash` cgroup while processes live there, and every later Bash call in that seat fails with EBUSY on clone3 until `-memory` is written to `.../claude-code-bash/cgroup.subtree_control` (use the Write tool; Bash itself cannot run). Rehearse units with a fake `systemctl` shim plus a pure Conflicts=/PartOf= graph check. Leftover scratch from such a run has root-owned `run/systemd/inaccessible` entries that `rm` cannot remove.
- **A background Bash that `exec`s loses its shell-snapshots cmdline.** `/proc/<pid>/environ` keeps `CLAUDE_CODE_SHELL`, which Bash-tool shells carry and hooks, MCP servers and the window itself do not; match a Bash-tool child by environ too (`seat_restart.background_commands`).
- **Relaunching a detached helper with a corrected brief does not stop the first unit.** Both ran and the old brief's output landed over the new run's file. Stop the old unit by name before relaunching, and have a run re-read the file it will edit just before editing.
- **`timers_guard.read_states` lets a `TimeoutExpired` from its own list calls escape as a traceback** rather than the RuntimeError its docstring promises: a stuck `systemctl` fails `timer-guard.service` loudly and writes no reading, so ops_watch's failed-unit watch sees it but the guard itself does not alarm (known, left as is).
- **Dispatcher journal: an ACCEPTED Designer stage result is logged `do=role_stage` with `kind=role:Designer:stage_rejected`** (`role_launch.py` uses one kind for both branches). Grep the why text ('accepted'/'REJECTED') or `do=alarm`, never the kind, to tell a rejected stage.
- **A `--live` reading must be a file the unit rewrites EVERY run.** `scratch_reap`'s `alarms.log` is written only on a new refusal, so a promise on it ages out with the unit healthy; use `last_run.json` (guard: `selftest_scratch_reap_live_reading.py`).
- **`systemd-run` expands `${VAR}` in the command it is given,** so a `bash -c` body with `${PIPESTATUS[0]}` becomes a bare `exit` and a failed build read exit 0 inside a walled unit. In a toolchain or probe command use `set -o pipefail`, or write `$$`, never `${...}`.
- **`rename(2)` over a symlink is not lookup-atomic on this ext4:** a reader stat'ing through it got ENOENT 3 times in ~116k reads under 5,000 `os.replace` swaps (0 on tmpfs); a second look finds it. A swap-a-symlink deploy must treat a single miss as transient (a oneshot starting in that instant fails and its timer retries).
- **`seat_restart.py request` refuses from a systemd unit** (no `~/.claude/sessions/<pid>.json` for the calling window), so a timer can never start a fresh Conductor window through it; a timed backstop must go through the Dispatcher's role launch.
- **A leading `-` on a systemd `ExecStart` (`ExecStart=-/usr/bin/python3 ...`) makes the unit report success whatever the step exits,** so an UNMEASURED exit 2 goes unseen. Use `-` only for a step whose failure is truly harmless, and say why beside it (`findings_fold` in `testq-tick.service` was fixed this way).
- **A session that dies alone between dequeuing a prompt and persisting it to its transcript loses that prompt, and nothing in `seat_restart`/testpilot can see it** (TLC row d_old_alone_gap violated the no-loss property in 69 states; the fixed protocol passes only with that hazard excluded). UNMEASURED: whether the CLI persists before it acks the dequeue, and whether a SIGTERMed process's transcript still accepts a prompt. Measure both before claiming no-loss on process death.
- **Moving a directory tree under live daemons: stop first, then move.** Stop every unit that runs working-tree code before editing paths (transient `systemd-run` timers vanish on stop, so record their recipe first), kill Windows readers by PID, then a same-drive `mv` is instant. Units still running a stale clone's code cannot read the `RM_DATA_ROOT` seam and need env overrides (`ARTPIPE_STATE_DIR`, `OBS_DIR`, `WINBUILD_ROOT`, `RM_PULSE_DIGESTS`).
- **Kill a Claude window by pid only after binding the pid to its registration.** Compare Claude Code's `sessions/<pid>.json` `procStart` with `/proc/<pid>/stat` field 22 (same clock ticks, measured equal), and signal through `os.pidfd_open` after re-checking the start time. Any pid recorded later than the registration may already be a reused pid.
- **Two launchers racing for one relaunch must share one `O_EXCL` marker and one deadline written into the kill record.** The give-up alarm must never fire while a tile may still claim; otherwise the owner's manual reopen plus a late tile claim launch two windows.
- **A daemon unit's `WorkingDirectory` is part of a deploy.** `rm-artpiped` ran from the retired foundry clone through a drop-in `zz-foundry-workdir.conf`, so fixes landed on main never reached it. After a fix to a daemon, check `systemctl --user show <unit> -p WorkingDirectory` and that clone's HEAD.
- **A timer's cadence is read by its consumers' staleness thresholds.** Before slowing a timer, grep for the age limit that watches its output (testq `steward.py` `STALE_S=300` assumes a 60 s `testq-tick`; a 5-min slow-down would raise false STALE_HEARTBEAT incidents).
