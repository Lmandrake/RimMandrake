# Ideoligions — design, author, validate, judge

**Four jobs, and you are only ever in one of them. Pick it before you read further.**

| I want to… | Go to | Reference |
|---|---|---|
| **DESIGN** — invent a religion that changes how a campaign plays | §2 | `references/design.md` |
| **BUILD** — write the XML | §3 | `references/authoring.md` |
| **TEST** — prove it built as specified | §4 | `references/validation.md` |
| **EVALUATE** — judge someone else's religion | §5 | `references/rubric.md` |

Words that this skill uses:

- A **meme** (`MemeDef`) is one belief of a religion. A **structure meme** is the one meme that sets the worship room.
  All other memes are normal memes.
- A **precept** (`PreceptDef`) is one rule of a religion, for example "no mining". An **issue** (`IssueDef`) is the
  subject that its precepts take a position on.
- The **generator** is the game code that makes an `Ideo` at world generation.
- The **def dump** is the file set of every def that a live game loaded. `DEF_DUMP` in
  `src/RimMandrake/Utils/game_paths.py` is the path of the newest dump.

The counts in this skill come from the dump of 2026-11-23 (314 mods), if the line does not say otherwise. Old counts
and corrected lines are in `references/history.md`. The counts in the other reference files are from 2026-08-14.

**The installed vocabulary is not in this skill.** The palette file lists each legal defName:
`D:\Luke\dev\RimMandrake\design\Jawa\worldbuilding\data\ideology_palette.md`. The command
`python3 src/RimMandrake/Utils/ideology_palette.py` regenerates the palette from the live def dump. The `_Generated by` line near
the top of the palette gives its capture date. If the capture date is older than the last change to the mod list, regenerate the
palette first.

**Never write a defName you have not read out of that file.** If a `FactionDef` names an uninstalled meme, the faction
generates without the meme. The only sign is one red line in `Player.log` (§4).

## 1. The one fact that reorganises everything else

🔴 **There is no `IdeoDef`.** An `Ideo` is a runtime object. The game builds it at world generation and stores it in the
save. Nothing in XML *is* a religion. XML only **constrains what gets generated**. Two routes exist. Neither route does
what a modder expects:

| route | reaches | can set memes | can set precepts |
|---|---|---|---|
| `IdeoPresetDef` | the player's start screen only | ✅ `<memes>` | ❌ **no field exists** |
| `FactionDef` ideo block | NPC factions at worldgen | ✅ | ❌ **no whitelist field exists** |

🔴 **Neither route can list the precepts a religion holds.** The only precept field of `FactionDef` is
`disallowedPrecepts`, a *blacklist*. The complete field set of `IdeoPresetDef` is
`categoryDef · iconPath · classicPlus · memes`. The dump has 46 presets.

**So a design document with a "Precepts (8)" table is not a build spec.** The precepts come from the memes:

- Each `MemeDef` can carry `requireOne`, a list of groups. The generator takes one precept from each group.
- The generator skips a precept that another rule refuses. Such rules are `disallowedPrecepts`, `conflictingMemes`,
  `requiredMemes` and a shared issue. If every precept of a group is refused, the group gives nothing.
- Then the generator adds random precepts. The draw uses the precepts that name one of the memes in
  `associatedMemes`. The generator also fills an empty issue, if a legal precept of that issue has a nonzero
  `defaultSelectionWeight`.
- **Choosing memes is how you choose doctrine.** `requiredPreceptsOnly` means "take *only* those": no draw by impact, no
  fill of empty issues and no specialist roles (`Precept_RoleMulti`). The religion still gets its rituals, its leader,
  its moralist and the other precepts outside the precept limit.

⇒ **A precept table is a design artefact and a review artefact — never an authoring artefact.** The table is still
worth the work. §5 judges the table, and a person copies it into the in-game ideo editor. But the person who writes the
XML cannot use the table directly. Say which one you are producing.

## 2. DESIGN — what makes a religion interesting

Full treatment: `references/design.md`. The four rules that matter most:

1. **A religion is interesting when it *forbids something the player would otherwise do by reflex*.**
   `TreeCutting_Prohibited` is a better design than any three mood modifiers. The player meets that precept
   on turn one, and nobody has to say that the religion exists.
   🔴 **But that example is for the player's religion. That example does not transfer to an NPC faction:**
   - `TreeCutting_Prohibited` has `defaultSelectionWeight: 0`, and the `requireOne` of no meme can yield it. Its only
     route to an NPC faction is a random draw for a religion that holds `NaturePrimacy`. The draw is never sure, and
     `requiredPreceptsOnly` stops it.
   - `Mining_Prohibited` has the same random route. `Mining_Prohibited` also has `enabledForNPCFactions: false`. Its refusal and its
     thoughts do nothing on an NPC pawn (§6).
   - No XML route whitelists a precept (§1). So **the design that forbids a reflex is reachable for the player and
     largely unreachable for an NPC faction.**
   - Design an NPC religion from memes that *guarantee* a refusal. Only 20 of 139 memes do.
     `references/design.md` §2.2 lists the 20.
2. **Belief is only visible through friction.** If no action ever triggers a precept, the player never sees the precept.
   Good prose does not change that. Rank every precept by *events per campaign hour*, not by flavour. The rubric of §5
   counts that ranking.
3. **Collide it with the player's religion, not with a stat.** The best example is faction 5 (Free Droid Enclaves) in
   `design/Jawa/worldbuilding/faction_religions_spec.md`. That one faction could hand the player the galaxy. Its
   religion holds that the labour model of the player is murder. So the player must make a *decision*, and decisions are
   the deliverable.
4. **Name-blind test.** Remove the names from the religions of two neighbouring factions. If a player could not tell
   which is which, one of the two religions is decoration.

🔴 **Impact is a RATING, not a budget.** `MemeDef.impact` is an integer. All 36 structure memes have impact 0. Of the
normal memes, 26 have impact 1, 50 have 2, 23 have 3 and 4 have 4.

- `MaxMemeImpact = 3` and `MaxCombinedImpact = 9` exist in `IdeoImpactUtility`. The two constants only clamp the label that the game
  shows. The presets `VME_Inhuman_Ravagers` and `VME_Insectoid_Psykers` both total **10**.
- **The ceiling is a COUNT, and only the editor enforces it.** `MemeCountRangeAbsolute = 1–4` normal memes (the
  structure meme is not counted). A random NPC religion starts with 1–3 normal memes. Other limits:
  `MaxStyleCategories = 3` and `MaxRituals = 6`.
- `forcedMemes` has no clamp. The game accepts five normal memes in silence. Keep to the count yourself.
- **Never pass `--impact-budget` to the validator.** Its default, `None`, is correct. Derivation:
  `references/authoring.md` §meme budget.

## 3. BUILD — the authoring layer

Full field reference, skeletons and `MayRequire` rules: `references/authoring.md`.

**Copy the Horax cult, not the Empire.** The Horax cult is the only vanilla example of a fully *authored* NPC religion.
The file is `C:\Program Files (x86)\Steam\steamapps\common\RimWorld\Data\Anomaly\Defs\FactionDefs\Factions_Misc.xml`,
lines 44–71:

```xml
<fixedIdeo>true</fixedIdeo>                     <!-- the authored fields below replace the random ones -->
<ideoName>Nightmare Deep</ideoName>
<ideoDescription>…</ideoDescription>
<hiddenIdeo>true</hiddenIdeo>                   <!-- keep it off the ideo list UI -->
<deityPresets>…</deityPresets>                  <!-- replaces the random gods; deityCount 0 is allowed -->
<styles><li>Horaxian</li>…</styles>
<forcedMemes>                                    <!-- the COMPLETE set, structure included -->
  <li MayRequire="Ludeon.RimWorld.Ideology">Structure_Archist</li>
  <li>Inhuman</li><li>Ritualist</li>
</forcedMemes>
<requiredPreceptsOnly>true</requiredPreceptsOnly>
<disallowedPrecepts>…</disallowedPrecepts>
```

The Empire (`…\Data\Royalty\Defs\FactionDefs\Faction_Empire.xml`) uses the other family of fields:
`requiredMemes` + `allowedMemes` + `structureMemeWeights` + `disallowedPrecepts`. That family of fields *constrains
a generated* religion. That family does not author a religion.

| field | meaning |
|---|---|
| `fixedIdeo` | build a religion for this faction alone, then apply `ideoName`, `ideoDescription`, `deityPresets`, `styles` and `hiddenIdeo`. Without `fixedIdeo`, the new religion gets none of those five |
| `forcedMemes` | **the complete meme set**. It also works without `fixedIdeo`. If it holds no structure meme, only `structureMemeWeights` or `requiredMemes` can supply one. Do not use `requiredMemes` with it: a required meme outside `forcedMemes` is a red `ConfigError`, and one in both lists is added twice |
| `requiredMemes` | must contain these; the rest is randomised |
| `allowedMemes` | the random remainder may only draw from these |
| `disallowedMemes` | never pick these |
| `structureMemeWeights` | weighted pick of the structure meme |
| `requiredPreceptsOnly` | no random precepts (§1). It also works without `fixedIdeo` |
| `disallowedPrecepts` | blacklist (**the only precept field**) |
| `deityPresets` | named gods; needs `fixedIdeo`. The presets replace the random gods at any `deityCount` |
| `hiddenIdeo` | hide from the player's ideo list |
| `classicIdeo` | give this faction the Ideology-off fallback set |

- With `fixedIdeo`, always write `ideoName` and `ideoDescription`. If one is absent, the game sets that text to null.
- A faction without `fixedIdeo` does not always get a new religion. The game can give the faction an existing generated
  religion that passes its meme lists. The chance is 20%. For a hidden faction, or when 10 generated religions exist, the
  game always tries that first.

🔴 **Wrap every modded def in `MayRequire`.** If the mod is off and the name is not wrapped, the game drops the name and
logs a red line (§4). If the name is wrapped, the game drops it in silence. PackageId table: `references/authoring.md`.

## 4. TEST & VALIDATE — the protocol

Full protocol: `references/validation.md`. A script does the offline half. Give it one input flag:

```bash
python3 src/RimMandrake/Utils/validate_ideoligion.py --xml <FactionDef file or directory>
python3 src/RimMandrake/Utils/validate_ideoligion.py --md <spec.md>      # or --spec <file.json>
```

If the live mod list is not the full list, also pass
`--mods-config infrastructure/state/modlists/ModsConfig.FULL.LATEST.xml`. Without that flag, each modded meme reads
`def/inactive-mod`, and each religion that holds one reads INVALID.

**Offline, before any game load.** The script has 33 finding codes. 17 of them can be ERROR, and an ERROR makes a
religion INVALID. The main ERROR checks:

- every defName exists in the live dump;
- the religion holds one structure meme and only one;
- no two held memes share one of their `exclusionTags`;
- no precept names a held meme in `conflictingMemes`;
- no precept has `visible:false`;
- each precept that has `requiredMemes` has one of them in the religion.

The `deityCount` of a structure is an `IntRange`. A deity count outside that range is a **WARN, not an ERROR**. Such a WARN cannot
make a religion INVALID.

🔴 **The script does NOT check `MayRequire`, and it looks like it does.** `def/needs-mayrequire` is an **INFO**. The code prints
the attribute that you must write. Nothing checks that you wrote it: `from_xml` reads `li.text` and never reads
attributes. **No offline check finds a missing `MayRequire`. Read the XML yourself, every time.**

**Only a game load can prove** that the game *built* the ideo. The load shows four things:

- `fixedIdeo` took effect, and the memes are exactly yours;
- the generator did not substitute another religion;
- the deity names appear;
- the styles resolved.

The bridge tool `jawa/ideo_of` reads the memes, precepts, key deity and factions of each built ideo. `jawa/ideo_of` does not list styles.

`references/validation.md` §4 (live) holds the dev-mode route and the lines to read from `Player.log`.

### 4b. 🔴 A SAVED ideo is a different artifact, and the validator above cannot read it

`validate_ideoligion.py` reads **XML you author**: the `FactionDef` ideo block, or the same block in a patch. A `.rid`
(saved ideoligion) and a `.xtp` (saved xenotype) are **Scribe output from a running game**. Scribe is the game's save
writer. Such a file has tab indents, `Class="..."` attributes and `IsNull="True"` marks. For such a file the authoring
validator prints `no religions found in the input` and exits 1. **The validator checked nothing.** The exit is not a verdict on
the file.

Use the other tool:

```bash
python3 src/RimMandrake/Utils/validate_save_artifact.py "<file.rid>" "<file.xtp>"
```

The tool looks up every def reference in the def dump. Its exit codes:

- `0`: no reference dangles, and none is cut. Read the output too: `UNMEASURABLE` and `TYPE MISMATCH` references also
  exit 0;
- `1`: dangling (a reference resolves to no def), or a reference names a def that the Cherry Picker mod removes;
- **`2`**: **UNMEASURED**. The tool could not look (no dump, or an unreadable file). Never conflate 2 with 0.

**Why this matters more than authoring validation: an ideo BAKES AT WORLD CREATION and cannot be retrofitted.** The
owner loads the saved file at the one irreversible moment. A faction that is absent at that moment has the same property.

**The trap: a precept `<li>` nests other def types inside itself.** One agent read every `<def>` element and checked
all of them against `PreceptDef`. The agent reported **71 missing precepts. Every one was false.**

```xml
<li Class="Precept_Ritual">
  <def>AM_FuneralNoCorpse</def>                            <- PreceptDef
  <behavior><def>Funeral</def></behavior>                  <- RitualBehaviorDef
  <outcomeEffect><def>AttendedFuneralNoCorpse</def></...>  <- RitualOutcomeEffectDef
  <obligationTargetFilter><def>AnyEmptyGrave</def></...>   <- RitualObligationTargetFilterDef
  <targetFilter><def>SelectedThing</def></targetFilter>    <- RitualTargetFilterDef  (a DIFFERENT type!)
```

⚠️ `RitualTargetFilterDef` and `RitualObligationTargetFilterDef` are two types. Their names are almost the same, and some
of their member names are the same. Do not guess the type from the name.

**The rule that makes this safe: a reference is MISSING only if it resolves against NO def type at all.** If a reference
resolves but has an unexpected type, the tool reports a softer `TYPE MISMATCH`. The tool never reports such a reference as
missing. So a wrong guess costs a note, not a false defect.

⬜ **And "absent from the dump" is not "absent from the game."** A dump can hold no rows for a def type. Each reference
of that type then reads `UNMEASURABLE`. Such a reading is a hole in the evidence, not a result, and the tool prints it as its own
class. Never change such a reading into a pass or a failure. An old dump had no `AbilityDef` rows; the current dump does.

**These values are not references.** The values look like defNames and resolve to nothing. The first run of the tool read them
as defs, and that made 73 false positives:

- `precepts/li/name` (the display name, for example "population", "trading", "junk");
- `labelKey`, `buildingTags/li`, `patternGroupTag` and `usedSymbols`;
- the `modIds`/`modNames` block, which records the mods at save time;
- runtime handles such as `Precept_6309`;
- the frequency and gender enums (`MaleUsually`, `Uncommon`, …).

📌 The `<modIds>` block is **provenance, not a dependency list**. A mod in the block that no longer loads is expected and
harmless. Such a mod matters only if a *reference* also fails to resolve. The line
`provenance list: UNMEASURED` means that the tool could not read the live mod list.

**What an authoring mistake does in the game.** Only the first mistake makes a red line in the log:

| mistake | what the game does | the validator finds it |
|---|---|---|
| an uninstalled defName, or a missing `MayRequire` on a mod that is off | drops the name. `Player.log` gets one red `Could not resolve cross-reference` line | the defName yes; the missing `MayRequire` never |
| an uninstalled defName inside `MayRequire` of a mod that is off | drops the name in silence | yes |
| a meme exclusion collision in `forcedMemes` or `requiredMemes` | keeps both memes in silence. The random draw and the editor refuse such a pair; these two lists do not check it | yes |
| a precept whose `requiredMemes` are absent | does not add the precept, in silence | only from `--md` and `--spec`; XML carries no precepts |
| a deityPreset without `fixedIdeo` | ignores the preset, in silence | no |

A deityPreset on a `deityCount 0` structure is not a mistake when `fixedIdeo` is true. The game shows the named god.

---

**A `.rid` that loads on a smaller mod list fails in two ways:**

- `Ideo.ExposeData` drops a precept whose own def is missing, and a ritual precept whose `behavior` is null. The log gets one red line for all of them:
  `Some ideoligion precepts were null after loading.`
- A RITUAL precept can survive half-built. Its own def exists (Festival, a Core ritual precept). But its
  `sourcePattern`, behavior def or outcome def, or a `Class`, is from an absent mod. Such rituals threw `PostLoadInit`
  NREs (null-reference errors) at every load. In the source, a missing `sourcePattern` or outcome def throws there.

`validate_save_artifact.py` does not see the second failure. The tool checks names against the newest dump, usually a
dump of the FULL list. The tool does not check `Class=` attributes. So 246/251 references of one file passed while the
dev world logged ritual NREs. Check a `.rid` against the packageIds of the target list.
`src/RimMandrake/Utils/remake/salvation_paint_clean.py` shows how: its docstring gives the rules, and its `--check` run
prints the removal list for the PAINT mod list (`infrastructure/state/modlists/ModsConfig.PAINT.RULED_2026-10-20.xml`).

## 5. EVALUATE — judging a religion

Full rubric, scoring and a worked example: `references/rubric.md`.

**Two independent verdicts. Never merge them into one number.**

- **VALIDITY** is mechanical and falsifiable. The script runs the checks in §4. If any error fires, the religion is
  `INVALID`. There is no partial credit. For example, if two memes collide, no random draw and
  no editor session can make that religion.
- **INTEREST** is counted, not felt. The rubric scores six axes, and each axis has a stated measurement. The number of
  *encounters per campaign* sets the ceiling. The quality of the prose does not.

**Verdict form:** `VALID/INVALID · interest N/18 · <one sentence naming the single
thing that would most improve it>`.

## 6. Traps

- **`classic: true` is NOT the do-not-author marker; `visible: false` is.** 50 precepts carry `classic`. The 50 include
  `IdeoRole_Leader`, `Funeral`, `IdeoRelic` and `Corpses_Ugly`, and all four are legitimate. 31 precepts have
  `visible: false` (`Cannibalism_Classic`, `LeaderSpeech`, `Trial`, `Conversion`, `Execution`, …). Those belong to the
  engine. Never hand-author one.
- **`enabledForNPCFactions: false` switches off most effects of 36 precepts on NPC pawns.** The 36 include
  `DrugUse_Essential`, `Comfort_Essential`, every `Violence_*` and three of the five `Nomadism_*`. The generator can still
  give such a precept to a faction religion. But its refusals act only on pawns of your faction. Its hearsay thoughts
  and its mood thoughts act only on your colonists, slaves and prisoners. Social (opinion) thoughts still act on an NPC
  pawn. So does a `PreceptComp_SelfTookMemoryThought` (13 of the 36 have one). A faction design that names one gets a tooltip, or a mood change that the player
  never sees. The validator reports it as ERROR `precept/npc-disabled`.
- **Meme collisions are `exclusionTags`, not a conflicts list.** Two memes that share a tag must not be in one religion.
  `Loyalist` + `Supremacist` both carry `GroupRelation`. `Transhumanist` + `VME_Fleshcrafters` both carry
  `FleshAugmentation`. Our faction specs once held both pairs, and both pairs are illegal. The table in §4 says what
  the game does with such a pair.
- **Every `fixedIdeo` religion is marked `solid`, and vanilla takes the first `solid` religion as the Horax religion**
  (`IdeoManager.Horaxian`). With several fixed factions, that religion can be one of ours. A baby then gets no exposure to
  that religion, and `IdeoChangeToWeight` gives it weight 0. Read in the source, not seen in game.
- **`Charity` has no negative position.** The issue has `Charity_Essential/Important/Worthwhile` only. "Charity: abhorrent"
  cannot be said.
- **`PreferredXenotype` picks its xenotype at ideo-generation time, not in XML.** The precept can appear only when the
  `xenotypeSet` of the faction has exactly one entry, and then by chance. Species composition comes from the xenotype
  chances of the `PawnKindDef`.
- **Under Ideology a `BuildableDef` with `canGenerateDefaultDesignator=false` is IDEO-ONLY.** `Ideo.MembersCanBuild`
  returns false if no meme, style or precept names the def. Then `GenConstruct.CanConstruct` refuses every
  colonist whose ideo is not classic, with 'Only Faithholders can build'. No WorkGiver offers a delivery job or a build
  job. Any def that its own custom designator places has this problem. The fix is `RM_OwnDesignatorBuildable.cs` (in
  `src/RimMandrake/FlowWorks/Source/`); it covers each `mandrake.*` mod. Diagnose with `jawa/workgiver_probe`, which
  reports `canConstruct` and the fail reason of each gate.
- **A `RitualBehaviorDef` without `<roles />` cannot start from the UI or the tool.** Give every ritual behaviour a
  `roles` element, even an empty one. Vanilla copies the list without a null check.

Keep this list short. Detail goes to `skills/rimworld-modding/references/traps-*.md`.

## The repo copy of an ideoligion is not the live one

- **Writing the repo `.rid` is not deploying it.** The repo copy is `src/Jawa/ideoligion/The Salvation.rid`. The game
  does not read it. The game reads the player ideoligion from the `Ideos` folder in the LocalLow `Ludeon Studios` folder.
  No deploy script exists for it. Copy the file deliberately, then read it back, as with any mod file.
