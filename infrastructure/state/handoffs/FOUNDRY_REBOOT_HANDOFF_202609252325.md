## Traps learned

- `jawa/set_current_map` failing leaves `Current.Game.CurrentMap` on whatever map was
  already current, silently — never trust an earlier call's return value before a
  `set_time_speed` mutation; always re-check `jawa/map_info` immediately first (filed:
  LESSONS_INBOX).
- A `jawa/world_tile_map_generate`'d map with no player pawn on it gets auto-culled once
  it stops being current — it will not still be there a few calls later; anchor with a
  colonist first if it needs to persist (filed: LESSONS_INBOX).
- RimWorld's World-tab UI staying open is not tied to which map is
  `Current.Game.CurrentMap` — a tool can report the right `mapId` while the visible
  screen still shows World/Terrain. A screenshot is the only way to confirm what's
  actually on screen (filed: LESSONS_INBOX).
- Three biome-mod-build items (`LONGSHADE_RM_MOD_BUILD_1`, `STILLSAND_RM_MOD_BUILD_1`,
  `THEROT_RM_MOD_BUILD_1`) all had item files claiming "OWED from scratch" while the
  actual build was already substantially complete and committed — always check
  `git log --oneline --all -- <path>` and `find <mod dir>` before trusting a
  Phase-A-style item's own STATE table (see: `queue-items-decay-verify-first` memory).
