### Git, publish and clones

- **Stale reads on the drvfs mount can mimic a revert.** `grep`, `tail` and `git status` all reported uncommitted edits gone, then minutes later showed them intact. Before acting on any "my file lost its changes" signal, wait about a minute and re-read from a fresh process; agreement of several stale readers is one reader, not corroboration. A wrong revert diagnosis leads to destructive recovery or a double-applied wave. Your ext4 clone is never stale.
- **`selftest_art_ledger_fixes.py` crashes before its verdict** (`git add infrastructure/state/art/events/BUILD.jsonl: pathspec did not match`): its `git_fixture` needs the shard to exist before `git add`, and `artledger.seat()` reads `RIMFLOW_SEAT` before `ART_SEAT`, so under `run_selftests` in a seat session the fixture's `ART_SEAT=BUILD` loses to the inherited `RIMFLOW_SEAT=BENCH` and the event lands in BENCH.jsonl. It passes with `env -u RIMFLOW_SEAT`; fixtures that set `ART_SEAT` must also pop `RIMFLOW_SEAT`/`AGENT_SEAT`.
- **`gpt_consult.py` and `code_review_status.py mark-clean --gpt-job` path traps.** From a scratch clone (no `skills/`) gpt_consult fails with `ModuleNotFoundError codex_image`: run the bench copy by absolute path with cwd in the scratch clone and repo-RELATIVE `-f` paths, because the receipt matches by repo-relative path (absolute paths can never mark clean). `--gpt-job` wants the BARE job name from the `[consult] receipt job consult-...` line; the full path printed on the first line is refused as 'no verifiable receipt'. The receipt must cover the committed files themselves: a review of a diff file does not count, so the last review before mark-clean must inline the files (`-f <path>`) after commit.

### GPT, Codex and image tools

- **GPT review misses most defects and times out often; Opus is the second reader.** Measured on 4 builder diffs with 9 known later-found defects: an Opus subagent caught 8 of 9 in 33-59 s (mean 48 s), `gpt_consult` at default effort with the diff only caught 2 of 9 in 20-53 s; 7 of 48 logged GPT calls (15%) hit the 500 s timeout with no answer and 3 more were near-empty. n=4, ground truth from tester and GPT rounds, so indicative. Use Opus as the fallback when GPT times out and as a second reader always, not only when GPT is slow.
- **`codex.exe` with expired ChatGPT auth prints a plausible session header, then 401 refresh-token spam, and exits 1.** Grade the answer body, not the header; re-login is owner-only.
- **`codex.exe exec` needs every input inlined into the prompt.** From an ext4 (`\\wsl.localhost`) cwd its sandbox helper fails (`orchestrator_helper_launch_failed`); reading a `\\wsl.localhost` path from a D: cwd hangs; even from D: the sandbox is flaky. Use `gpt_consult.py` (it inlines text files and stages the call on D:). `gpt_consult.py` defaults to `gpt-6.1-sol` at high effort (owner ruling); art (`codex_image.py`) stays on gpt-5.5. To show GPT images, call `codex exec` with `-i <winpath>` per image, a `--` terminator, then `-` for a stdin prompt (`codex_image.py`'s run pattern); a 3-image art review answered in 50 s.
- **A `gpt_consult` that is too big or lets codex roam returns late, empty or silently truncated.** Keep a consult under ~700k chars (at that size 5 parallel runs took 438-970 s; a 777k-char one had its middle silently dropped and still answered), and ask GPT to list anything it could not see ('Outside this slice') and re-run a smaller consult for what it names. At high effort a ~150 KB prompt (dossier plus four whole .cs files) ran past a 580 s `--timeout` and returned NOTHING (the answer file is written only at the end): inside a 600 s foreground limit trim to ~50 KB of excerpts and give a word budget (then under 10 min). Full-file reviews time out because codex goes web-searching decompiled game source or runs PowerShell/python on the files (2,000+ line file: 520 s; 7 files ~100k chars: 500 s twice): add `--lockdown --effort medium`, the line 'Do NOT run any tools or commands; just read and answer', and at most 4 files (answered in 51-150 s). Verify every GPT claim against the file or vanilla Data before accepting it (it reported an extra closing brace in a file whose braces balance 27/27, and called MeleeDodgeChance 8 an 800% bug when vanilla uses 15 and 8 on the unfinalized scale).
- **`gpt_consult` is refused under a low Codex runway unless given `--required "<rule>"`;** a code review is rule-required (code is not clean until a review says so).
- **`gpt_call_log` `tokens_used` is None on about half of `gpt_consult` calls** (1046 of 2167 on one day): `codex.log` does not always print the figure `TOKENS_RE` expects. `gpt_consult_rounds.py report` counts these as `tok?` and never fills them from the chars/4 estimate, so per-round token cost is a lower bound until `--json` events (`events_tokens`) or another real source is used.
- **`gpt_consult --out` answer files end without a trailing newline.** `cat a.txt b.txt` joins the last JSON line of one batch to the first of the next (24 verdict lines read as 20). Join with an explicit newline (`for f; do cat $f; echo; done`) and count lines against the item count before trusting a merged verdict file.

### Windows, WSL and paths

- 🔴 **What outlives a dead parent (MEASURED 2026-11-01, real `claude_bounded` runs; `D:\ClaudeWork\rimmandrake\helpers_dead_parent\probe`).**
  SIGTERM (goodbye, ticket restart, backstop): background Bash and a subagent's running Bash die with exit 137, no report.
  SIGKILL (crash, kill fallback): the LLM loops die, but both Bash commands run on as orphans, finish, and nobody reads
  them. `/clear`: the only route that lost helpers in 7 days, and it has no restart record. Reboot or WSL restart: all of
  it, `setsid` included. Only `setsid`/`systemd-run` outlives TERM and KILL, and a watcher in `run_in_background` dies
  at the next goodbye while the remote work it watches carries on. `helper_receipts.py` reports all of these to the
  next window; it does not keep them alive.
- ⚠️ **A `/proc/<pid>/environ` scan for a marker env var is never clean on this WSL box:** same-uid systemd (user manager), `(sd-pam)` and `ssh-agent` are non-dumpable, so `open(environ)` raises PermissionError. Rule a process out only on positive evidence (exited, other uid, or start time from `/proc/<pid>/stat` field 22 plus btime older than the run's start minus 5 s, since the marker is inherited); anything else unreadable is UNMEASURED. systemd 259 user scopes honour `RuntimeMaxSec` (TERM at the bound, KILL `TimeoutStopSec` later; a TERM-ignoring child bounded at 5 s died at 35.4 s).
- ⚠️ **WSL drvfs (`/mnt/d`) is the wrong place for watched or hot state.** TLC `-metadir` under `/mnt/d` pushed a liveness run past 480 s versus 15 s on a local tmp dir (`run_tlc.py` uses `tempfile.mkdtemp`); liveness checking also grows far faster than safety (2 candidates: 2.5M states in ~60 s for safety, over 8 min for liveness, so check it at 1 candidate). A systemd `.path` unit (inotify) never fires for a file written under `/mnt/d`, while on ext4 (`~/rm/restart-now`) it fired 1.5 ms after the write: watch a Linux-native dir, and probe any WSL path watcher before trusting it.
- **A systemd user unit or `systemd-run --user` one-shot starts with the manager's bare PATH.** It has no `~/.local/bin` (34 of 39 units here set none) and no Windows dirs on WSL, so a bare `claude`, `claude-account`, `gh` or `shutil.which('curl.exe')` dies FileNotFoundError / returns None (claude_bounded.sh exits 127; every ops_memory generation was blind). Resolve with `shutil.which(name)` or `os.path.expanduser('~/.local/bin/'+name)`, fall back to a fixed `/mnt/c/Windows/System32/...` path for a Windows exe (`powershell.exe` is under `/mnt/c/Windows/System32/WindowsPowerShell/v1.0`; `verify_from_archmagi.sh --wake` fails 'send failed' without it), pass `--setenv=PATH=...` to `systemd-run`, test with `env -i PATH=/usr/bin:/bin <cmd>`, and read the first real run's log before calling it armed. `selftest_systemd_path_bins.py` guards the repo's own units; a child of a oneshot dies with the unit's cgroup even under setsid, so start it as its own transient unit (`systemd-run --user --collect`).
- **WSL 'page allocation failure: order:7' (vmbus_alloc_ring from hvs_probe, every new hv_sock channel: /mnt drvfs and interop) is watermark starvation, not fragmentation alone.** Page cache holds MemFree at the low watermark, so `compact_memory` finds nothing and `drop_caches` refills in minutes. Fix: `min_free_kbytes=1GiB` + `watermark_scale_factor=200` (`src/RimMandrake/Utils/systemd/90-rm-order7.conf`, `/etc/sysctl.d`, `rm-order7.timer`). Root without sudo: `wsl.exe -u root`.
- **`tasklist.exe` cannot see the art daemon.** `artpiped.py` is a plain WSL Linux process, so an empty `tasklist.exe | grep artpip` proves nothing. Check with `pgrep -f artpiped.py` from WSL. Empty `pending/` and `active/` with a live PID means fed-and-waiting, not stopped: feed it with `fill_queue.py` rather than launching a duplicate daemon.
- **ASCII `strings` cannot see .NET string literals; they are UTF-16LE.** The `#US` heap stores literals as UTF-16LE, so default `strings` reads `w\0i\0l\0d\0...` and matches nothing: three whole-tree sweeps for the literal `wildAnimals` across every mod DLL found zero hits while `ChooseWildAnimalSpawns.dll` was overwriting that field on all 81 biomes. A clean ASCII sweep of a managed binary is not evidence of absence: say UNMEASURED. (Attribute names are the opposite case: UTF-8 blobs, see rimbridge traps.)
- **Windows `python.exe` misreads WSL absolute paths: `/mnt/d/Luke/...` becomes `D:\mnt\d\Luke\...` ("can't open file").** Every script that shells to `python.exe` (the bridge client, the companion `build.py`) must `cd` to the repo and pass a RELATIVE path. Never send a driver's client output to `/dev/null`: capture it per cycle, or the real error hides behind a generic "map never became ready". Also `bridgetools/build.py`'s "would remove tools" guard derives the tool set by regex over DLL bytes (`jawa/[a-z_]{3,40}`), so it can refuse a deploy for a fictitious loss (`LOSES jawa/pawn_`, a fragment) when a description string changed. - **A process just returned by `subprocess.Popen` may not have a readable argv yet:** `/proc/<pid>/cmdline` read short on 8% of fresh spawns (25/300 alone, 92/1200 at 12 threads, this WSL kernel). A test that judges a child by its cmdline must wait for it; an unsettled read answered False and `selftest_relentless_live_round` `t_tick_env` went green past its own AttributeError on one run of three.

### Units, timers, hooks and processes

- **`cp -r` of a symlinked directory copies the link, not the files.** `~/.claude/projects/-home-mandrake-rm-bench/memory` is a symlink, so `cp -r` of it made a "backup" that changed with the original. Back up with `cp -rL` and check the copy with `ls -la` (a directory, not `->`) before deleting anything.
- 🔴 **`pkill -f` / `pgrep -f <pattern>` match the agent's own shell (exit 144), and a self-matching wait loop never ends.** The Bash tool runs each command as `zsh -c '... eval "<my whole command>"'`, so the pattern sits in my own argv. On Linux add `-A` (`--ignore-ancestors`): `pkill -A -f pat` / `pgrep -A -f pat` (measured: `-f` alone matched 2, wrapper plus the `$(...)` fork; `-A -f` matched 0). `pgrep -f pat | grep -v $$` is NOT enough (a `$(...)` fork has its own PID with the same argv, and `grep -v $$` also drops PIDs containing those digits). Or break the literal (`"litel[l]m"`), use `ps -eo pid,args | grep '[p]attern'`, and wait on a PID. On macOS BSD pgrep ancestors are excluded by default and `-a` means INCLUDE them (opposite of Linux, UNMEASURED). `setsid nohup cmd &` then `ps -p $!` shows nothing even though the job lives (setsid forks when it leads a process group, so `$!` is setsid's own pid); check liveness with `pgrep` or launch with `systemd-run --user --slice=rm-harness.slice`, and never delete a job's clone on a `ps -p $!` miss. `/tmp` is tmpfs: a full clone of the repo there fills it (8 GB). The same holds for a `claude -p` loop: its prompt text sits in its own command line, so a pass's `pgrep -f` on a command named in the prompt matches itself and waits forever; `--setting-sources project` also drops the global `bash_guard` that would have refused it.
- **`safe_load` never complains about duplicate YAML keys; hunt them with `yaml.compose` plus a duplicate-key walk.** An insert in `canon.yml` replaced the `cradle_memory:` header line, leaving the owner's ship-memory ruling as a second ruled/src pair under `cathedral_voice`, and every YAML reader silently dropped one.
- **A polling loop that reads a growing file with `tail -c +$((START_SIZE+1))` must update `START_SIZE` after every read.** Otherwise each poll re-reads from the original offset and re-emits the same matched lines forever (seen watching Player.log for a restart to finish).

## Probing filters, sandboxes and meters
- **Test an env or path filter with the production directory layout, not a tmp dir outside the filtered root.** `judge_env` dropped every value naming `clones_root`, the judge work root sat under it, so `RM_GPT_CALL_LOG` was dropped and no judge GPT call was ever metered; the fix lets a caller-supplied value inside the call's own workspace survive.
- **Probe a spend meter by injecting spend where each helper really writes.** A meter that reads only transcripts under one root is blind to helpers that get a fresh HOME in a tempdir and are rmtree'd (testers): the verdict still DECIDEs with no blocking diagnostics.
- **A sandbox probe counts only after its mutation is shown to leak.** Under `bwrap --unshare-user`, `/proc/<host pid>/root` is already EACCES, so dropping `--unshare-pid` changed nothing the probe looked at: show the mutant leaks (e.g. `/proc/1/cmdline` is bwrap) before a clean probe counts. Run a Windows interop probe with NO args (`whoami` with args exits nonzero and hid live interop). Also: `bwrap --unshare-net` does NOT close AF_VSOCK on WSL2 (the Windows host answers on CID 2, ports 50000-50005), so add a seccomp filter returning EAFNOSUPPORT for `socket(AF_VSOCK)`; and a sandbox hiding local copies of an answer is defeated if the repo is public and the network shared (an unauthenticated `git fetch https://github.com/...` fetched the fix commit), so probe the internet copy (`git ls-remote`) and `/var/log` (syslog/journal hold dispatch briefs and ledger events).
- **A locked-down codex is still steered by instruction files.** With every tool feature off, `--ignore-rules` and `--ephemeral`, an `AGENTS.md` in its cwd and a `CODEX_HOME/skills/<x>/SKILL.md` each changed the reply; `project_doc_max_bytes=0` and `[skills] include_instructions=false` each stopped it. `models_cache.json` also carries per-model instruction templates (`models[].model_messages.instructions_template`). An isolated judge needs those knobs plus an allow-listed home and an instruction-free cwd chain; filename scans alone cannot beat a same-user plant/read/remove race.
- **A Player.log 'no errors from mod X' check built on record grouping keeps passing broken loads.** New unindented continuation shapes appear every pass ([Ref], Full node:, Unity frames, Harmony wrapper frames). Use a forward window (error-worded line with the mod named on it or in the next few lines) plus 'any stack frame of ours' and accept the conservative false FAIL (see graffiti_v1_live_proof.py log_verdict).
