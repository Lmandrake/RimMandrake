# Tools with surprising side effects — RimMandrake

Moved from the project `CLAUDE.md` on 2026-10-11 (weekly cleaning), text unchanged except heading levels. CLAUDE.md keeps a one-line rule and points here. Entries state what IS: delete a line the moment it turns false, never annotate it.

## Machine and research facts

- 🔴 **RimSage answers on the Windows Desktop ONLY — on the Mac laptop it has never
  connected** (MEASURED 2026-09-16: five timed-out session logs 2026-09-02→09-16,
  `mcp.rimsage.com` TCP-dead while general egress is fine, no `mcp__rimsage__*` tool in
  the toolset at all, no cached decompiled tree). So on the laptop an **engine-internals
  question is UNMEASURABLE** — say so rather than reasoning from a doc, and never brief a
  subagent to "use RimSage" there: it costs a whole run to rediscover. Still fine offline
  on either machine: the def dump (`measure`, `refresh.py`) for DEFS, and reading our own
  source. ⚠️ **Several docs assert engine facts that trace to an earlier agent's prose,
  not a decompiler** — `About.xml`'s "vanilla ignition already works on any flammable
  terrain", and `Flood.noPossibleCell` being private with no accessor. Do not launder
  those into measurements.
- ✅ **CANON research DOES work from the Mac, and directly.** Wookieepedia's
  `action=parse&page=<X>&format=json&prop=wikitext` API answers unauthenticated over plain
  `curl` with **no size cap** (MEASURED 2026-09-23: 13 dianoga pages pulled clean). ⇒ Prefer it
  over Fetcher, which **silently TRUNCATES AT 50,000 chars** and has eaten a species' whole
  Biology section. Resolve titles with `action=query&list=search&srsearch=<name>` — a guessed
  exact page title returns MISSING for real subjects constantly, which is not evidence a subject
  is non-canon. ⚠️ `timeout` does not exist on macOS and its failure **resets the shell's cwd**;
  use `curl --max-time`.
- 🔴 **The SteveDesktop runner's Python has no third-party packages unless someone installed
  them** — a proof row that imports one fails there as a FAIL that is a machine fact, not a mod
  defect (MEASURED in the findings fold: `No module named 'PIL'` on four FlowWorks diptych rows,
  job J20261026T004751Z-6e5292; `No module named 'lxml'` on Cuisine
  `rotting_bed_grows_marsh_fungus/offline_patch_shape`, 2026-11-06). Before judging such a row,
  read the import: a `ModuleNotFoundError` row is a runner-environment finding (Operations), and
  a validation script should import optional packages inside the row and report UNMEASURED, never
  FAIL, when they are absent.
- 🔴 **If a driver reads UNMEASURED 'no result at the current mod hash' although it ran and its rows PASS, compute `mod_hash` twice with the same interpreter that stamped it.** On one Windows desktop `python.exe` gave a different hash on every run with identical file bytes: logical CPU 18 returned wrong SIMD hash results (pinned with `start /affinity`, sha256 gave 60 different digests out of 60; md5 and crc32 stay stable and hide it). Probe by hashing the same buffer N times, pinned per core, not by rereading files.
- ⚠️ **RimSage's index predates Odyssey 1.6 reading policies:** `read_csharp_symbol RimWorld.ReadingPolicyDatabase` returns not-found, so Odyssey-internals questions are unanswerable there. Reason from a Player.log diff and say UNMEASURED.
- **Hasleo Backup Suite Free 6.0.2 cannot do an unattended system-disk clone.** The vendor table says Free does not clone a system disk; the binary says Free has no CLI and no backup filters; no ignore-bad-sectors option exists. The UI still walks to the final Proceed page, so reaching it proves nothing. For unattended clones with an unreadable cluster use wimlib VSS capture piped to apply, with exclude and restart on a read error; a pipable capture reads everything twice (it hashes all data before writing).
- **A root-disk fall is not necessarily scratch.** Two falls (578->140 GB at ~3.3 GB/min, back in one step) left `ops_watch` `series/disk.jsonl` `pool_gb` and `scratch_total` flat, so no reaper could free them and the grower vanished unnamed. Read `disk.root_free_gb` against `pool_gb`/`scratch_total_gb` before blaming clones; the 10-minute pressure tick writes `~/.local/state/rm-scratch-reap/growth_capture.json` naming the top `/proc` `write_bytes` writers on a fast fall.

## Tools with surprising side effects
- **`cp -r` of a symlinked directory copies the link, not the files.** `~/.claude/projects/-home-mandrake-rm-bench/memory` is a symlink, so `cp -r` of it made a "backup" that changed with the original. Back up with `cp -rL` and check the copy with `ls -la` (a directory, not `->`) before deleting anything.
- 🔴 **When a new game or world won't start, read the FIRST exception in `Player.log`, not the
  loudest.** `rimworld/start_debug_game_ready` and `load_game_ready` both work (VERIFIED on the
  full mod list, 2026-09-27). They were "broken on any mod list" for a while, but every
  visible symptom was a cascade from one of three bugs in our own content, and none was in the
  engine. (1) A `BiomeWorker.GetScore` called `SurfaceTile.Rivers`, which NREs because the
  biome isn't assigned yet during `WorldGenStep_Terrain`. Terrain gen died on tile 0, and the
  loud `WorldPathGrid`/`WorldGrid.get_Item` out-of-range spam came after it. Read the raw
  `potentialRivers` instead. (2) A drug (non-`None` `drugCategory`) with no
  `CompProperties_Drug` NREs `DrugPolicy.InitializeIfNeeded` inside `Game`'s constructor.
  `DrugBase` does not supply that comp. (3) A creature ThingDef naming a type from an
  inactive mod gets discarded, and the raceless PawnKindDef it leaves behind kills
  `GeneticRim.Core`'s cctor, which stops starting-pawn generation
  (`DEBUG_GAME_READY_WORLDUI_CRASH_1`). Harness: `src/RimMandrake/bridgetools/prove_quicktest_world.py`.
- 🔴 **A `PreToolUse` hook added to `.claude/settings.json` mid-session does not fire** — not for this window's Bash calls and not for its subagents' — until a new session starts; a hook already present at session start does fire for subagents. Test a new hook in a fresh window, never by exercising it in the one that added it.

- 🔴 **What outlives a dead parent (MEASURED 2026-11-01, real `claude_bounded` runs; `D:\ClaudeWork\rimmandrake\helpers_dead_parent\probe`).**
  SIGTERM (goodbye, ticket restart, backstop): background Bash and a subagent's running Bash die with exit 137, no report.
  SIGKILL (crash, kill fallback): the LLM loops die, but both Bash commands run on as orphans, finish, and nobody reads
  them. `/clear`: the only route that lost helpers in 7 days, and it has no restart record. Reboot or WSL restart: all of
  it, `setsid` included. Only `setsid`/`systemd-run` outlives TERM and KILL, and a watcher in `run_in_background` dies
  at the next goodbye while the remote work it watches carries on. `helper_receipts.py` reports all of these to the
  next window; it does not keep them alive.

- 🔴 **A backgrounded `Agent` dies at 600 s of silence and leaves NOTHING on disk.** Three died
  that way 2026-09-17, all mid-read before their first write, all leaving a clean tree — so each
  cost a whole run rather than being truncated; the two that survived streamed output at 385 s
  and 575 s. **Brief every writing subagent to create its output file as a skeleton FIRST and
  fill it section by section** — a file write emits progress and persists partial work. A long
  read-then-write brief is the shape that trips it.
  🔴 **It happened AGAIN 2026-09-23** on a mechanical creature census, and the cheaper lesson is:
  for a **mechanical** census (glob, parse, count, tabulate), writing the script inline costs less
  than briefing an agent to survive the watchdog. Reserve subagents for work that needs judgement.
- ⚠️ **Two `PreToolUse` gates refuse tool calls outright and are easy to trip:**
  the `Agent` tool **refuses without an explicit `model`** (omitting it silently inherits this
  seat's tier, which is how past censuses ran on Opus; named agent types and `fork` are exempt) —
  ladder in `infrastructure/agents/Agent_Policy.md`. And `AskUserQuestion` is validated by
  `validate-question-card.py`: a `header` longer than **12 characters**, or a question not ending
  in `?`, refuses the **whole card**. Count the header before calling.
- 🔑 **A question-card option LABEL the owner clicks is OUR sentence, not his** — record it with
  `--by-card`, never `--owner-said`. Full rule: one field per kind of authority (owner, by question card 2026-10-11): `--owner-said` = his words (typo fixes and joining his own sentences are fine, meaning unchanged) · `--by-card "<question → option>"` = a decision he took by card (the label is our text) · `--per-ruling <item-id|event>` = a standing ruling cited by reference (it stands until he changes it) · `--why "…"` = your own words. No transcript proof runs; nothing checks a quote but its shape.
- ⚠️ **`RM_CreatureBehaviors.csproj` sets `EnableDefaultCompileItems false` and lists every file.** A new
  `.cs` in `Source/` without a `<Compile Include>` line **compiles into nothing, with no error**. Adding a
  file to that assembly is always a two-file change.
- 🔴 **`handoff.py` cannot tell two BENCH windows apart.** It REFUSES on "BRIDGE still held by
  BENCH" even when the hold belongs to the *other* window's live session, because both sign as
  `BENCH`. ⛔ Do not release it to satisfy the gate — that breaks a live game. `--force` records
  it as open, which is the correct exit, and the handoff must name whose hold it was.
- 🔴 **`modcheck run <Mod>` REWRITES the live `ModsConfig.xml`** — it calls `modlist_swap` and
  swaps to MINIMAL. It reads like a query verb and is a Charter expensive-list action. On the
  Mac it dies on the Windows path; on the Desktop it swaps his list unasked (2026-09-17).
- 🔴 **`daemon-reload` restarts the count of a `systemd-run --on-active` timer** (measured 2026-11-06,
  OPS_TIMERS_REVIVE_115F: a 30 s timer with a reload at +20 s fired at +50 s; an `--on-calendar` one fired at +30 s).
  Selftests and deploys reload often here, so a delay beyond a few minutes needs `--on-calendar`.
- 🔴 **`pkill -f` / `pgrep -f <pattern>` match the agent's own shell (exit 144), and a self-matching wait loop never ends.** The Bash tool runs each command as `zsh -c '... eval "<my whole command>"'`, so the pattern sits in my own argv. On Linux add `-A` (`--ignore-ancestors`): `pkill -A -f pat` / `pgrep -A -f pat` (measured: `-f` alone matched 2, wrapper plus the `$(...)` fork; `-A -f` matched 0). `pgrep -f pat | grep -v $$` is NOT enough (a `$(...)` fork has its own PID with the same argv, and `grep -v $$` also drops PIDs containing those digits). Or break the literal (`"litel[l]m"`), use `ps -eo pid,args | grep '[p]attern'`, and wait on a PID. On macOS BSD pgrep ancestors are excluded by default and `-a` means INCLUDE them (opposite of Linux, UNMEASURED). `setsid nohup cmd &` then `ps -p $!` shows nothing even though the job lives (setsid forks when it leads a process group, so `$!` is setsid's own pid); check liveness with `pgrep` or launch with `systemd-run --user --slice=rm-harness.slice`, and never delete a job's clone on a `ps -p $!` miss. `/tmp` is tmpfs: a full clone of the repo there fills it (8 GB).
- ⚠️ **The modal sweep's `jawa/window_list_close` answer "No open window's type name contains X" (`success:false`) is the CLEAN, normal result.** Recording it as an ERROR marks every verdict of the run `unknown`. Likewise `python.exe` cannot run git on a `\\wsl.localhost` checkout, so run identity reads `unknown` and no deploy is proven fresh: run git through `wsl.exe`.
- ⚠️ **A staged build can reuse a stale DLL: `winbuild.py` in a scratch clone after `git checkout` printed BUILT in 1.7 s but the DLL lacked a method added in that sha (the Windows `obj/` cache judged the source current), and a mutation-test rebuild within ~1 s reuses the old DLL.** `touch` the changed `.cs` (sleep ~4 s) and rebuild with `winbuild.py <Mod> -- --no-incremental`, then confirm the `.srchash` changed and that a new method name is in the DLL bytes before committing it. `./publish`'s own rebuild already passes `--no-incremental`.

- **`systemd-run -E NAME` with NAME unset in the caller sets `NAME=''` in the new unit (systemd 259), it does not skip it.** A reader doing `env.get(NAME, default)` then gets `''`, not the default: wrapup's seat-clone carry and bridge lock went blind for every role unit. Read handed-on vars with `env.get(NAME) or default`, or scrub empties first.
- **A reach probe's truncated 'why' hides which adapter failed:** rerun `offbox_readings` by hand at the owner's `reach.sha`. An offbox adapter whose output scales with commit subjects (`git_log_candidate`, 120 lines) can outgrow `OFFBOX_OUT_MAX` (20000 B) and be killed: bound each line (`git %<(N,trunc)`); an adapter running a fixed selftest list must not go red when a candidate merely predates one of the tests.
- **A churn alarm 'unmeasured failed it N times' can be N blind checks of one reach gap, not N bad attempts** (4 UNMEASURED checks all failed to `readlink` host `/proc/<pid>/cwd` for `selftest_scratch_reap_tmp.py`). A reach fix only helps candidates rebased onto it. Before diagnosing, read the item's `attempts.jsonl` ends and its latest check verdict; a blind PASS after the last failure already reads the churn point 0 (`ops_watch.churn_why`).
- **`PssCaptureSnapshot` (VA clone) on a 1 GB process failed with error 1450 `ERROR_NO_SYSTEM_RESOURCES`** when ~3 GB commit was free (2 of 4 runs): a snapshot dump of a multi-GB game can fail under memory pressure. `health_minidump.py` falls back to a direct `MiniDumpWriteDump` and records `fallbackFrom`/`pssError`.
- **A `claude -p` run from a systemd unit gets no Windows PATH or `RIMFLOW_SEAT`, and `--setting-sources project` still loads the user CLAUDE.md:** exclude it with `claudeMdExcludes` in the project settings. A fresh clone's ledger keeps a released bridge hold until its stale timer, so it refuses though the shared lock is free.
- **Editing a loop's `loop.sh` does not change a running `while` loop:** bash already parsed it. Replace the file atomically and restart at a pass end, or use the clone's `.claude/settings.json`, which each new pass reads.
- **A detached helper's record can say finished while its `<ITEM>.det` clone is still the owner's work area.** `detached_helper.py return --all` waits a 3600 s grace for such a clone and only an explicit `--unit <unit>` returns it; release it once the Conductor agrees. Bundles returned from `.det` clones can carry stale bridge-release lines; do not publish them.
- **`RM_HoseLinks` slot cache reaches some inputs only through its 60-tick phased audit, not the same tick:** a trail cleared and refilled to the same length with the same far cell (`KeyOf` folds trail identity+count) matters only for HoseCut over a raised leaf; a port changing owner by `SetFactionDirect` bypasses the `SetFaction` topology patch (the liquid net has the same gap); a leaf built already raised was folded into GlobalKey via `RM_Drawbridges.RaisedLeafCount`. The pre-Move `RM_HoseLinks.Live` check still re-reads HoseCut/Spawned at transfer. FlowWorks SelfTest `Src()` collapses whitespace runs to one space, so source pins must use single spaces; `selftest_flowworks_stock.py` waits silently on the seat dotnet lock (an empty log on timeout means queued, not hung).
- **artpiped `FAIL worker_error 0s` rows next to a 'sandbox not ready' warning are not sandbox casualties:** read the failed manifest's `worker_stderr_tail` first. They were `Input image does not exist` (xart_* jobs pointing into a deleted Relentless clone).
- **A fake `subprocess.Popen` in a selftest must not report pid 0.** Code that `os.killpg(p.pid, SIGKILL)`s its child (`relentless_live.run_proof`) then kills the test's own process group, which shows as exit 137 with no output. Use a pid no process holds (`2**30`).
- **`systemd-run` expands `${VAR}` in the command it is given,** so a `bash -c` body with `${PIPESTATUS[0]}` becomes a bare `exit` and a failed build read exit 0 inside a walled unit. In a toolchain or probe command use `set -o pipefail`, or write `$$`, never `${...}`.
- **`rename(2)` over a symlink is not lookup-atomic on this ext4:** a reader stat'ing through it got ENOENT 3 times in ~116k reads under 5,000 `os.replace` swaps (0 on tmpfs); a second look finds it. A swap-a-symlink deploy must treat a single miss as transient (a oneshot starting in that instant fails and its timer retries).
- **A process just returned by `subprocess.Popen` may not have a readable argv yet:** `/proc/<pid>/cmdline` read short on 8% of fresh spawns (25/300 alone, 92/1200 at 12 threads, this WSL kernel). A test that judges a child by its cmdline must wait for it; an unsettled read answered False and `selftest_relentless_live_round` `t_tick_env` went green past its own AttributeError on one run of three.
- **An `ops_watch` alarm target's name is minted as `<name>_<4-letter twist>` and must pass the ledger mint grammar (3-7 words, <=44 chars),** so the rule's own name may hold at most 6 words and 39 chars. Longer, the alarm sits PENDING with 'no mintable alarm name' and never files, and `ops_watch.py lint` does not catch it. Test with `mint_problems(name+'_'+alarm_twist(name))`.
- **`seat_restart.py request` refuses from a systemd unit** (no `~/.claude/sessions/<pid>.json` for the calling window), so a timer can never start a fresh Conductor window through it; a timed backstop must go through the Dispatcher's role launch.
- **Lodestar's `handoff.py --wake` run in this repo prints a stale October handoff;** use the project's own `src/RimMandrake/Utils/handoff.py --wake`.

## NVIDIA free-tier endpoint (Nemotron workforce)
- **Nemotron is the viable free NVIDIA workforce, not Kimi.** Re-run `src/RimMandrake/Utils/nemotron_probe.py` before trusting any model name: the catalog shrinks daily (102 models then 83 the next day; models that answered 200 vanished) and listed names can 404 for this account (`kimi-k2.6`). Pick `nvidia/nemotron-3-super-120b-a12b` (20/20 tool calls, ~1.2 s, retrieves a needle at 616k prompt tokens). 503 `ResourceExhausted` is shared capacity: transient, retryable, a seat degrades. A 429 on `moonshotai/kimi-k3` is a per-model quota wall (15 of 20 rapid calls) that retrying worsens, a seat stalls. The endpoint never errors on an over-long prompt, so acceptance proves nothing: only a retrieval test separates long context from silent truncation.
- **Qualify a model for agentic work with a loop containing a deliberate bad argument, never a single tool call** (`src/RimMandrake/Utils/nemotron_agent_trial.py`). The discriminator is error recovery: all four usable nemotrons emit valid calls, but `nemotron-3-nano-30b-a3b` dropped a path prefix and thrashed seven turns repeating one grep. Under Claude Code its failure mode is a polite empty answer (`is_error: false`, exit 0) after losing the prompt, so grade the ANSWER, never the exit code.
- **Gateway traps (LiteLLM in a venv, config `src/RimMandrake/Utils/litellm_nemotron.yaml`).** Claude Code does not recognise the model name and silently assumes a 200k window, so pass `CLAUDE_CODE_MAX_CONTEXT_TOKENS`; set `ANTHROPIC_API_KEY=` EMPTY or the claude.ai OAuth login wins and the window never reaches the gateway. A Sonnet fallback is not buildable through LiteLLM here (it needs an API key; auth is OAuth). System pip refuses under PEP 668, so use a venv.
