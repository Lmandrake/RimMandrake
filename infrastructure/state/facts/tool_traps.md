  read the import: a `ModuleNotFoundError` row is a runner-environment finding (Operations), and

- 🔴 **If a driver reads UNMEASURED 'no result at the current mod hash' although it ran and its rows PASS, compute `mod_hash` twice with the same interpreter that stamped it.** On one Windows desktop `python.exe` gave a different hash on every run with identical file bytes: logical CPU 18 returned wrong SIMD hash results (pinned with `start /affinity`, sha256 gave 60 different digests out of 60; md5 and crc32 stay stable and hide it). The UI walks to the final Proceed page, so reaching it proves nothing. - ⚠️ **A staged build can reuse a stale DLL: `winbuild.py` in a scratch clone after `git checkout` printed BUILT in 1.7 s but the DLL lacked a method added in that sha (the Windows `obj/` cache judged the source current), and a mutation-test rebuild within ~1 s reuses the old DLL.** Cause: `winbuild.stage_build` rsyncs with `-t --modify-window=2` and mtimes truncated to whole seconds, so an edit within 2 s of the previous staged copy that keeps the same SIZE (probe/revert, one-digit sed) is not re-staged, or stages OLDER than the obj output, and MSBuild runs the old source. `touch` the changed `.cs` (sleep ~4 s) and rebuild with `winbuild.py <Mod> -- --no-incremental`, then confirm the `.srchash` changed and that a new method name is in the DLL bytes before committing it. `./publish`'s own rebuild already passes `--no-incremental`.

### Ledger, rimflow, handoffs and lessons

- 🔑 **A question-card option LABEL the owner clicks is OUR sentence, not his** — record it with
  `--by-card`, never `--owner-said`. Full rule: one field per kind of authority (owner, by question card 2026-10-11): `--owner-said` = his words (typo fixes and joining his own sentences are fine, meaning unchanged) · `--by-card "<question → option>"` = a decision he took by card (the label is our text) · `--per-ruling <item-id|event>` = a standing ruling cited by reference (it stands until he changes it) · `--why "…"` = your own words. - **Test an env or path filter with the production directory layout, not a tmp dir outside the filtered root.** `judge_env` dropped every value naming `clones_root`, the judge work root sat under it, so `RM_GPT_CALL_LOG` was dropped and no judge GPT call was ever metered; the fix lets a caller-supplied value inside the call's own workspace survive.
