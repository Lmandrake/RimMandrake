A schema-2 slots{} record is trusted twice by enact: its KEY decides the install path (rel_for) and its letter decides the bytes. A sheet-side guard on the letter (c3a382b9e0) is not enough; enact must check that the letter belongs to the key's lane (now done: ENACT_SLOT_PICK_VERIFY_MEMBERSHIP), and a key from an older build installs at a stale path (ENACT_STALE_SLOT_KEY_MIGRATE_PATH, 12 real records). Whenever a stored record names both a target and a payload, the consumer should check that they agree against the current snapshot, and should not trust the UI that wrote them.
