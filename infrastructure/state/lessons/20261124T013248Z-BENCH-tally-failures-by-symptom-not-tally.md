A tally of failures by symptom is not a tally by cause: '51 of 73 past live FAILs were not mod faults' (24 could not read, 22 harness or transport, 5 wrong build) names no run spoiled by a gap between bridge calls, and it does not exclude one either (a late read can sit under 'could not read'). Before a design moves work into the game to close 'the gaps', read the records for the named cause, and say 'not named' instead of 'none'. Same tick is also not same state: an act from Python on a paused game lands on tick T, but paused frames still run MapUpdate and mod frame code (FlowWorks RM_PocketGrid.UpdatePaused), so tick T+1 can read different inputs.
