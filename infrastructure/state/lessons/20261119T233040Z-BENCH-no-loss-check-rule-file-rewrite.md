A no-loss check on a rule-file rewrite (checkable.py compare, rule_doc_lint.py keep) reads numbers, paths, ids, quotes and code spans only, so it passes a rewrite that changed meanings or broke a test that reads the files: after the checks pass, run every test that reads the files, and have a reader who did not write the draft compare old and new text line by line (hunk by hunk). The span check alone is not evidence that the meaning stayed.

So before a rule-file rewrite is called done: run every test that reads the files, and have a second reader compare old and new text hunk by hunk.
