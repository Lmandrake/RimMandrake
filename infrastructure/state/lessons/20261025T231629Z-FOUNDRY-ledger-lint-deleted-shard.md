An append-only lint that iterates only the files present at the CHECKED revision cannot see the biggest violation: a shard deleted outright (or truncated to zero bytes, which an 'if not data: return' early-exit skipped) linted clean. ledger_lint.py now walks the union of rev and base shard lists and judges an empty/absent shard against its base lines; and an unknown --rev, whose failed git ls-tree listed no shards and read '0 findings', now exits 2. Any 'nothing was wrong' over a list should be checked for 'the list was empty because the lister failed'. Note the pre-push hook still treats exit 2 as pass.
