A backgrounded subagent can go silent and leave finished, well-formed work UNCOMMITTED on disk with no trace in the task registry (TaskOutput says 'No task found') and no ledger note (Mlie porting Pass 9, recovered at 48b72ac41). Before writing off a dispatched agent as lost, run git status --porcelain on its natural output area: the agent died, the work often did not. Also, the running-agents list in TaskOutput errors is environment-wide (other seats' agents appear), and messaging a half-remembered task ID can resume a different, already-finished agent that just recaps old work.
