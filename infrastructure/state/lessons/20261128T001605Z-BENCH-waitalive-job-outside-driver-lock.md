A job started with waitalive.py run is outside the session's process tree, so a game's driver lock that the session holds does not cover it. A subagent ran its fresh-load script under waitalive on 2026-11-27: game_instance.py stop was REFUSED ('ArchBig is another live driver's'), the launch that followed started a second ArchBig beside the first, and the scene ran on the old load while the notes called it fresh. Run every command that stops, launches or deploys a game directly in the foreground with the Bash timeout at its maximum, never under waitalive, and read the load record for a REFUSED line before a run is called fresh. waitalive stays right for a publish or a long offline job, which needs no driver lock.
