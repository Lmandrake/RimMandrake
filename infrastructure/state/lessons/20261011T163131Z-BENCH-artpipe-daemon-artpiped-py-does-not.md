The artpipe daemon (artpiped.py) does not hot-reload: an edit to its own source (timeout constant, manifest field) never takes effect until the process is restarted. CODEX_WORKER_SANDBOX_WRITE_1 looked like an unfixable bug across 9 failed jobs because two real fixes sat in source while the old process ran; restarting it (queue idle, SIGTERM) took the same 3-job test from 3/3 failing to 0/3. Before trusting any 'still broken after the fix' on that channel, compare the daemon's process start time with the last edit to artpiped.py, and check pgrep -af artpipe for more than one PID (two daemons fight over the w0/w1/w2 codex slots and produce 'no rollout file found' failures that look like a codex bug).
