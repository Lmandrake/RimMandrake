./publish refuses to land a source-only commit when the shared mod DLL pair is dirty in the seat clone (peers' winbuild output): 'a DLL needs rebuilding ... not mine to overwrite'. Since the pair is a regenerable artifact, the working fix (2026-10-24, pits+water 4cccbfe1fa) was: back the pair up under D:\ClaudeWork\rimmandrake\backups\, write HEAD's bytes with 'git show HEAD:<path> > <path>' for both files, ./publish (it rebuilds from committed source in a scratch clone and commits the pair), then winbuild.py <Mod> again so the working-tree DLL carries the peers' uncommitted source once more.
