RimWorld 1.6 ReservationManager.CanReserve returns false outright when ANY existing reservation on the target (same layer, respected claimant) has a different maxPawns than the one you ask with (decomp Verse.AI/ReservationManager.cs: reservation.MaxPawns != maxPawns -> false). A job giver's CanReserve must therefore use the exact maxPawns and stackCount its driver's Reserve uses; asking CanReserve(pawn, t, 1) before a driver Reserve(t, job, 10, 1) silently stops a shared target ever being shared (found in RM_JobGiver_EatMetal: a second metal eater dug fresh steel instead). Also: a bare thing.stackCount write skips DirtyMapMesh and listerMergeables; shrink a spawned stack with SplitOff(n).Destroy().
