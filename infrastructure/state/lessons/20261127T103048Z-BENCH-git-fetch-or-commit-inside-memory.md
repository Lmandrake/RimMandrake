A git fetch or commit inside a memory-limited systemd unit starts git's automatic packing (maintenance --auto -> gc --auto -> repack) inside that unit's cgroup: on the 1 GB tick it swapped 7 GB and took 13 min, and systemd killed it at unit end, leaving tmp_pack_* for the next run to restart. A hand 'git config gc.auto 0' does not last (pulse-deploy lost it between 2026-11-17 and 2026-11-27) and a held clone that nothing packs grows without bound (bench: 125769 loose objects, 34 GB). Hold in code (clone_pack.hold, sync_clone) and pack on a schedule (rm-clone-pack.timer). Also: waitalive watching 'systemd-run --wait' sees 0 CPU and reads HUNG; wait on the unit's main pid (waitfor pid) instead.
