repair_torn_ledger.py decoded the ledger with strict UTF-8, so a write torn inside a multibyte char (rimflow writes ensure_ascii=False; em-dashes are everywhere) crashed the repair tool with UnicodeDecodeError instead of finding the torn line. Reproduced 2026-11-02 (wave 79). Fixed: decode with surrogateescape, treat a line that will not strict-encode as bad, write the backup with surrogateescape so it keeps the original bytes; selftest case 10 covers it. General: a tool whose job is repairing torn bytes must never strictly decode them first.
