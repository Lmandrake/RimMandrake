oom_attribution.py --since (and any 'journalctl -k --since X') reads ONLY the current boot: -k/--dmesg implies -b, so a window reaching an earlier boot silently returns that boot's kernel kills as nothing (10-30..11-01 read 0 kills; 17 were there). Read kernel lines across boots with 'journalctl _TRANSPORT=kernel --since X --until Y'; oom_attribution.py does so since HARNESS_MEMORY_MEASURE_WHO_HIT_TWELVE_GIG, and --boot -2 reads one older boot.
