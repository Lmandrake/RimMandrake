A RimWorld that we launch takes the foreground in three ways (focus_probe.py, 2026-11-27): its first window activates itself about 5 s after the start (a start from a WSL-launched shell can count as started by his terminal's process, so Windows lets it); Steam's 'Launching...' window takes it when the URL fires; and when that window closes Windows hands the foreground to a game window with NO foreground event. A map load takes none. Start-Process -WindowStyle cannot say 'do not activate'; a WMI Win32_Process.Create start with ShowWindow 4 removes most of it, and WMI replaces the whole environment block (pass it). A guard that undoes steals must not wait on the loading game's thread (sync SetWindowPos on it blocked 0.7 s) and must run its hooks on a thread that never scans the z-order.
