git reset --keep refuses on ANY untracked file at a path the move adds, even one byte-identical to the incoming blob, and names only the first collision it meets — that is what stalled ./publish twice on 2026-11-17 after a peer landed the same conversation record. It also does NOT refuse on an ignored file there: it overwrites it silently (measured; origin/main added 2 such paths in 400 commits). And a path it cannot hash (symlink, directory) must never be called identical. seat_sync.untracked_added now splits the three cases; the ignored-overwrite is left as it was, deliberately.
