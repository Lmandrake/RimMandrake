arena_tasks.run_vet used ThreadPoolExecutor.map, which yields in submission order: one slow task (a check can take two 300 s CHECK_TIMEOUTs plus trace rounds) held every later finished task's records unwritten, so an outer timeout under the 540 s agent cap lost all of them and repeated vet runs made no progress. Fixed with as_completed. A task whose checks need more than one agent command (RP_SELFTEST_FILTER_BUILD_SERIAL_DLL, 3 checks) still cannot be vetted inside the cap: --budget only stops new starts, it does not bound in-flight tasks.
