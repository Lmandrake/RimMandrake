An offline perf harness that drives only the kernel through a fake world cannot predict live cost when the live world's callbacks do engine work. EXCAVATION_COMPONENT_DIAGNOSE_TICK_SPIKES: the offline slice max was 2.6 ms and the live one 161 ms. The cause was the adapter's ComponentResolved -> SetTerrain per look-band change (about 25 us each, up to 6000 in one slice), which the harness's no-op callback never ran. Also, Mono runs the same kernel about 2x slower than CoreCLR/.NET Framework. Before trusting an offline number, count the callbacks per pulse and price each one live.
