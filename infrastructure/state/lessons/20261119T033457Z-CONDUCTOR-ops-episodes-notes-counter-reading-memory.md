ops_episodes.py note on a COUNTER reading (memory.json kind 'counter', ops_memory KINDS counter: *.days_since_advance, *.week_used_pct; e.g. plan.days_since_advance, codex.week_used_pct) is graded on its per-hour RATE 'v', not the level ('level'/'last', the value the digest shows); the printed '(now X)' echo is that rate. So a level-valued note either never holds or holds trivially: 'plan.days_since_advance > 15' can never hold (the rate sits near 0.042/h (days_since_advance flat reads ~0.042/h) while nothing advances, 14.86 being the level, and goes negative on a reset; write '> 0.03' for 'still no advance'), and '< 62' against codex used % (level 44) compared 1.69 %/h and holds trivially. Read readings[key].kind and the '(now X)' echo before writing --value, and write the threshold as a per-hour rate. Measured on three consecutive days: two Operations runs (2026-11-16 13:55Z, 2026-11-17 01:55Z) wrote the level by mistake, and note 20261119T0330Z#1 is void for this reason; the lesson did not prevent the third mistake, so this is a tool defect (a note that refuses a level on a counter would end it).
