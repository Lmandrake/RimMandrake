A 'return' inside a 'with t.component(...)' row in a modcheck chain does not end the row; it ends the whole CHAIN. Every later row is never entered: absent from the run record, and absent from required_checks.json too, because the offline probe walks the same code. TrophyCraft's crafting returned on PASS and its layer and pendant rows had never run (fcf30f3fcb). Put a row's early exits in a helper function and call it inside the with block. Also: when you lift a declared UNMEASURED latch, restore the PRIOR upstream_reason, never None, because a later plain FAIL latches without setting a reason.
