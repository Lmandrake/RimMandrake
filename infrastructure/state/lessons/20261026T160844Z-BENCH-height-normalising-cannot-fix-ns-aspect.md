Normalising derived facings to one visible height (wholeset/norm.py, used for whole-set redraws) can CREATE an F_SIZE_JUMP between north and south when the two renders disagree in aspect. RM_Muttavaq s1r3: the raw north was 487 px tall x 928 wide and the south 416 x 990. Scaling each to the east's 252 px height made north 480 wide against south's 600, and GPT confirmed 'north narrower than south'. No single transform keeps both height and width parity, so this is a render inconsistency to regenerate (the derive prompt must hold the body's front and rear width and height to the east), not one to post-process. Check the N/S width ratio after normalising (flag if more than 10% apart) before spending a judge call.
