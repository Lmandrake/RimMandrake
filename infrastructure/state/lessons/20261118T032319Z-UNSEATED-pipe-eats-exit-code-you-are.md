A pipe eats the exit code you are about to report: `cmd | tail` returned 0 while the acceptance test under it was FAILING with 43 blocked items, and I nearly recorded that as a pass. Capture it immediately (`cmd > log 2>&1; rc=$?`) or read the tool's own printed verdict line; `set -o pipefail` before any pipe whose status you will use. This is the same habit that hid four consecutive consult failures on 2026-11-17 — it is not a one-off, it is the default behaviour of every pipeline in this repo's tooling.
