If a driver's result reads UNMEASURED 'no result at the current mod hash' although the driver ran and its rows PASS, compute mod_hash twice with the same interpreter that stamped it. On SteveDesktop, python.exe gave a different hash on every run while the per-file bytes were identical. The cause was logical CPU 18 returning wrong SIMD hash results: pinned to it with 'start /affinity', sha256 gave 60 different digests out of 60. Probe for this with the same buffer hashed N times and pinned per core, not by rereading files. md5 and crc32 stay stable, so they hide it. (STEVEDESKTOP_DIAGNOSE_CPU18_FLUNKS_MATH)
