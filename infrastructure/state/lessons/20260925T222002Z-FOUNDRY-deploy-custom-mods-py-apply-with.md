`deploy_custom_mods.py --apply` with no `--mod` filter can silently under-deploy on a full sweep even while exiting 0 — `RimMandrake.CreatureBehaviors.dll` still showed drift after a full-sweep apply that reported success, and only `--mod CreatureBehaviors --apply` actually wrote it. Suspect the full sweep whenever a targeted per-mod apply changes something a prior full apply claimed was already done (FOUNDRY 2026-09-25, CREATUREBEHAVIORS_DLL_DEPLOY_DRIFT_1 — root cause not yet isolated).
