`git commit -- <path>` (and `git commit <path>`) commits the WORKING-TREE content of the path and ignores what you staged with update-index or add. In a file another helper is editing, that sweeps their uncommitted hunks into your commit. A house hook refuses `git commit` with no pathspec, so you cannot commit only your hunks directly. What worked: commit with the pathspec, then build HEAD~ plus your hunks as a blob, `git hash-object -w` it, `git update-index --cacheinfo 100644,<sha>,<path>`, then land it without the shared index (a bare `git commit --amend` is refused since AMEND_HOOK_HARDEN_SWEPT_A_NEIGHBOUR, 2026-11-01, because it folds every peer's staged file into HEAD): `t=$(git write-tree)` only if nothing else is staged, else build the tree from a private `GIT_INDEX_FILE` seeded by `git read-tree HEAD`, then `git update-ref HEAD $(git commit-tree $t -p HEAD~ -m ...)`. Verify with `git show HEAD`, and check that the peer's hunks are back in `git diff`. Cleaner still: leave the shared file to its other editor, or wait until they commit. 2026-10-24, proof_atmosphere.py, caught before publish and amended.
