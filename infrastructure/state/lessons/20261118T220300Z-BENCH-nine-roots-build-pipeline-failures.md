Nine roots behind a build pipeline's failures, measured on the retired Relentless Pipeline (2026-11-05 failure catalog); check any pipeline design against them. (1) It acts on a reading it cannot trust: a 0-usage reading became a full charge, an unreachable file a weak proof; every reading must carry whether the instrument could see. (2) One bad source multiplies into N tickets or N retries: deduplicate inflow by source event, not by text, before admission. (3) A global gate where a scoped one was needed: a gate must say which items its cause can affect. (4) A fix that needs itself to land: repair routes must not run in the machinery they repair. (5) Routing by verdict word, not by cause: product, measurement and environment failures need different routes; 'not sure' must not default to a builder. (6) A contract easier than its failure: check that a pass condition would have failed on the original failure (a negative control). (7) The owner is the alarm of last resort: alarms must name items and fire on a new event, not only on aggregates. (8) Missing levers mean state is edited by hand, leaving no causal record. (9) A conclusion outlives its evidence: link each hold, showing or ticket to the reading behind it so it is recomputed when that changes.
