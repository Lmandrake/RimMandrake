A live GC storm can be predicted offline. Unity's Boehm GC collects about once per heap/3 bytes allocated, so GC count ~= bytes allocated / (heap/3). The 325-basin relay wave fit this: 200 lays x 340 MB on a 3.45 GB heap ~= 60 GCs, which is what live showed. Measure per-op garbage in the net8 SelfTest with GC.GetAllocatedBytesForCurrentThread around the op, and split it with temporary byte-clock laps. Then set the bound from the target GC count, not from a round number. Here 64 KB was unreachable and pointless, and 6 MB gives about 1 GC per wave. Before landing an allocation refactor, prove it is behaviour-preserving: hash every lay's points before and after (here 504 lays, bit-identical).
