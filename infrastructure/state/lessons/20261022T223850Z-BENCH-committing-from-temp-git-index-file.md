Committing from a temp GIT_INDEX_FILE (read-tree HEAD; add; write-tree; commit-tree -p HEAD) in a shared seat clone is racy: if a peer commits between read-tree and commit-tree, the new commit silently reverts the peer's files. Read HEAD once, build the index from that same sha, and update-ref with that sha as the expected old value (MEASURED 2026-10-22 BENCH overflow builder: survived only because the peer landed before read-tree).
