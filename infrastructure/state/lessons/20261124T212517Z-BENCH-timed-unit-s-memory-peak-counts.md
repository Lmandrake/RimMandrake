A timed unit's memory peak counts the page cache that its git children fault in: one cold 'git log -- <path>' over the whole history of a clone with a 10.6 GB pack charged 974 MB to the unit, though git's own anonymous memory was about 70 MB. Give git a --since (with a day of slack for commit clocks) and run the read through own_cgroup.run. To bench it, drop the pack from the cache first with posix_fadvise DONTNEED, or the pages are charged to whoever read them before and the peak reads falsely low.
