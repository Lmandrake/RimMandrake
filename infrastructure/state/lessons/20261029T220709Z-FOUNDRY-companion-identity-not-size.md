A JawaBench companion DLL's identity cannot be read from its size or its build stamp. Size: a PE file is 512-byte aligned, so a rebuild from different source routinely has the identical byte count, and sync_test_mods.py's file-count+bytes 'same' let SteveDesktop run droid_dig on a companion missing manualPrioritiesOn (J20261029T211737Z-3af227, rows UNMEASURED/HARNESS). Build stamp: AssemblyInformationalVersion '+<sha>' is the HEAD of whichever clone built it, often a seat/scratch commit absent from every other clone (both Archmagi copies on 2026-10-29), so ancestry checks are impossible. Fix (STEVE_COMPANION_FIX_DLL_STALE_NO_PRIORITIES): build.py embeds AssemblyMetadata JawaBenchSrcHash = hash of the companion sources; companion_identity.py compares it with the git tree at the job's sha; the testq worker's deploy phase refuses (INVALID/DEPLOY) or installs a FRESH staged copy with the game down. Compare binaries by sha256 or an embedded source hash, never size.
