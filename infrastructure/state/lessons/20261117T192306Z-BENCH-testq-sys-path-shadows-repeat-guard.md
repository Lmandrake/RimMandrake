testq and rimflow both have a repeat_guard.py. Any testq code that does sys.path.insert(0, rimflow) (pipeline_admit._moh before this fix, and testq._rimflow, which is still there) makes a later plain 'import repeat_guard' load rimflow's module. testq's repeat guard then failed open on every submit and fill, and the only sign was a log line, 'repeat guard could not read <mod>: no attribute hold'. Load a sibling module by its file path (importlib spec_from_file_location), never by putting another package dir first on sys.path. Fixed in pipeline_admit._moh, testq._own_repeat_guard and ingest.test_author_lines; the selftest_testq_pipeline_admit import_checks section and the moh_syspath and rg_plain_import mutants cover it.
