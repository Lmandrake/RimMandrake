## The slick/locked mechanism
Both source docs named the concept and explicitly deferred the mechanical
shape ("a mechanical slick-vs-locked web state is deferred to the roster/
web-Things work, noted here so it is not lost") — neither ever specified a
comp, a radius, or a building, only "v1 expresses it as flavor + the
hediff's tend-resistance." Built to exactly that, reusing existing patterns
rather than inventing a new rule system:

- `RUT_Webwork_Slick` (`src/RimUtinni/UtinniPatches/Defs/HediffDefs/
  RUT_WebworkSlick.xml`) — three stages (sticky -> slicked -> locked)
  escalating a Moving capMod, `HediffCompProperties_SeverityPerDay` (slow
  natural decay) + `TendDuration` (fast decay tended — "a doctor can free
  them"). Top stage CRIPPLES (Moving setMax 0.08), never downs, matching
  `RM_Hediff_SunScald`'s own 2026-09-11 ruling against a stronger mechanism
  than was ever asked for.
- `RM_CompProperties_AdhesiveSlick` + `RM_CompAdhesiveSlick`
  (`RimMandrake.CreatureBehaviors`) — a generic RM_-tier ThingComp (any
  Building can carry it), same posture as the assembly's own
  `RM_CompHeatPusherGated`/`RM_CompDrumLure`: ticks, scans its own cell (or
  a configured radius) for pawns, refreshes the configured hediff.
  "Commandable": gated behind vanilla `CompFlickable.SwitchIsOn` when the
  parent carries one (same idiom as `RM_CompDryFieldEmitter.IsActive`/
  `CompDWCharger`) — the player's own Gizmo toggle, zero new C# for the
  on/off half.
- Wired onto `RUT_Webwork_Web` (the sheet web — the one of the three a pawn
  actually stands IN) alongside `CompProperties_Flickable`.
- Mod Settings: `adhesiveSlickEnabled` / `adhesiveSlickSeverityMultiplier`
  added to `RM_CreatureBehaviorsMod.cs`, same shape as every other toggle in
  that file (off degrades cleanly: a caught hediff still decays/tends
  normally, it just stops topping up).

**Deliberately not built** (would need an owner ruling, not specified by
either source doc): a player-CRAFTABLE version of the trap. This v1 rides
the wild sheet web the biome already spawns via `RM_MapComponent_FrontCreep`
(border creep) — there is no bench recipe of its own. If the owner wants a
player-buildable slick trap, that is a follow-on item, not a guess here.
