  original rain-generation formula from `ashkarr_paint.py`, gated on reproducing ≥99% of
  live `rain_mm` values exactly before writing anything (its own hard-coded safety gate).

  instead — a deliberately cruder percentile clamp, chosen BECAUSE this script's approach
  was proven non-viable.

  makes re-running this today strictly worse, not just stale: it also states the CSV's
  prior lineage (seeded by `ashkarr_paint.py`, which this script reverse-engineers) is now
  DEPRECATED — the file is exported from a savegame, not generated by that code path at
  all.
- Net: `--apply` cannot currently do anything (the 99% gate refuses it, same as before) —
  running it is harmless — but the tool can never succeed at its stated purpose again. This
  is a dead-file candidate by the project's own convention (a permanently non-viable
  experiment whose replacement already shipped), not a live one-shot worth keeping as
  provenance the way `ashkarr_dry_jungle.py`/`ashkarr_clamp_rain.py` are.
- Also missing the sibling `verify_frozen.warn_if_stale()` convention (moot in practice
  since the 99% gate independently blocks any write, but noted for completeness).
