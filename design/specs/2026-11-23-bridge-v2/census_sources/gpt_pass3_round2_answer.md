1. **BLOCKER — `11_design.md`, tuning rule; `act.md`, State changes.** Tune a setting, let the simulation change, save, restart, then load that save in a clean accepted run. The process stamp has disappeared; the altered world survives and can count. Restoring the field at close does not undo simulation history. **Repair:** persist contamination in saves and derived fixtures; inherit it on load. Restart alone cannot establish clean provenance.

2. **BLOCKER — README, “Two stamps”; design, raw access.** A scene writes a field through `s.raw("jawa/static_call", ...)`. It receives EXPLORED, but no supplied rule makes that contamination persist across sessions. A second accepted session in the same process can therefore omit the raw call and count. **Repair:** make potentially mutating raw calls set an authoritative, process-wide contamination stamp, inherited by new sessions and attach. Treat unknown raw tools as mutating.

3. **BLOCKER — design, “Rigid interfaces and gates”; both red-check sections.** A fake reply saying “stopped at tick 100” passes `test_run_stops_on_the_tick_of_the_condition` even if the real hand stops at 101. Fake frame counts likewise cannot prove that a batch had no intervening frame. **Repair:** retain fake tests for Python behavior, but require live checks with independently observed ticks, frames and read-back effects for these promises.

4. **BLOCKER — `run.md`, lost-reply recovery; `act.md`, `REPEATED_REQUEST`.** In `r = s.run(...)`, lose the first reply: `r` was never assigned, so neither advertised recovery method is callable. An act retry instead raises a refusal and can close the session despite successful execution. **Repair:** allocate a recoverable request handle before sending. Identical act retries return the stored Effect; reuse of an ID with different arguments raises a distinct conflict. Retain deduplication state across driver replacement.

5. **BLOCKER — `run.md`, condition recording and faults.** The position read fails on the only tick a raider leaves the moat. Treating the unknown predicate as false produces a misleading limit result; treating it as true invents a hit. Neither behavior is specified. Dropped trace rows can also leave a closing record, avoiding `TRACE_INCOMPLETE`. **Repair:** define unknown-condition behavior explicitly and invalidate affected evidence. Resolve “conditions are always recorded” versus `UNRECORDED_VALUE` by automatically recording supported dependencies and refusing unsupported ones.

6. **SHOULD FIX — `act.md`, `TUNE_NOT_LIVE`.** A writable setting exists, but the mod copied it into a cache during startup. Reflection can locate and write the field; it cannot establish that the field is “read only at load” or identify the necessary follow-up. The promised refusal needs knowledge not supplied by the target path. **Repair:** permit tuning through classified write recipes; refuse unclassified targets by name. Test each recipe against the game.

7. **SHOULD FIX — `run.md`, stop and return semantics.** Immediately after `fill` at tick T, call `s.run(until=c.ticks_after("fill", 0), limit=10)`. The condition is already true, but evaluation is specified only after a tick: T or T+1 is unresolved. On a limit or cancellation, `r.tick` is described as the tick the condition became true, although it never did. **Repair:** specify initial evaluation, tick endpoints and hit/limit precedence; make `r.tick` always mean the actual stop tick.

8. **SHOULD FIX — `run.md`, group recording.** Track `"raiders"`; one member dies at tick 40 and another spawns at 41. Does recording follow current membership, retain the original cast, or include both? Removing the dead pawn from the group can erase the expected `gone` state and its unreadable count. **Repair:** choose frozen or changing membership explicitly, record membership changes and stable entity IDs, and define departure samples.

9. **SHOULD FIX — `act.md`, Effect and batch promises.** An order can be accepted while its intended work remains pending; reading back the accepted job does not prove the intended effect. For an explosion, “the value before and after” names no particular observation. The batch also admits `reload`, without resolving whether loading can span frames. **Repair:** define each verb’s observed postcondition and distinguish acceptance from completion. Exclude reload and other yielding operations from the no-frame batch guarantee.

10. **SHOULD FIX — README, universal receipts and session order.** `scene.contract` runs before a game is touched; `scene.judge` can run offline after the session closes. Neither can obtain current game-filled build lines, although every return supposedly contains them. **Repair:** distinguish live receipts from declarations and offline judgments. Offline receipts reference the source trace’s provenance; unavailable current-game fields are explicitly inapplicable.

11. **SHOULD FIX — `act.md`, `TWO_ACTS_ONE_TICK`.** Two changing calls on the same paused tick either succeed or refuse depending on an experiment that has not happened. Yet the page promises a refusal test for every row. Version 0.1.0 has no determinate behavior to implement or test. **Repair:** state its behavior for this version. Activate a different rule through a versioned contract change after the experiment.

12. **SHOULD FIX — `act.md`, Accepts and examples; design, signature gate.** Every verb supposedly takes `name=`, but the second `b.place` and the tune example omit it. The Accepts table also omits almost all verb arguments, so comparing it with signatures cannot provide the advertised protection. **Repair:** state whether `name` is required or optional and correct the examples. Publish the actual per-verb arguments and defaults in the material checked against signatures.

13. **SHOULD FIX — design, promotion rule versus “Kept” hands.** Two scenes call `jawa/static_call` for entirely different proof helpers. The census promotes the shared tool name, although no shared semantic capability was demonstrated—and the design separately says `static_call` remains reachable only through `s.raw`. **Repair:** promote a shared typed operation, not a transport tool name. Exclude generic dispatchers from automatic promotion; make census output a proposal requiring review.

14. **SHOULD FIX — design, struggle rule; README, growth rule.** Two scenes perform the same raw sequence of two reads, then calculate a result in Python. That triggers a new hands ticket despite having no timing or observation problem; a Python helper would remove the duplication. The README also omits this fourth trigger entirely. **Repair:** require evidence of a bridge-boundary limitation before demanding a new hand. Keep ordinary composition in Python and reconcile the trigger lists.
