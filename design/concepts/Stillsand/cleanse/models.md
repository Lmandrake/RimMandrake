# Instruments to build when the named risk is encountered

These are specifications, not built models or measurements. Order is build priority. No output may be reported as measured game behaviour before the calibration below succeeds for the source, assemblies, dependency versions, settings and save being tested. All use all DLC. The existing cave/sun/dune/ledger kernels and fuzz are reusable parts, not calibrated whole-mod proof. A changed dependency invalidates the affected calibration, not unrelated bars.

## M_STATES: generated situations and ownership walks

**Question.** Can a retained cave, creature or work transition lose or duplicate an identity, claim another owner's state, or reactivate a deferred feature?

**Informs.** B_LIFE, B_PRESERVE, B_REFUGE, B_SIGNS, B_SUPPLY, B_WHOLE, R_FEED, R_LIFE, R_PRESERVE, R_REFUGE, R_ROWS, R_SAVE, R_SCOPE, R_SETTINGS, R_SIGN, R_SWIM. Unknown meetings `wildlife_state`, `saved_state` and `corpse_owner`. This is the required generator of situations, with each generated case tagged by the bars that read it.

**Inputs/range.** Read resolved defs and declared settings, cave membership/roof masks and held-item/pawn ownership from supplied snapshots. Enumerate no-cave/held/cleared/reoccupied; live/dead/despawned/tamed occupant; item on recorded cell/carried/stockpile straddling edge/outside/unroofed/destroyed; rot enabled/already disabled by another owner; ordinary animal corpse/titan site/ordinary item. Walk roof loss, movement, loading, job interruption, worker death, feed exhaustion, blocked output, stack split/merge, receiver shade entry/exit, disabling/re-enabling each retained feature and default-off deferred-feature gates. For swimmers cover Sand/Gravel/deep drift/hard rock, active-field absent/present, dry/damaged/dead/departing actors, droid and flesh targets; hold hydration/carried-water inputs in paired swaps. Generate transition orders up to length 6, including save-load between each state-changing pair. Use symmetry classes for identical stack members and actors. Run explicit 40-worker contention schedules as a separate bounded sweep; do not call pairwise coverage a proof of the longer interactions.

**Assumptions/leaves out.** Production reducers/decisions can be called in a host with recorded engine state, or their adapters can be checked against the engine. The generator must not implement its own rival eligibility/preservation rule and then prove itself. It does not model Unity rendering, audibility, emergent AI choice, exact combat or flight animation. If an adapter cannot expose the real transition, that branch becomes an explicit runtime case, not an offline pass. Ordinary wildlife AI and DoBill execution still need their B_LIFE/B_SUPPLY state traces.

**Calibration before belief.** T_OBSERVER records a normal engine trace across each distinct transition class, plus a boundary case where roof, den or held ownership changes. Compare actual item/pawn IDs, row identity, owned disabled/vanish flags, jobs/reservations, pending products and toggle eligibility at the same event boundaries. Require exact discrete agreement; clock agreement is within one declared owning scan/tick interval and that interval is recorded, not guessed. A disagreement blocks use of that adapter's offline verdict. Compare save-before/reloaded/no-reload siblings; include externally disabled rot to catch a false ownership restore.

**Produces/decision.** A state graph, transition-to-bar coverage manifest, shortest failing order and engine-replay fixture per discrepancy. Decide which ownership/atomicity/decoupling rule must change first; never “fix” loss by loosening a bar. Unknown old extra states are listed rather than discarded.

**Rough size/trigger.** [guess] A few thousand to tens of thousands of reduced traces, minutes offline, based on the independent axes above; one focused engine trace per distinct transition class. Build first, because unknown identity/ownership meetings and default-off coupling exist now. T_STATES owns the adapter and regression instrument.

## M_SEASON: complete-map season and accumulated consequences

**Question.** With ordinary life, wind, weather, caves and work all running, does an open desert with practical repeated expeditions persist instead of becoming a resource flood, barren dead cast, stalled settlement or error storm?

**Informs.** B_LAND, B_LIFE, B_REFUGE, B_SIGNS, B_SUN, B_SUPPLY, B_WHOLE, R_LAYOUT, R_LIFE, R_RECEIVER, R_SCOPE, R_SIGN, R_SWIM, R_WEATHER. Unknown `landscape` and `weather_sand` meetings, including the three-way loop: water/food supports animals, animals consume/produce resources and modify shelter use, settlement clearing/hauling changes drift and animal access. The model includes kept engine behaviour and ordinary vanilla weather; it does not fake a second biome signature.

**Inputs/range.** Start from whole saved local-map arrays, not cleared test pads: terrain/depth, cover and rocks, cave masks and row/contents, plant ages, living species/food, bodies, wreck stocks, roof and job/input inventories, wind and weather history. Sweep supported supplied layouts at 225, 250 and 325 cells per side plus the actual largest intended supplied local map; no alternative planet or seed generation. Run 15 game days, with fresh and 100-day-aged initial states, parties of 1/6/40 colonists, inhabited and uninhabited starts. Use the actual game's days/quadrum conversion. Replay recorded ordinary weather/event draw streams and separately bound their observed extremes. Include a storm overlapping a moving giant-shadow transition and a live work cycle; do not wait for every random event to happen naturally. Label a replay as a controlled weather history, never natural frequency proof. Keep everything at proposed shipped defaults and next-version extras off. Compare original/reload-at-midpoint/reordered exploration-versus-work schedules.

**Assumptions/leaves out.** Use imported engine depth/growth/population transition interfaces or declared reduced rates measured from snapshots. Preserve feed consumption, plant growth/death, eligible spawn/departure, drift transport and clear-yield accounting; include boundary sand flux rather than asserting conservation in an open system. Do not approximate labour/pathing into an automatic success: supply M_SUPPLY's service envelope and flag cases outside calibration. Combat, audibility, composition and visual openness cannot be accepted by the model alone. If the shared engine exposes no credible offline transition interface, use an instrumented runtime season for that part. That limitation increases runtime cost; it does not justify a fictional simulator verdict.

**Calibration before belief.** Read the same save at start and after ordinary weather/feeding/clearing/growth/work intervals. Replay the captured exogenous choices in the model. Require exact identity and discrete production/death/arrival/departure accounting where the engine is replayed, no invented water/food/output, and depth/plant-progress residuals within the game's own quantization/owning update interval. For an aggregate approximation, publish its errors against both an uninhabited map and a working colony, including the worst region; it may only identify risk and choose scenes, never directly pass a bar. A model that predicts the average but misses a flooded cave entrance fails calibration. The authoritative whole pass remains the full runtime bar.

**Produces/decision.** Time maps of exposed traversable routes, flora/animal distribution, stocks, jobs waiting, cave eligibility and error counts; event-accounting tables; worst interval/region per bar. A flood means supplies or new contents appearing without the declared source, or a living/terrain carpet that removes the open crossing. A desert failure means no viable ordinary life or no practical regional discovery route, not merely low fertility. A stall means valid queued work cannot resume after its reason clears. Repeated exceptions are an error storm. Change the responsible rates, source coupling, clearing policy or optional choice, then replay only affected intervals; keep numerical thresholds in checks, not bars.

**Rough size/trigger.** [guess] Tens of complete-map scenario runs; a reduced grid simulation is minutes to hours, runtime calibration longer. Build after M_STATES, before tuning interdependent rates. Trigger exists now (unknown whole-map feedback); also trigger if a constant is changed twice to move a check, or the whole bar first fails. T_SEASON owns it.

## M_LAYOUT: cover, passage and receiver geometry sweep

**Question.** Across legal positions and bearings, can the same geometry make an earned refuge and moving shelter usable while correctly exposing the work apparatus and stopping hidden travel on genuinely hard ground?

**Informs.** B_LAND, B_LIFE, B_PRESERVE, B_REFUGE, B_SUN, B_SUPPLY, B_WHOLE, R_LAYOUT, R_PRESERVE, R_RECEIVER, R_REFUGE, R_SCOPE, R_SWIM, R_WEATHER. Unknown `sun_geometry` and `refuge_geometry` meetings. Attacks the rule choices about local layout and receiver location before challenging any shared Direct Sun requirement.

**Inputs/range.** Use RM_PreciousCaveGeometry, current shared sun/cast math and moving-shade layer with exact resolved footprint/caster/roof data. Enumerate supplied maps' legal build positions and orientations; solar elevations over the dayside including near-horizon, zenith and either side of every existing branch threshold; all actual fixed-world tile bearings plus angular cell-edge boundaries. Include outcrop edge/corner/too-thin/disconnected/hollow/blocked shapes, existing tor cases, chamber rims, entrance clearance for each real pawn/giant footprint, skull pockets/rib gaps, plant growth stages, parasol overlaps, moving/dead/removed giants and multiple overlapping casters. Cross roofed sand with active drift above/below the shared swim threshold, and appliances root/interaction cell/worker under different cover. Include absent/disabled drift service. Use shape/cell equivalence reduction, but report the full declared axis coverage.

**Assumptions/leaves out.** Rendering is not shade geometry and never the oracle. Use the shared engine's cast representation; an independent geometry reference checks roof coverage, ray direction and continuity, not a rival biome-specific heat law. Do not recreate the old angle-dependent roof exceptions. This sweep checks reachability and current occupancy snapshots, not whether an unblocked hostile will later choose to attack, weather frequency or human judgement of an evocative landscape. Existing cave selftests use synthetic yardangs and cannot alone prove real rock/roof placement.

**Calibration before belief.** T_OBSERVER exports actual terrain/roof/caster positions, computed exposure/shade and GridVersion, pawn footprint/path results and RM_SunPower receiver factor from unmodified runtime fixtures. Sample each distinct shape/edge/transition class and compare every cell of those sampled masks. Roof blocking and reachability agree exactly; continuous shade/sun factor differences must be at most 0.0001 and felt-temperature differences at most 0.05 C with matched air/weather. Those are proposed instrument tolerances, not bars or measurements. Include moving caster old-cell clearing and overlap restoration after removal. If live cached reads have not reached their declared update point, wait that point and report latency; a recompute command cannot prove ordinary update latency. Mismatch names the violated adapter/rule and invalidates its sweep until repaired.

**Produces/decision.** Exposure/passage masks, receiver/worker disagreement plots, counterexample layouts, worst blocked mouth and stale-shadow path. Decide receiver rule/location, layout fallback or update invalidation; do not “fix” by granting biome-specific shade. T_LAYOUT and T_SUN own the instruments/implementation boundary.

**Rough size/trigger.** [guess] Tens of thousands of cell/pose cases per supplied layout after equivalence reduction, minutes offline. Build as soon as M_STATES establishes reliable state exports, because unknown cover meetings already exist. Also trigger on the first misplaced mouth, unsafe reported cover, moving shade mismatch or receiver retuning.

## M_SUPPLY: practical provisioning and dependency economy

**Question.** Can a real discovery change the next trip's provisions or equipment through reachable ordinary jobs and trade without any deferred extra supplying the missing link?

**Informs.** B_LIFE, B_PRESERVE, B_SUPPLY, B_WHOLE, R_FEED, R_LIFE, R_PRESERVE, R_RECEIVER, R_ROWS, R_SAVE, R_SCOPE, R_WATER. Unknown `supply` meeting and the loop between local extraction, workshop construction, water recovery, expedition use and next input access.

**Inputs/range.** Build the recipe/construction/harvest/butcher/salvage/trade graph from resolved defs and actual providers. Include plain furnace (biosilica/steel), bench (wood/steel), plain oven/still, glass-sand clearing, trade-only fine sand, lens glass/precision lenses, brine/eggs/meat feeds, labour skill and workgivers. Mark the rare upgrades, sieve, turret, wringing, Debt and all event rewards unavailable. Analyze starts with imported basic supplies versus no industrial inputs; each retained cave row, taken cave, depleted cave, brine access, no useful cave, low/high usable sun and ordinary storms, occupied/blocked receivers, scarce shared input and 1/6/40 workers. Compare workshop-first with exploration-first, interruption/death/reload and blocked output. DBH present/absent is a provider boundary, never a DLC boundary. With DBH absent, plain RM water is physical carried/traded stock, not a newly invented thirst or potion action.

**Assumptions/leaves out.** Recipe graph reachability is not completed work. Labour queue estimates use measured service/reservation traces; exact planner schedules use the game's actual order rules. No guaranteed trader visitation, no unlimited free fine sand, no automatic conversion of market value into wanted goods. A trade route counts only if the supplying tier has an actual offer/provider; its absence becomes a disclosed constrained start or a build discrepancy. This model does not judge enjoyment or promise total self-sufficiency. Brine dipping is the existing replenishable source with real work cost, not simulated depletion silently added to its spec.

**Calibration before belief.** Observe normal extraction, bill, hauling, cooking and rare-tick still cycles with inputs/outputs and reservations recorded. Require exact discrete item/volume agreement with defs, no consumed feed without placed/pending output, and a planner trace that predicts actual queue progress within its declared service interval. Test a blocked output cell and shared last input. Sample an actual trade inventory/ordinary exchange for the trade branch; no current supplier measurement is claimed here. Record exact scalar values as checks only. A clean graph cannot certify an unobserved runtime job path; B_SUPPLY retains the normal-action state trace.

**Produces/decision.** Reachable provision/equipment graph, bill/bootstrap deadlocks, conserved resource ledger and worker-contention timeline, shortest actual route from each useful discovery to its next use. Decide whether a kept dependency needs a fix, a start must carry an input, or an optional rule causes a deadlock. Never rescue it by secretly re-enabling the sieve or giving free completed outputs.

**Rough size/trigger.** [guess] Hundreds of recipe/stock combinations and a few dozen scheduling traces, seconds for graph checks and minutes for queue simulations. Trigger exists now: input access without sieve/upgrades is unproven. Also build on the first stalled bill, lost output, or repeated yield/work-rate retune. T_SUPPLY owns it.

No credible offline model can certify visual openness at ordinary zoom, visible warning clarity or actual audibility among other sounds. B_LAND and B_SIGNS use the cheapest short live looks/listens for those properties; T_SIGN supplies a matched quiet/control observer. B_WHOLE combines calibrated model/state evidence with the runtime season. None of the instruments is built during this design-only pass.
