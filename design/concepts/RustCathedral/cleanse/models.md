# Instruments specified now, not built or run on this pass

Build in the order below. All size figures are engineering estimates, not game measurements. An offline result remains a model prediction until the stated game agreement is demonstrated with matching def/settings/assembly fingerprints. Existing shared-kernel fuzz is useful arithmetic evidence, not calibration of jobs, pathing, audio, targeting or save callbacks. ## M1: Situation and transition generator

**Question:** Can each permitted player action, interruption, actor identity and save boundary produce exactly its intended local consequence and recovery, including actual guards, drill targets, terrain exposure and Enclave consequences across neighbouring maps?

**Informs:** B2/B3/B5/B6 and causal portions of B1/B4/B7; R2–R9/R11/R12. It first addresses the `defence` unknown meeting and provides the transaction/event spine needed by the `attitude`, `warnings`, `residents` and `continuity` unknown meetings. It also validates the argued repayment conservation group.

**Inputs/range:** Read resolved defs/settings and the same `RM_AttitudeKernel` used in game. Extend an executable consumer adapter for action events, target selection and transaction receipts; do not copy desired results into a test-only substitute. Enumerate event classes: loose mining, divider breach, sacred first hit/claim/destruction/repair/repeat offence, line start/abort/catch, eel butchery, player/nonplayer bolt kill, deep drill eligible/ineligible/removed/blocked, repayment reserve/deliver/commit/cancel, carrier death, resident strand/death/exit, toggles, map change and reload. Actor partitions: player biological, player droid, pass-holder, visitor and hostile. Initial state partitions: threshold-epsilon/threshold/threshold+epsilon, each displayed band, actual Enclave relation-kind latch on both sides of -75 and 0, local deep-standing bounds, active debt absent/single/multiple, active source absent/single/competing. Enumerate paths to depth 6, then targeted longer loops: same object claim-damage-destroy, duplicate callback after reload, two partial deliveries before carrier death, drill destroyed during response and departure during repayment. Extend the sacred ledger walk over two Cathedral map identities, with the origin loaded/unloaded/deleted and the destination fresh/revisited; include ordinary external goodwill changes, actual Enclave hostility callbacks, partial payments on both visits and duplicate credits. Enumerate debt-free/sub-latch/multiple/latched sacred receipts and confirm that the hum floor does not depend on a scalar threshold accident. Include terrain entry/dwell/exit, mitigated/unprotected entrants and the current toxic/irradiated/sulfuric-edge provider manifest. Sweep each resolved threshold at +/- one representable small step, preserving exact comparator semantics. Test integer extrema at valid API bounds; malformed input gets a named rejection.

**Generated oracle readings:** Use bars' observations: source material depleted and inventory received, warning location/source id, active job/target, debit receipt, consumed/returned material, resident identity/location/death record, force held/exit state, actual Enclave goodwill/relation-kind/contact eligibility and guests/trade/ship consequences, global sacred receipts versus local mirrors, pool-source health/exposure deltas. Checks C3/C7/C8/C9/C12/C14 are the exact regression probes. Include mutant fixtures that omit attribution, restore the stage cap, double-charge after reload, allow dry transit, accept zero-value payment choose AssaultColony, suppress the actual Enclave debit while paying the local ledger, forget sacred receipts on a new map, leave sub-latch debt calm, omit all fishing input or leave pools cosmetic-only. Each must fail the relevant reading, not just a source regex.

**Assumptions/exclusions:** Scalar kernel arithmetic can be exact; real engine job lifecycle, faction relation-change handlers, terrain exposure callbacks, Harmony overload calls and serialized ids cannot be assumed from a stub. A minimal fixture may abstract ordinary haul path time only after it matches the real transaction sequence. Leave human salience, sprites, all weapon hit probabilities and arbitrary external mod patches out. If actual target/job adapters cannot be executed offline without engine code, output those paths as requiring state replay, not as green synthetic proofs.

**Real-game calibration before belief:** T36 must export an isolated disposable save's def/settings/assembly hashes, full pre/post transaction journal, actual job targets/path cells and reload ids. Drive one real case from each event class and actor/target semantic partition above, plus the shortest failing mutant counterpart where staging can safely break the relevant consumer. Deterministic fields (material counts, standing/debit receipts, source ids, target class/exit reason, death/exit presence, traversed-water validity and serialization equality) must agree exactly; timestamps may differ by at most one documented scheduler sampling interval, never enough to reverse warning-before-escalation ordering. A discrepancy invalidates the affected partition until the model or game adapter is explained and fixed. Old `ProofStage1` synthetic worker counts or direct debit setters are not calibration.

**Output:** Machine-readable situation list, reduced transition graph, shortest counterexample per bar, unreachable partitions explicitly labelled, saved replay plan for each game calibration case, and a coverage report over the stated partitions. Unknown does not become false zero. No new acceptance quota is invented from a count of cases.

**Rough size:** About 2–4 days of instrument work; tens of thousands of pruned short traces plus targeted loops, seconds to minutes per offline batch. Real calibration is a separate targeted state-reading session with all DLC, not a full suite rerun each edit.

**Build trigger:** First build, immediately on resumption after proposal approval: the defence unknown already exists and T29/T30/T33/T34 need a trustworthy event/state oracle. Extend the generator on a newly found game state or the first failure it cannot express; do not add arbitrary examples as a substitute for a partition.


**Review repair calibration:** Before trusting sacred state walks, match actual Enclave goodwill, relation-kind, contact eligibility and staged guest/request/ship callbacks exactly across hostility and recovery, with no scheduled raid. Match global receipt IDs/partial deposits and local hum-floor states on both maps, including origin removal and reload. For minor recovery, record a real fishing-attributed above-calm rise and cue, then fork cancellation/quiet and continued-fishing arms; an always-calm input must fail. Sample pool entry/dwell/exit under identical dry-ground weather/exposure controls; match provider attribution and harmful direction, using exact health/exposure deltas when actual tick scheduling is replayed. Otherwise the terrain model remains uncalibrated. These results decide event routing, persistence, warning-floor and provider-consumption repairs, never a change to the August ruling.

## M2: Local geometry and boundary sweep

**Question:** Do local maze layouts keep route choice, native movement, public retreat and public-side repayment compatible before and after permitted breaches and ordinary depletion?

**Informs:** B1/B2/B3/B4/B5/B6/B7; R1/R4/R5/R6/R8/R10/R12. Settles the `layout` unknown meeting as a group, not just each pair. Provides boundary/path inputs to M1 and M3; cannot settle normal-zoom visual legibility.

**Inputs/range:** The proposed local map-maker's actual cell grid and object footprint export, resolved passability and affordances, terrain/water/roof map, labelled public corridors, protected footprints, guard loops, loose salvage, marked dividers and debt sites. Sizes 200/250/300/325 square; all four rotations, mirrored layouts if the maker supports them, every legal template translation including clipping at the permitted edge margin, dry layouts and canal crossings/parallel channels/disconnected pools/narrow necks. This is a sweep of local layout placements, never a planet/world seed generator. Enumerate every legally marked single breach, intersections of breaches touching the same corridor/guard/repayment region, each ordinary salvage component removed, and worst combined public-side blockages the builder permits. Include path starts at every public entrance, each guarded doorway, each repayment approach cell, each resident spawn partition and every reachable active offence location. For oversized sprites use the pawn's actual collision footprint, separately drawing its visual extent; do not quietly treat drawSize as collision size.

**Calculation:** Flood-fill public reachability; shortest legal routes to salvage, marker and exit; route comparison before/after cutting each marked divider; ingress/egress intersection with guard footprints and weapon visibility; actual eel traversed paths constrained to water (not endpoint-only validation); bolt routes to causes; public-side bill access under hostility; giant clearance; source identity stability after destruction. Public-side marker placement must not be justified by temporarily disabling guard attacks. Produce failure maps for simultaneous canal crossing + guardian footprint + destroyed debt site, a three-way obstruction missed by isolated paths. Mirror the shared geometric shade query for actual footprint/roof tests only; do not invent different heat.

**Assumptions/exclusions:** The actual game's cell pathfinder/LOS and building footprint rules must be sampled, not approximated as Euclidean distance. Offline planning does not decide whether an overhead pattern looks intentional, whether narrow silhouettes are recognisable, whether the audio is audible or whether a player chooses the shortcut. Arbitrary player construction that seals all public entrances is recorded as a refusal case, not blamed on native generation. No guarantees for foreign biomes or modded map sizes outside the declared envelope.

**Real-game calibration before belief:** On exported native layouts at each map-size/water/rotation semantic partition and on each distinct worst-case counterexample topology, read actual pathfinder paths, reachability, LOS, water and occupied cells using the same assembly/defs/settings fingerprint. Require exact agreement on passable/reachable/visible classifications and on whether the path crosses a protected/dry cell; equal path length only when the game path costs and tie-breaks are also imported. Equivalent shortest-path ties are allowed if they cross the same declared boundary classes. Compare native on-screen wall/doorway drawing to the labelled export to catch “correct graph, unreadable picture.” A mismatch in path/LOS rules invalidates all geometry deductions using that rule. Normal-zoom live assessment still decides B1 and the spatial-reading part of B4.

**Output:** Annotated local cell maps, public/held/blocked region overlays, path tables, worst-case route/bill/eel/bolt counterexample per bar, and before/after breach pictures. Never call those pictures real-game screenshots. T29/T36/T37 provide exporters; none exist as an adequate instrument today.

**Rough size:** About 2–3 days once the layout exporter exists; thousands of transformed layouts and graph recomputations with symmetry reduction. Include exhaustively the valid placements of each template in each size, not a claim that a few random local seeds exhaust geometry. If combinations explode, use connected-region equivalence classes and document why their bar failures are identical.

**Build trigger:** Existing layout unknown, before a new maze implementation is accepted. Rebuild the relevant sweep when a template/footprint/water rule changes, a repayment placement fails or a second constant retune is used to hide a route check failure.


**Review repair geometry:** Inputs additionally classify every stationary toxic/irradiated pool and sulfuric-looking edge separately from coolant canals, at each valid layout transform and map size already declared. Sweep public paths, deposit approaches and native spawn/movement cells beside pool edges before/after breaches. Use real terrain movement costs and hazard footprint, not colour alone. Compare game-exported terrain IDs, occupied cells and path classification exactly; use M1’s matched exposure traces for any route-duration exposure prediction. Output safe/unsafe route overlays and the worst simultaneous pool/canal/guard/debt-site blockage, then decide pool/template placement or public-route repair. Native seasonal survival remains M3’s question; offline colour maps cannot certify B1’s pre-entry recognition. Existing layout unknown triggers this extension before any pool implementation is accepted.

## M3: Whole-mod season and workload model

**Question:** With every kept mechanic active, do ordinary, restrained and exploitative colonies retain a usable salvage/temper/recovery cycle over a season, a reload and a different action order?

**Informs:** All bars, directly B7; all rules. Settles the `attitude`, `warnings`, `residents` and `continuity` unknown meetings jointly, consuming the M1 defence and M2 layout results. A passing scalar mood curve alone cannot settle any of these groups.

**Inputs/range:** Actual resolved default half-life, thresholds/hysteresis, per-act impulses, standing/debt/latch rules, source-attraction scheduler, cue/update delays, vanilla fishing duration/catch pool, mining/haul labour, bill quantities and carrier travel, guard/drill eligibility/cooldowns, native spawn/death/cleanable availability and tile temperature/pollution/weather time series. Current source numbers are starting inputs, not owner targets. No curiosity, line-cycle, readers, ship systems, repair arc or campaign progression is active. Use M2's valid/worst local layouts; colony counts 1/8/40; work partitions 0, 1, 2 and 8 concurrent fishers, 0/1/4 breach crews, 0/1/4 eligible drills, with the remaining colonists doing ordinary hauling/building. Separate calm salvage, intermittent minor work/cancellation, continued warned work, sacred offence then withdrawal, deep drill then removal, partial repayment, resident deaths and unreachable cause. Simulate 15 game days with save/reload at midpoint, a recovery extension to day 30 when required and a day-100 depletion/continuity stress continuation. Same action multiset runs in fishing-first and cut-first order, and again with repayment before/after a minor disturbance. Workload counts are deliberate stress inputs [guess], not an empirical report of typical play.

**Assumptions/calculation:** Discrete-event scheduler may batch only truly idle intervals. Feed actual act identities and cell paths; do not replace jobs by a constant “offences/day” when cancellation, concurrency and hauling cause the risk. Import the real weather and sun series; the eternal-noon location is not permission to lock the weather to clear. Track all scalar ledgers, event queues, residents, material stocks, public reachability, target/exit states, warnings/cancellations and log retries. Use a native same-kernel path and retain enough jobs/serialization callbacks to compare compressed and uncompressed traces. If those cannot be credibly represented, the whole-run state portion requires real tick replay; no unsupported synthetic whole pass.

**Failure regimes / decision changed:** Flag loss of public routes caused by native systems; renewed fees/debits after reload; minor-work recovery impossible despite stopping; standing debt unrelated to actual acts; unbounded response population or dropped objects; native life dying under shipped environment without a visible cause; response or delivery states with no outgoing transition despite valid actions; and warnings arriving after the next avoidable escalation. Finite deposits exhausted by actual player mining are allowed and separately reported. Results decide whether to change impulse/decay/attraction/cooldown rules, change geometry, add a missing state transition or repair an instrument. They never automatically weaken a bar or turn an extra back on. If tuning numbers twice moves a check without preserving the cycle, attack the rule first.

**Real-game calibration before belief:** T36 records complete trace snapshots from a native map under restrained, overlapping-minor and sacred/deep/repayment workloads, with midway reload and reverse action order. Match code/def/settings hashes and starting inventory, RNG and weather records. Exact equality is required for standing/debit receipts, inventories, material depletion, source and resident ids, spawn/death/exit counts, and event ordering across reload. Per-transition cue/target timing may differ by at most the actual documented sampler interval and may never invert cancellation-before-next-escalation. For stochastic fishing/guard events, replay the recorded RNG draw/event stream and require exact outcomes; if RNG cannot be captured, compare state-conditional outcomes and label rate conclusions uncalibrated instead of guessing a confidence interval. Compare compressed and actual-tick runs on the same scenario before accepting compression. A persisted scalar record cannot prove heard sound or attention: actual live listening and looking decide B4, and the whole replay plus those observations decides B7.

**Output:** Season timelines, heat/standing/irritation/debt and warning-delay plots, spatial cause/bolt/guard maps, resident/material conservation ledgers, reordered-run deltas, each worst-case counterexample linked to a bar and a real replay recipe. Report model predictions and game observations in separate columns. A trace with an unwired consequence, a hidden stage clamp, extras switched on or kept mechanic switched off is invalid even if calm.

**Rough size:** About 3–5 days after M1/M2 and the trace reader exist; hundreds of workload/layout/initial-state combinations with sampled RNG streams for exploration. Explore all stated workload partitions; boundary equivalence arguments may reduce combinations only when recorded. Full real season replay is planned work, not claimed done. No new parallel games or bridge use is authorised by this document itself.

**Build trigger:** Existing higher-order unknowns make this mandatory before whole-bar acceptance; build its minimal runner as soon as M1/M2 export reliable events. Extend on the first failure caused by concurrency, reload or a seasonal resource loop, or after repeated parameter retuning. Sensory salience has no credible offline model: T32's live instrument is explicitly required, not replaced by a coloured chart.


**Review repair whole-run domain:** Import actual pool cells/provider hazards, actor mitigation and native paths plus game-level sacred receipts, Enclave goodwill/relation-kind/contact state and unrelated diplomatic events. The season includes sub-latch debt, several debts, real diplomatic isolation/recovery and a visit to the neighbouring Cathedral map, with optional plot progression still off. A dry/no-canal workload retains toxic pools. Require exact cross-map receipt, goodwill, relation-kind and callback agreement with matching real saves; pool exposure time/deltas must match the actual-tick control using M1’s calibrated provider callbacks. Report diplomatic isolation separately from unchanged guard footprints, and true debt recovery separately from an always-calm unwired minor input. Include lost-public-route or native-survival failures caused by pool placement, without assuming immunity or harmless pools. This extension uses the existing whole-run unknowns/build trigger and decides placement/consumer/persistence repairs, not new diplomatic mechanics.
