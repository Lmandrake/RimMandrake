# Instruments specified, not built

All models below are Designer proposals. Their outputs are predictions, never measurements of RimWorld. Start with imported local-map state or finite synthetic **local cell** fixtures; do not generate, score, sweep seeds for, or modify planets. A saved state that disagrees with a model wins. Missing runtime/dependency source must be recovered before claiming calibration. The current kernels, Python mock and swarm budget are useful starting materials, not independent acceptance instruments.

## M1: Situation and transition generator

Question: Can any supported phase, ownership, save or settings transition duplicate an event, strand an occupant, lose an identity, or leave a deferred mechanic active?

Informs B5, B7, B8, R1/R4/R5/R6/R10/R11; unknown cycle_clock, pawn_identity and defaults meetings. Build first: safe transition and gating errors invalidate later season readings.

Inputs/range: parse the actual enum, feature gates and serialized fields, not a hand-transcribed assumed enum. Cross phase and boundary tick (before/at/after), pulse in/out of burst, flash open/closed, queues empty/partial/full, last-cue flags, map loaded/unloaded, saved/not saved; pawn wild/tamed/hostile/caravan, healthy/injured/downed/dead, sealed/awake/damage-woken, drafted/mental state, carried/on ground; cargo item/plant/building/projectile/gas/filth; base/top/temp layer ownership, foundation, safe landing near/far/none. Generate master/pulse/cycle and major feature off/on sequences, including both orders of disable/End/reload/re-enable. Dependency switches are inputs, never assumed synchronized. Full Cartesian coverage for each individual adapter and its boundary states; global combinations use dependency-driven covering arrays plus all three-way meetings in bars.json. Report what combinations are omitted. Default-off extras each get their negative and positive activation sequences from tickets, separately from qualifying default runs.

Assumptions: discrete phase decisions and object ownership can be abstracted without modeling path execution. Call the existing Verse-free kernels for actual rules; a separate invariant oracle asserts conservation and cause, so reproducing the same mistake in mock and implementation cannot self-certify it. Inventory keys absent from recovered runtime are instrument defects.

Leaves out: plant and injury tuning, visual form, full pathfinding, audio quality, probabilistic ecology, actual save serialization internals not exercised by a real reload.

Real-game calibration: serialize and reload disposable saves in each phase and at every queued-work boundary; compare independent map object IDs, stack totals/origins, terrain layers, phase/end ticks, Awake/job state and actual effect emitters against generated trace. Exact agreement is required for identity, ownership, gates, phase ordering and duplicate/no-duplicate event facts; tick boundaries may differ by no more than the resolved scheduling interval, recorded explicitly. Run missing-safe-cell and prematurely-ended-condition controls; a passing debug report cannot substitute. Mutations must be detected: duplicate gardens after load, local master ignored by flash growth, off extra whose callback still fires, resident nodule replacement, removal of foreign temp terrain.

Output: reachable-state graph, uncovered combinations, shortest failing sequence per invariant/bar and replayable local fixtures. Rough size [guess]: thousands of reduced cases plus dozens of actual save-reload calibrations; a small Python coordinator around existing kernel harness and state readers, roughly a few working days once state access exists. Trigger: build now for the three named unknown meetings; any new gate/save key or B7 failure extends it before another season run. Decisions changed: cleanup fallback, event idempotence, gate ownership and serialized-state compatibility; rules change before weakening bars.

## M2: Expedition geometry and work windows

Question: Over every supported route/placement regime, can an ordinary prepared crew actually ripen, cut, haul and leave, and can dispersed workers recall before the next hazard?

Informs B1/B3/B4/B6/B7/B8 and R2/R3/R4/R5/R7/R8/R9; unknown routes, crust and floatstone meetings. Build after transition invariants, before retuning yield or phase duration to hide an inaccessible opportunity.

Inputs/range: import local map cell graph, roof/caster/footprint geometry, terrain layers, actual safe building/shelter cells, vent field and garden eligibility. Exhaustively enumerate all eligible harvest sites and critical return necks on each imported map, all legal wreck rotations/footprints, all legal crust/melt ownership cases, and altered action orders. Use corpus sides 200/250/325, cone/flow/skirt contexts, no/one/under-cap/at-cap/over-cap/full-map lava; frozen-cell samples must include adversarial disconnected sets, not only random examples. The current 6000-cell cap is a read input. Sweep worker speed 0.5–1.5 of healthy adult baseline, crews 1/4/12 and colonies through 40, healthy normal carrying capacity, actual harvest work/maturity/departure clocks, shortest and alternative safe paths, heat-related avoidance and source-position extremes. Declarations bound the supported regimes; they are not bar tuning numbers. No site is excluded solely because it fails.

Assumptions: use game-exported per-step costs/reachability and real job interrupt/harvest/haul timings, not Euclidean speed. Treat latest safe departure as a backwards route calculation through time-varying safe cells. Dynamic fires are imported bounding arrival-time envelopes from the season/heat readers; a static graph alone cannot certify a fire crossing. Current normalized yield can produce incremental stock over multiple trips; zero construction progress despite completed eligible trips fails the opportunity, not a fixed quota.

Leaves out: live appearance, combat interrupts, deliberate work refusal, complete vanilla AI scheduling. If a crew’s observed job scheduling falls outside the calibrated envelope, report unmeasured and use real replay; do not increase the envelope until all outputs pass. No guarantee every island or every garden is harvestable.

Real-game calibration: compare chosen/extreme routes with actual pathfinder paths and reachability on the same recorded maps, including diagonals, doors, walls, fog and terrain changes. Require exact reachable/unreachable agreement and exact path cost for static cases. Natural maturity and crew completion predictions must match actual completion order and conservative deadline classification: the model must never label an observed late retreat safe. Timing tolerance is one resolved work/tick interval, accounted for as a safety margin, not a percentage chosen after the result. Independently read material provenance/consumption, path endpoints and occupancy, not cycle counters. Calibrate no-safe-cell cleanup separately: emergency support is an explicit state, not a fictional escape route.

Output: reachability and latest-departure heatmaps, usable garden regions, permanently connected base regions, work-time/haul/material ledger, worst placement and route per bar, failing local fixtures. Rough size [guess]: tens of imported local maps, millions of inexpensive cell/route classifications and a few dozen actual job replays; several days with existing path-state access. Trigger: build for the three named unknown meetings; also any cap, garden placement, obstacle-footprint, phase-time or harvest-work constant changed twice to move a check. Decisions changed: seeding eligibility, freeze/melt ordering, permanent corridor preservation and warning timing. Do not attack the owner’s prompt-response answer first.

## M3: Whole Forge season

Question: With every retained mechanic and dependency running, does the coupled rain/fire/growth/food/resource system keep producing workable intervals across a season instead of collapse, runaway stock or a stalled cycle?

Informs B2/B3/B5/B6/B8, R1/R3/R6/R7/R8/R10/R11 and unknown flora_food and sky_habitat meetings; its integrated forecast also feeds the geometry and heat meetings.

Inputs/range: actual loaded defs/settings, phase ranges, weather and sun geometry, imported whole-map terrain/fuel/plants/pawn populations and ages/needs, roofs/structures, field rebuilds, mortality/predation/ordinary arrivals, ordinary reproduction only, feeding sources, harvest/haul/build schedules, shared growth/moisture profiles and Bones/Wreckage products. Use each map/colony regime of B8 for 15 days/900000 processed ticks, extend to complete an entire chain; repeat from a day-100 save and through several seasons for trend detection. Include mid-cycle save/reload and both declared action orders; no accelerated plant ticks relative to the clock. Diagnostic arms: no hunting/no deliberate clearance; cycle off; each causal contribution separately removed. Only all-on defaults qualify. No water-flood, explosive-bulloo, swell, research or injected-swarm feedback is allowed at default.

Assumptions: actual C# phase logic and resolved plant-growth rules can be integrated; use measured flux/transition envelopes for vanilla fire, spawning, needs and AI, with uncertainty bands and clearly unmodeled states. The current source’s old mock rates are not game facts. Smoke-herd food intake must be read: the vapor-drifter comp supplies geography/immunity, not proof of calories. Existing shared feeding machinery is a dependency contract; no new gas-harvesting resource is modeled.

Leaves out: accurate recreation of the entire storyteller, combat choices, exact FPS, aesthetics or enjoyment. There is no credible purely offline replica of RimWorld’s complete AI and stochastic ecology in this proposal. This is a calibrated risk screen, followed by the real-tick state trace required by B8; it cannot single-handedly pass the whole bar.

Real-game calibration: before relying on long forecasts, collect all-on default traces for a complete natural cycle on sparse/dense/occupied maps. Compare actual time series of live plants/biomass, burning cells/fuel, animal IDs/needs/food intake/deaths, column occupancy, crust/gardens, harvested/consumed material and exceptions against forecast intervals. Require exact causal event ordering and object conservation; for ecology the predeclared uncertainty interval must cover the held-out game series and predict the same viability/feedback direction in every tested regime. Failing sign/direction or a missed extinction/runaway invalidates the model even if average counts agree. Publish bounds before held-out runs. A disabled-damage trace is not calibration. The integrated season trace is the final arbiter.

Output: whole-map time-lapse state maps, food/fire/material flow tables with uncertainty, worst regime per bar, failure provenance and trace-replay inputs. Rough size [guess]: dozens of map/colony/action configurations, hundreds of forecasts, short calibration runs plus default whole-season traces; a week-sized instrument rather than another game engine. Trigger: build for the two named unknown meetings before declaring the version whole; extend after the first live ecology/season failure or a growth/food/fire constant changed twice to move a check. Decisions changed: Forge tuning/data assignments, source/placement contracts, ordering and gate leakage; no redesign of shared engines or disguised restoration of extras.

## M4: Heat and shelter response

Question: Do direct rain scald, geometric Direct Sun and ordinary hot air together allow the specified first surprise, recall and roof/room distinction?

Informs B2/B4/B5/B8 and R1/R3/R4/R6/R7/R10; unknown weather_heat meeting. Build as soon as a qualifying all-on damage reader exists, in parallel in the build schedule with geometry, without requiring parallel agents on this pass.

Inputs/range: all B2 pawn/equipment/roof/response regimes, actual atmosphere/lava/room temperatures, shared sun/shade state at fixed recorded Forge solar elevations, native flesh/armour/exemptions, burst duration and long Rain phase overlap, time to interrupt/reach shelter/rescue. Sample actual damage distributions and fatal-body-part outcomes, not a scalar HP tank. Deferred moving plume is absent at default. If later enabled, its already-answered wall/roof rule requires an additional propagation sweep, not a biome-specific exception.

Assumptions: replay exported damage and temperature/armour evaluations or conservatively bound them. Do not claim that a hand-built injury simulator can certify pawn survival. If the vanilla anatomy/RNG damage path cannot be faithfully exercised offline, the cheapest credible instrument is M1-generated deterministic game-state trials; mark that portion live-state-only, without inventing an offline oracle. This is still cheaper than a long visual play session.

Leaves out: enjoyment, off-biome climates, DLC-less configurations, late voluntary exposure, unmodeled modded anatomies and combat. A roof removes direct falling scald; an enclosed room blocks direct sideways steam if that extra is enabled but remains subject to vanilla room temperature. Parasols/geometric shade follow the single shared sun rule.

Real-game calibration: matched exposed/roofed/geometrically shaded/enclosed pawn copies and no-rain controls with real heat/scald sources enabled. Require exact source/exemption/roof classification and same survival/rescue feasibility classification, injury progression and ordering within the known damage scheduling interval. Independently read health/injury/Heatstroke and thermometer/shade state; a comfortable-temperature patch is not automatically ambient air. Model fails if it calls a deadly response survivable. Capture RNG/config fingerprints for replay; do not average away a reproducible fatal initial opportunity.

Output: source-separated temperature/damage traces, response-time envelopes and worst-case anatomy/route fixtures. Rough size [guess]: hundreds of deterministic state trials, a compact envelope evaluator, several days with existing state readers. Trigger: the named unknown meeting, the first shelter/first-burst live failure, or a hazard/armour constant changed twice to move a check. Decisions changed: scald timing, warning/work windows and compliant Forge data wiring; no Forge heatKind or new heat species.
