# Instruments to specify before building

These are specifications, not implementations or measurements of the game. The existing plain-net8 production kernels/fuzz and static mutation suites provide useful parts; no result from them proves the complete map. Build in the order below. Calibration uses disposable fixed-world local maps or existing save fixtures only, never new planets, tile edits, bridge work on this pass or canonical saves. Check inputs against resolved composed defs with all DLC, both the RM base and the campaign patches; source-file XML is insufficient for inherited growth, body products or settings.

## M1: Enumerated situations and transition generator

Question: do the bars sort actual reachable state transitions correctly, including disabled extras, interruptions and alternate action orders?

Informs: B2–B6 and B8; R1–R12 as applicable; default-gates and lifecycle meetings; produces inputs for the other models. Assumption: local mechanics can be represented by the production kernel state plus recorded engine inputs, without inventing their own timing law. Reuse `Source/AbyssFuzz` action-sequence machinery, `RM_AbyssKernel.cs`, `RM_AbyssStateKernel.cs` and `validation.py` inventories, not a parallel copy of the algorithms.

Inputs/range: enumerate absent/present/destroyed/moved/powered/off lamps; plant/building/deepfire sources; clear/cold/transitional temperature; ambient Dark/Unveiling/Witchfire; roofed/unroofed; direct path/wall/corner/map edge; wild/tame/downed/dead/carried/despawned krizzaks and nevarithia; hungry/fed/attacking/fleeing native predators; no colony/new colony/forty colonists; RM-only versus campaign-resolved stock including Taozin. Enumerate actual supported map dimensions and building footprints from the loaded game configuration, not guessed dimensions. All kept major settings on at defaults, then each major feature off, then all-off, and each next-version parent/child off/on boundary. Age/saved settings variants cover new maps, a mid-season reload, long-lived maps at day 100 and old extras imported inertly. Use boundary-value partitions with order permutations: heat then plant/exclude feeder, plant then heat/exclude feeder, feeder dies vs lamp removed, weather change vs reload, halo death vs Unveiling. Exhaust small local state combinations; use covering arrays only for independent map-wide dimensions, disclose uncovered combinations.

Leaves out: subjective visual/audio quality, rendering frame rate, economy convergence, generic engine correctness outside the mod's inputs, unreachable combinations (record the invariant making each unreachable). No tests of prohibited worldgen or absent-DLC configurations.

Before belief: compare generated state traces to read-only game traces for each transition class. Final weather, target/job identity, pawn presence, setting gates and terrain/material category must agree exactly; density/glow/nutrition/health agree to the game's own numeric precision after the same scheduled update, with tick phase and unscribed safe resets explicitly aligned. Record actual tolerance justified by the sampled field representation; “looks close” is not agreement. Deliberately mutate absent-cause and gate conditions and show the generator flags the bar's reject picture. A trace class without calibration is marked untrusted, not covered.

Produces: state/transition coverage table, each bar's accept/reject trace, shortest failing action sequence, input hashes and excluded-region list. Size [guess]: a small CLI adapter plus fixtures, roughly a few engineer days using existing kernels; no new game engine. Trigger: immediately, because the proposal's state/lifecycle and default-off contracts cannot be established by def-presence checks. Existing pure fuzz can be used before calibration as a check only.

## M3: Dark geometry, optical paths and composition sweep

Question: can temperature clearance, mobile carried Dark, targeting, useful light and audio all describe the same local air without a safe-room targeting exploit or stale blindness?

Informs: B1–B4, B7, B8; R1–R4, R7, R8, R12; unknown dark-field and light-grid meetings. Assumptions: final density is a bounded deterministic function of recorded ordinary temperature, ambient condition and carried-particle geometry; actual engine wall occlusion and glower updates can be imported or queried for calibration. Do not claim vanilla ray/path behavior from an invented geometric approximation.

Inputs/range: every cell placement/rotation of actual glower and blocker footprints in minimal rooms/lanes, all map edges/corners, overlapping glowers, actual supported map sizes, short/long intervening Dark segments, clear endpoints with Dark between, roof changes, doors closed/open, cold/warm/transition air, native plant/artificial/deepfire sources, zero through dense feeder clusters, living halo moving at normal movement rates, downed/carried/despawned/dying halo, overlapping halos and Unveiling. Sweep temperature at either side of the formation transition and read both the field and player-readable ordinary temperature. Sweep source/observer/target positions, all bearings the game can choose, and geometry update ordering within a tick interval. Reload while a halo trails or a lamp is dimmed. Tuning ranges come from current constants plus their UI bounds; branch-equivalence partitions must include extremes and boundaries, not only a central scene.

Leaves out: artistic quality of the fog, pathfinding policy, colony economy, campaign pursuit scheduling. Fold-lamp lanes and cryptid phantom pockets are off: their disabled APIs must contribute neutral values, not require their own geometry to be built first.

Before belief: import a game's exact wall/roof/temperature/glower/position snapshot. Compare sampled density, glow-grid/overlight growth eligibility, actual attack-target feasibility and lens/listener density with game queries before/after the scheduled rebuild. Geometry categories and blocked/unblocked decisions must agree exactly; numeric fields agree to recorded engine precision. Any ray/overlight mismatch invalidates that region of the model. Validate cold/warm probes, mobile overlap, lamp removal, halo death and a save/reload as distinct transition classes. Never accept a matching debug drawing as proof of a matching targeting consumer.

Produces: density/light/temperature maps, line-path cases, coverage of footprint/bearing regions, per-bar worst geometry and shortest order-dependent failure; capture-site list for live presentation. Size [guess]: a compact local-grid sweep around existing density/light kernels plus calibration adapters, several engineer days; unknown optical hooks may be the costly part. Trigger: immediately after M1 identifies input shapes; dark-field and light-grid meetings are unknown, and current source lacks the halo/path/presentation contracts. Output changes the density composition/occlusion rules before art or tuning, or exposes an infeasible thermometer integration for review.

## M4: Wind, weather, feeding and cue timing walk

Question: does a natural mostly-Dark regime contain real stillness and pulses that feed native life and cue the player, with a brief recurrent clearing instead of permanent daylight or a starved food chain?

Informs: B1, B3, B5, B7, B8; R1, R5, R7, R9; unknown weather-gust meeting. Assumptions: wind and weather histories can be replayed as recorded engine inputs; gust detector and sound schedulers are production kernels; nutrition loss is taken from the game's resolved animal data, not guessed real-world metabolism.

Inputs/range: replay natural weather/wind records spanning a season on cold, thermal-transition and warm-margin Abyss maps, normal Dark, Witchfire, entry/exit of Unveiling, startup/reload mid-gust, pause and speed changes, viewed/unviewed maps. Sweep actual weather duration/commonality curves, wind-speed extremes and hysteresis boundaries, food-need rates, feeder numbers from isolated gharrek to expected full-map populations and dense pen stress. Include day 1 and day 100 existing state. Forced gusts are only controls to establish a kernel response, never evidence of natural recurrence. Primary-attack warning traces also sample hunt start far away, close engagement, interrupted/replaced jobs and reload, to catch a rattle used up offscreen.

Leaves out: audio timbre/recognizability, engine sky rendering, economy and vegetation spatial spread (those go to M2). No new Summ call, egg storm or probe timing: off means absent.

Before belief: exact timestamp/state agreement for detected gust edges, saved gust count, per-animal last-fed edge, actual nutrition updates, sound-event requests and warning-before-damage order against recorded game traces. Natural wind stays on its measured scale; missing input histories mean uncalibrated, not an invented weather generator. Compare simulated native food balance to the game's food-need deltas over entire still/gust cycles with maximum error no larger than one scheduled update's legitimate rounding. Validate weather dwell distributions against a separate natural game record; agreement must include clear/never-clear and long-still tails, not just mean dwell. Any regime lacking data remains unknown. Listener quality is still live-only.

Produces: weather/wind/feed/cue timelines, starvation-risk regions, distribution of Dark versus clear stretches, boundary cases that silence or duplicate a cue. Size [guess]: a small replay/timing harness over existing state kernels, about a few engineer days plus natural history capture. Trigger: immediate weather-gust unknown, or a feeding/cue first live failure, or changing a weather/feeding constant twice to satisfy a check. Output changes wind integration and pulse/food tuning, never declares equal beauty/terror quotas.

## M2: Whole-map season, light-food-material feedback

Question: with everything kept on, does a colony retain workable refuge and ordinary native life while grain/light loss create recoverable pressure rather than fuel flood, ecological desert, work stall or error storm?

Informs: all bars, especially B8; all rules; unknown food-web, exposed-material and map-time meetings and the three-way Dark/light/predator, grain/fuel/heat and wind/feed/prey loops. Assumptions: calibrated M1/M3/M4 supply local transitions and natural environmental inputs, resolved defs supply needs/yields, and coarse scheduling preserves ordinary growth, temperature, jobs, erosion attempts, feeding, recovery and material conservation. The model does not stand in for the live whole bar's appearance/audio.

Inputs/range: full local maps of every supported normal size/relief class, stratified cold/transition/warm-margin fixed-world inputs; zero/new/forty-colonist colonies; compact and dispersed shelters/farms; low/high roof coverage of the same exposed rock and steel; ordinary imported initial food/fuel versus established refinery/stock; RM-only and full campaign including the existing Taozin nest, tolerances, butcher products, static pursuit, scanner payload and shared engine defaults. Use actual map snapshots, not a regular grid mistaken for a real generated highland. Sweep food/growth/predation and grain attempt/damage/dust constants across current configurable range and candidate retunes. Run at least one full season per combination, a mid-cycle reload and the reversed main-action orders; stress continuation to day 100. Track ordinary weather fires as well as Dark mechanisms; do not lock clear sky or switch off a kept hazard. Stock already beyond all plausible scale is a stress diagnostic, not a required effortless-colony guarantee.

Leaves out: detailed pawn strategy, subjective fun, exact live frame rate, raids unrelated to the maintained pursuit dependency, deferred extras. No claim that a uniform random cell sampler preserves geography-dependent jobs unless calibrated. Report uncertainties in predator AI/travel/thermal approximations instead of making up an exact labor budget.

Before belief: on matching disposable game maps, compare snapshots at startup, after an entire ordinary Dark/gust/clearing cycle, mid-season, after reload and season end. Check vegetation/animal biomass by ecological role, hunger/death/corpse causes, harvested/consumed/stored food, effective illuminated crop area, roofed/unroofed erosion loss and tholin/fuel stock flows, unfinished-work/backlog and log exceptions. State categories and event causes agree exactly. Numeric trajectory confidence bands must contain the independent game trajectory at these checkpoints and have the same direction of change; widen uncertain bands transparently and refuse conclusions when they span both acceptable and catastrophic outcomes. Set a field-specific error budget from calibration precision and natural stochastic variance before using the model for a scope/tuning decision. A matching endpoint with wrong mid-season starvation is insufficient. Natural played runs, including second action order, calibrate labor assumptions; forced optimal pawns do not.

Produces: maps/time-series for light/vegetation/exposed material; food/fuel/repair flow tables; native survival/turnover and cause-of-loss ledger; worst regime for each bar; recovery versus runaway regions. Explicit decision: retune rates/rules if ordinary roofed work and maintained light farms cannot recover, if erosion removes the land during routine residence, if tholin makes unlimited surplus without cost, or if native food structure collapses. Do not solve those outputs by deleting a necessary bar or adding an unruled ritual/reward. Size [guess]: a medium replay/coarse simulator and input/export adapters, roughly a week of engineering after local calibration; begin with a single observed full-map snapshot and expand by differing failure modes.

Trigger: first full-map build after M1/M3/M4 calibration; unknown food-web/material/map-time meetings already justify it. Also rebuild the affected region when a relevant constant changes twice to move a check, or when the whole bar first fails in play. No model output is described as “measured in game” unless it is the calibration record itself.

No credible offline model decides whether etched relief, spatial Dark, returning visibility, warning text or muffled sound is readable and coherent to a player. B1, B7 and B8 therefore retain a bounded live look/listen component with state controls; live-only is not a label for a missing state instrument. Sound judging retains the existing owner-present requirement without reopening the ship-on decision.
