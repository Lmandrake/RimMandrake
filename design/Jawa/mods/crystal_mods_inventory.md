## 1. The orange glowing crystal — identified

**`KOTOR_SmallCrystal_orange`** (ThingDef, label "small crystal formation, orange"),
currently owned by **`mandrake.rsw.armoury`** ("Jawa Armoury Rebalance" — our own mod)
per the def dump. `CompProperties_Glower` `glowColor (230,155,75,255)` — a warm orange —
`glowRadius 2`; `graphicData.color (0.902, 0.608, 0.294, 1)` on `Buildings/Crystal_Formations/small_dyeable`.

  `WEAPONS_DONOR_RETIREMENT_1`: `D:\Luke\dev\Rimworld\src\RimStarWars\Armoury\Defs\Absorbed_KotorWeapons\ThingDefs_Mineables\Absorbed_KotorWeapons_KotORResource_CrystalFormations_Small.xml`
  (defNames preserved verbatim; generated by `gen_kotorweapons_absorption.py`).

  `ModsConfig.xml` (0 hits) — so the absorbed copy is what the dump resolves to. This

**Where it spawns (mechanism, not guessed):** the record's own `mineableScatterCommonality`
is `0` — it does not scatter on its own. It is placed by
**`BMT_CrystalsGenerator`** (GenStepDef, order 320, `GenStep_ScatterCrystals`,
owned by **Biomes! Caverns**, `biomesteam.biomescaverns`), patched by our own
`D:\Luke\dev\Rimworld\src\RimStarWars\Armoury\Patches\Absorbed_AdditionalMods\kotorweapons\BiomesCaverns\Absorbed_Kotorweapons_BiomesCaverns_Patch_KotORCrystalFormationInjector.xml`

`WEAPONS_DONOR_RETIREMENT_1`) to add all 7 small colors + 3 medium + Stygium + 2 large
into `BMT_CrystalsGenerator`'s scatter groups. Confirmed live in the dump: the resolved
`BMT_CrystalsGenerator` record's groups include `KOTOR_SmallCrystal_orange` at weight
0.15 (outdoor-adjacent group) / 0.05 (interior group). **That genstep's validator
requires the `BMT_Crystal` terrain affordance** — i.e. it only fires on a
Biomes! Caverns crystal-cavern-type map. `BMT_CrystalCaverns` is the exact BiomeDef the
Lantern Deeps sheet cites as its cave-map def (`isCavern true`). **So: the orange
crystal the owner saw was almost certainly in a crystal-cavern map — the same map type
the Lantern Deeps is already built on.**

Yield on mining: `SecondaryMineableYield.ModExtension_SecondaryMineableYield` (not the
vanilla `building.mineableThing` path) — 60% chance of 2× `guy762_crystalitem_orange`,
20% chance of 1×. `guy762_crystalitem_orange` feeds lightsaber crafting as a
`guy762_SWForceLightsabers_CrystalPart_orange` `HiltPartDef` (category `focuscrystal`).

**Caveat, not chased further:** the *standalone* genstep `KOTOR_CrystalFormation`
(order 1100, `guy762.mm.kotorcore`, also absorbed into our Armoury pack as
`Absorbed_KotorCore_CrystalMapGenerator.xml`) resolves in the live dump to a **single**
scatter group containing only `KOTOR_StygiumCrystal` — the repo's copy of that same
file still lists all 7 colors + 3 medium + Stygium. Something between our repo file and
the deployed/live game state trimmed it (a newer kotorcore version, a load-order
override, or a deploy drift — CLAUDE.md's standing warning that "the repo copy is
never what the game loads" applies here). **Does not change the orange-crystal finding
above** (that identification rests on `BMT_CrystalsGenerator`, which resolved cleanly
and matches the repo source), but flag it: `KOTOR_CrystalFormation`'s current live
scatter is Stygium-only, not the multicolor list the repo file shows.

from one of our mod imports — housed here too... examines ingesting that mod so every
crystal harvest lives in one place."* Given what's actually in the stack:

| system | recommendation | effort | why |

**Bottom line for the owner's ruling:** two real crystal-resource systems already sit in
the stack pointed at the Deeps — KOTOR-family formations (orange included, already
absorbed) and the lightsaber mod's kyber (not yet absorbed) — plus the native
Biomes! Caverns blue crystal that already IS lanternstone. The unify-into-one-system
work is mostly **retargeting genstep gates to Lantern Deeps maps**, not building new
mechanism. GRiNDTerra's and Alpha Biomes' "crystal" defs are false leads (decorative
grass and an unrelated plant family respectively) and don't belong in the unification.
