## Landing tools
- ./publish (Utils/publish.py, 223 lines): `git add --all -- <paths>`; `git commit -- <paths>` (pathspec); fetch; replay every not-yet-upstream local commit via `git merge-tree --write-tree` + `commit-tree`; `git reset --keep <tip>`; push HEAD:main; <=8 tries on non-ff (sleep 0.5*n); ambiguous push failure -> fetch + is-ancestor check. Never stashes, never force. ON CONFLICT: raises Refuse naming the conflicted paths, commit stays intact on HEAD, exit 2 (stderr "REFUSED: ..."), no auto-resolution. Also refuses if `reset --keep` would overwrite a dirty file origin changed (that is the untracked/dirty-collision class: untracked files that origin newly adds make reset --keep fail). Refuses merge commits among local commits. Does NOT retry index.lock (git add/commit fails -> Refuse, nothing committed).
- land.sh (87 lines): ONE sha or explicit paths via temp GIT_INDEX_FILE seeded from origin/main; never reads shared index/worktree; up to 5 push retries with sleep; then seat_sync.py --no-fetch. This is the lock-free path (does not touch .git/index, so no index.lock contention) -- except when it runs `reset --keep` in seat_sync.
- ./sync (seat_sync.py): reset --keep origin/main only if lossless, else REFUSED with reason.
- Pre-push hook infrastructure/githooks/pre-push + Claude hook block_ledger_lint.py judge LOCAL HEAD (so plumbing push from a behind clone => NOT_APPEND refusal; run ./sync first). Push in a separate Bash call from a rebase.

## Design constraints for an N-lane design
1. Never worktrees (hook-blocked, owner card). Never stash/autostash/reset --hard/checkout --/ git merge in a shared tree/ push --force.
2. One writer per index: parallel lanes must not share .git/index. Either separate clone per lane (scratch_clone.py, ~0 s, ~0 own bytes with alternates, but checkout cost ~7-14 GB unless sparse/--filter) or write-by-plumbing (land.sh -m with a temp index) so no lane touches the shared index.
3. Lane file sets must be disjoint (or serialized); the repo's tracked state is shard-per-writer (ledger events/<SEAT>.jsonl merge=union; code_review/<SEAT>.jsonl). New lanes need own shards or a lane-id suffix; lint refuses edited/reordered lines; ledger writes must be appended in a clone that is not behind origin.
4. Landing must be: explicit paths, replay onto fresh origin/main by merge-tree, ff-only push with retry, proof by `merge-base --is-ancestor`, and report PUBLISHED sha. Conflict = report to window, never clear.
5. Untracked/dirty files that another lane lands (Transient/ outputs, review-sheet img) break reset --keep: either lane clones are clean (scratch clones) or lanes' generated outputs are .gitignored / not committed from two clones; Transient is tracked+pushed ~14d, which caused today's block.
6. Pre-push hook ledger lint judges local HEAD => each lane clone must be synced (fresh from origin) before landing a ledger line.
7. Disk/RAM: seat cgroup 10 GB; scratch clones in ~/.cache or /home/mandrake/rm/scratch, never /tmp; --filter=blob:none or sparse; delete only after 0 unpushed + 0 untracked; set core.hooksPath per clone; need an expiry reaper (not built).
8. Subagent constraints: pass `model`; brief verbatim "never background any command; never end your turn to wait"; write output skeleton first (600 s watchdog); at most one live-game lane; heavy ML not in the seat cgroup.
9. Helpers must not run git status/log concurrently with the window's ./publish in the same clone (index.lock) -- i.e. read-only git in helpers takes locks; use `git --no-optional-locks` (not documented in repo; suggestion) or give helpers no git at all.
10. Never delete a lock younger than a minute; crash leaves stale locks and empty objects: `git fsck --no-dangling` on wake.
11. Handoff gate: a handoff requires everything pushed; lane results must reach origin before the lane ends.
