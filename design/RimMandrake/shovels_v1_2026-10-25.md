## 1. The thing: `RM_Shovel` (FlowWorks, `Defs/Pits/ThingDefs/RM_Shovel.xml`)

- A stuffable **tool item, not a weapon** (self-review R1): `category` Item, `thingCategories` a new `RM_Tools` under
  Manufactured, no `equipmentType`, no `weaponTags`, so no pawnkind ever generates wielding it, Simple Sidearms and
  ideoligion weapon precepts ignore it, and a violence-incapable colonist can still dig. Mass ~2 kg, `techLevel`
  Neolithic, stuff `Metallic` + `Woody`, cost ~40 stuff, work ~1,600, **no research**, recipe at the crafting spot and
  both smithies (`recipeMaker.recipeUsers`; bench defNames read from the def dump in phase 2, never typed from memory).
  A swingable-spade weapon variant is a v2 option, not v1.
- A marker `RM_DiggingTool : DefModExtension` (empty in v1) on the def. The rule asks "does the pawn hold a thing with
  `RM_DiggingTool`", never "is it RM_Shovel", so another mod (or a v2 pick/mattock) opts in by patch.
- Trader stock: not in v1 (raiders drop them; the crafting spot makes them). Starting scenarios: unchanged (open Q3).
- Art: `Textures/Things/Item/Equipment/RM_Shovel.png` is owed. Filed as an art item (SHOVEL_SPRITE_SKETCH_BLADE_DOWN_HANDLE_UP);
  no generation in this item. Until it lands the def points at a vanilla item texture whose path is verified on disk
  in phase 2 (reading-rimworld-graphics), with a `<!-- PLACEHOLDER art -->` comment so the art audit finds it.

## 2. Who needs one: `RM_ShovelRule` (pure) + `RM_Shovels` (Verse)

Pure, selftested (`RM_ShovelMath.NeedsShovel(settingOn, isMachineLabour, raceDigsBareHanded)`):
- Setting **"Digging needs a shovel"** off -> nobody needs one (shipped behaviour before this item).
- Machine labour (`RM_DigLabor.IsMachineLabour`) -> no shovel: *"And droids. And machines."*
- A race / flesh type carrying a new `RM_DigsBareHanded : DefModExtension` -> no shovel. FlowWorks names no franchise
  def; this is the hook v2 utility creatures (digger animals) and burrowing xenotypes patch onto, guarded by
  PatchOperationFindMod. v1 ships no patch using it.
- Everyone else (colonists, slaves, prisoners on work, raiders, visitors) needs one.

Verse (`RM_Shovels`):
- `HasShovel(pawn)`: any thing in `pawn.inventory.innerContainer` has `RM_DiggingTool` (inventory is its only home: a colonist keeps a rifle equipped and the shovel in the pack, and carrying fill
  (`carryTracker`) does not collide with it).
- `FindShovelFor(pawn, maxDist)`: closest spawned thing with `RM_DiggingTool` that is reachable, not forbidden to the pawn
  (for colonists), `CanReserve`, not burning — via `listerThings` over the (cached) list of defs carrying the extension.

## 3. Colonists: WorkGivers and JobDrivers

`WorkGiver_DigCanal.HasJobOnCell` / `WorkGiver_FillInCanal.HasJobOnCell`, after the stale-designation tests (a missing
shovel never deletes a designation — it is temporary, like a pawn standing in the square):
- needs a shovel and has one -> as today;
- needs one, has none: `HasJobOnCell` stays CHEAP (self-review R2): true only if `RM_Shovels.AnyFreeShovel(map)`
  (a per-map, per-tick memo over `listerThings` counts, no path search); else `JobFailReason.Is("Needs a shovel
  (none free on the map).")`, false. `ShouldSkip` returns true outright when the pawn needs one, holds none and the
  map has none, so a shovel-less colony pays nothing per designated square.
- `JobOnCell` does the one reachability search (`FindShovelFor`) and returns the job **with `targetC` = that shovel**,
  or null (the scanner moves on) when none is reachable/reservable.
JobDrivers (`JobDriver_DigCanal`, `JobDriver_FillInCanal`): when `job.targetC` is valid, prepend
`Goto(C, ClosestTouch)` + take-one-into-inventory (the vanilla take-to-inventory toil, verified in phase 2), reserve C
in `TryMakePreToilReservations`; the fill driver's own carry toils (B = material) follow unchanged. Every work toil
gets `FailOn(() => RM_Shovels.Needs(pawn) && !RM_Shovels.HasShovel(pawn))` (a shovel dropped mid-job ends the cut,
nothing paid twice: the cut/fill effect fires only at the end of the work toil, as today).

Keeping it: an inventory shovel must survive vanilla's inventory clean-up. Engine names confirmed present in the
1.6 assembly (strings): `JobGiver_DropUnusedInventory`, `JobGiver_UnloadYourInventory`, `TakeCountToInventory`. Whether
DropUnusedInventory would drop a non-drug, non-food tool item is **an engine question this seat cannot decompile** (no
RimSage here); phase 2 settles it by the live row SH_shovel_stays_in_inventory, and if it drops, a Harmony prefix
exempts `RM_DiggingTool` things. Not reasoned from a doc.

Alert: `Alert_RM_DigNeedsShovel` — dig or fill designations exist, no free colonist holds a shovel and none lies on
the map: "Dig orders are waiting for a shovel. Make one at a crafting spot." Folded into the existing dig alert file
pattern (`RM_DeepDigAlert.cs`).

Other dig paths: "Repair breach" and dig-to orders go through the same designation/WorkGiver, so they inherit the rule.
God-mode / dev instant digs are untouched. Pyrelands sand shovelling and drift shovelling are NOT gated in v1 (open Q2).

## 4. Raiders: shovels in the raid, shovels to fill, and time

a) **Raids bring shovels.** New postfix beside the jump-pack one on `IncidentWorker_Raid.PostProcessSpawnedPawns`
   (`RM_Patch_Raid_Shovels`, `PatchFeature` on `raiderShovelsEnabled`): on a map with a dug trench
   (`ClimbCellCount >= MinClimbCellsForJumpPacks`, same gate), for a faction of tech Neolithic or better, a
   deterministic share of humanlike tool-users (`RM_ShovelMath.GetsShovel(thingID, share)`, the jump-pack hash idea)
   get one shovel **in inventory**. Stuff: wood below Industrial, steel from Industrial (defNames verified in phase 2).
   Settings: "Raiders who bring a shovel" (assault, default **25%**, PROVISIONAL) and "Sieges who bring a shovel"
   (default **50%**, PROVISIONAL). Dead raiders' shovels are loot: the colony's first shovels may come from a raid.
b) **Only shovel-holders fill.** In `RM_RaiderTrench.FillJob`, before `FetchJob`: if `NeedsShovel` and not
   `HasShovel`, try `FindShovelFor(p, FetchRadius)` (a raider will grab ANY loose shovel in reach, the colony's
   included — forbidden-ness binds only the colony) -> `TakeCountToInventory` job; else null (no fill job: the raid
   jumps/ladders/waits exactly as with no fill material). Ladders and jumps need no shovel. Fetching fill material and
   tipping it are both behind the gate (one check at `FillJob` entry). `RM_RaiderTrenchMath.Choose` is unchanged: it
   already reads `fill != null`.
c) **Sieges dig (the "siege option").** Reading of *"raiders can't just quickly dig some new pits, then use those
   materials to fill your pit ... They would need shovels, and a lot of time. Good siege option though. Should
   happen."*: a siege has the time; an assault does not. Two parts, each its own setting, sequenced AFTER a+b so the
   gate ships even if this slips:
   - **Borrow pits**: while a `LordJob_Siege` is in its camp toil (`LordToil_Siege`), shovel-holding siege pawns
     with no build job dig one notch at a time in borrow squares within the siege camp radius, on ground that yields
     spoil (rock ground, rubble, ice: `RM_DigSpoil`; dirt yields nothing, so a siege on pure soil only scavenges),
     never inside the colony's home area, never adjacent to the colony's trench. Reuses the colonist cut
     (`RM_DigCanalJob` work and spoil) with a raider-only JobGiver added to the siege camp duty by patch; the spoil
     is ordinary gravel/chunks the existing `FetchJob` already finds. Cap: N borrow squares per siege (default 6).
   - **Siege breach**: once the siege lord moves to its assault toil (`LordToil_AssaultColony` inside
     `LordJob_Siege`), `TryCross` no longer returns null for it: `IsSiege` becomes "siege still camped". Built per the
     2026-10-25 card but shipped default OFF until Q1 is answered; on a yes it SUPERSEDES the Q7 text "Sieges never" (settings tooltips, the class comment,
     `ProofDecision` "siege" row) — owner to confirm (Q1); on a yes both default ON, on a no the borrow pits are cut.
