## 1. Engine primer: how an incident or quest reaches the player (VERIFIED, RimSage 2026-10-10)

Every mod below is a variation on one pipeline. Knowing it is most of the wisdom, because each mod's
bugs are places where it stepped outside it.

```
StorytellerDef.comps (Randy: ~30 comps)            <- WHEN: each comp's MakeIntervalIncidents / Notify_PawnEvent
   └─ FiringIncident(def, parms)                   <- WHAT + parms.points
        └─ Storyteller.TryFire(fi)                 <- CanFireNow(parms) && TryExecute(parms)
             ├─ IncidentWorker.CanFireNow          <- the generic gates (below), then CanFireNowSub (yours)
             └─ IncidentWorker.TryExecute          <- TryExecuteWorker (yours); then TryFire stamps StoryState on true
IncidentQueue.Add(def, fireTick, parms, retry)     <- the delayed path: re-tries TryFire every ~833 ticks
IncidentWorker_GiveQuest                           <- an IncidentDef whose job is to generate a QuestScriptDef
```

**`IncidentWorker.CanFireNow` (RimWorld/IncidentWorker.cs 35-154).** When `parms.forced` is false it
checks, in order: `def.TargetAllowed` (targetTags), `earliestDay` (days since settle), the difficulty's
`disabledWhen` and `allowBigThreats`, `minThreatPoints`/`maxThreatPoints`, `allowedBiomes`/
`disallowedBiomes` (by the target tile's primary biome), `layerWhitelist`/`layerBlacklist` and
`PlanetLayerDef.onlyAllowWhitelistedIncidents`, `ScenPart_DisableIncident`, `minPopulation` (free
colonists everywhere), `FiredTooRecently`, `minGreatestPopulation`, Anomaly threat tier, any active
`GameCondition` with `preventIncidents`, game ending, and a 5-day ThreatBig grace after new wanderers.
Only then does it call **your `CanFireNowSub`**, cached per tick **per def, not per target** (`lastCheckCanRunTick`; the worker is a per-def singleton, so a second target asked in the same tick gets the first target's answer), and forced false during Anomaly's void awakening. **`forced = true` skips every one of
those gates but still runs `CanFireNowSub`** — so a dev "fire incident" or a scripted `forced` call
bypasses cooldowns and biome bans, and a Harmony patch on a generic gate (Faction Raid Cooldown) is
invisible to forced calls. Our Aftermath already relies on this (`AftermathRuleRunner.cs` sets
`forced = true`).

**`FiredTooRecently`** reads `target.StoryState.lastFireTicks[def]` against `minRefireDays`, and also
every def in `RefireCheckIncidents` (built from the `refireCheckTags`/`tags` lists on `IncidentDef`).
⇒ Shared cooldowns between OUR incidents are pure XML: give them a common tag and `refireCheckTags`.
Note the cooldown is **per target** (per map's StoryState), not global.

**`TryExecute`** (183-231): if `def.requireColonistsPresent` and the map has no spawned free colonist it
**returns true without doing anything** — and because it returned true, `TryFire` stamps the cooldown: the
incident is consumed silently. For a crew that is often off-ship, refuse in `CanFireNowSub` instead (so the
storyteller picks something else). On success `TryExecute` records tales. `Find.Storyteller.RecordIncidentFired(def)`
runs whatever the worker returned, but it only feeds Anomaly's recent-incident ratio (VERIFIED,
Storyteller.cs 335-350). **The cooldown and the ThreatBig clock are stamped by `StoryState.Notify_IncidentFired`**
(VERIFIED, StoryState.cs 88-116: `lastFireTicks[def]`, `lastThreatBigTick`, `numThreatBigs`, random-quest and
random-incident recency), which `Storyteller.TryFire` calls only when `CanFireNow` and `TryExecute` both return
true, and **which returns immediately for a `forced` fire**. Consequences:
- a worker that returns `true` before its outcome exists gets the cooldown, the ThreatBig clock reset (delaying
  the next big threat) and the recency damping, with nothing on the map — the root of the Raid Protection Fee bug;
- a `forced` fire neither respects nor *sets* cooldowns or the ThreatBig clock, so the storyteller does not space
  around it (our Aftermath's forced follow-ups are invisible to Randy in both directions);
- calling `def.Worker.TryExecute(parms)` directly (not via `TryFire` or the queue) skips `CanFireNow` **and** the
  stamp. Our schedulers go through `Find.Storyteller.TryFire(new FiringIncident(def, null, parms))` or the queue.

**`bypassStorytellerSettings`** (VERIFIED in `CanFireNow`): skips only `earliestDay`, the difficulty
`disabledWhen`/`allowBigThreats` check and `ScenPart_DisableIncident`; cooldown, biome, layer, population, points
and `preventIncidents` still apply. It is the right flag for a scripted beat that should ignore difficulty and
scenario bans but keep biome rules and spacing — usually better than `forced`.

**Selection weight (`StorytellerComp.IncidentChanceFinal`, StorytellerComp.cs 115-132):**
`BaseChanceThisGame` (baseChance, or baseChanceWithRoyalty) × `chanceFactorByPopulationCurve` ×
**population intent** × `Worker.ChanceFactorNow(target)` × recent-repeat damping
(`QuestTuning.RecentStoryWeightFactors`). Population intent: `populationEffect` IncreaseHard +0.4,
IncreaseMedium 0, IncreaseEasy −0.4 added to `StorytellerUtilityPopulation.PopulationIntent`, floored at
the comp's `minIncChancePopulationIntentFactor` (Randy's `RandomMain` sets 0.2; the base default is 0.05, so a comp we add without setting it floors lower). Randy's
`populationIntentFactorFromPopCurve` is `(0,8) (1,2) (4,1) (7,0.35) (11,0) (20,-1)`: **with our crew of
6-7, vanilla already throttles joiners hard, but never to zero** (the 0.2 floor). A joiner incident we
write must set `populationEffect`, or it escapes this throttle entirely.

**Quests (`NaturalRandomQuestChooser`, VERIFIED):** first a coin flip with
`QuestTuning.IncreasesPopQuestChanceByPopIntentCurve` on `PopulationIntentForQuest` picks a
population-increasing or a non-increasing pool; within the pool, weight = `rootSelectionWeight`
(0 if points < `rootMinPoints`, days < `rootEarliestDay`, progress < `rootMinProgressScore`, or any quest
of this root appeared within `minRefireDays`) × `rootSelectionWeightFactorFromPointsCurve` × recency
damping. ⇒ **A quest that can hand the player a colonist must set `rootIncreasesPopulation`**, or it
bypasses the population gate the same way an incident without `populationEffect` does. `QuestScriptDef`
config errors if `rootSelectionWeight > 0` with no `expireDaysRange` and no `autoAccept`.
`IncidentWorker_GiveQuest.CanFireNowSub` additionally refuses on a planet layer whose
`onlyAllowWhitelistedQuests` is set and in space unless `everAcceptableInSpace` — relevant to our
`RM_SeabedLayer` (whether that layer sets either flag: UNVERIFIED here).

**Threat points (`StorytellerUtility.DefaultThreatPointsNow`):** wealth curve + per-colonist points
(free colonists by wealth; slaves ×0.75; trainable animals 0.08×combatPower; colony mechs; **quest
lodgers excluded**), × random factor × adaptation × difficulty `threatScale` × the storyteller's
`pointsFactorFromDaysPassed`, clamped to 10,000. ⇒ A scarcity game with a small crew and low wealth gets
small raids automatically; to make danger *qualitative* we change *what* arrives, not the points.

**Randy as shipped** (`StorytellerDef Randy`, merged def, VERIFIED): `StorytellerCompProperties_RandomMain`
`mtbDays 1.35`, `maxThreatBigIntervalDays 13`, `randomPointsFactorRange 0.5~1.5`, category weights
Misc 3.5 / FactionArrival 2.4 / ThreatBig 1.4 / OrbitalVisitor 1.1 / ThreatSmall 0.6 / ShipChunkDrop 0.22;
two `StorytellerCompProperties_RandomQuest` (GiveQuest, `onDays` 10 or 12, Royalty switch);
`StorytellerCompProperties_FactionInteraction` for `RaidFriendly` (10/yr) and Royalty's
`CaravanArrivalTributeCollector`; `StorytellerCompProperties_Triggered` for `StrangerInBlackJoin` (fires
off `Notify_PawnEvent`); `StorytellerCompProperties_CategoryMTB` Misc on the World every 15 days; plus the
DLC on/off cycles. ⇒ **We can add a storyteller comp to Randy by patching `StorytellerDef[defName="Randy"]/comps`**
without writing a storyteller — that is how a custom pacing rule coexists with the ruled "vanilla Randy". Comps are rebuilt from the def on load, so such a patch reaches existing saves; and an `OnOffCycle` comp's cycle phase is seeded by its index in the comp list, so **append, never insert**, or every later cycle in Randy shifts phase mid-campaign (VERIFIED, review 2026-10-10).

**Choices: modal dialog vs letter** (VERIFIED, review 2026-10-10). `Dialog_NodeTree` sets `forcePause`,
`absorbInputAroundWindow`, `closeOnAccept = false`, `closeOnCancel = false`, but **not `preventSave`**; saving is
blocked only by `TilePicker.Active` or a window with `preventSave`. So play is paused while it is up (the tick
autosaver cannot fire), but a save can still be taken by other routes, capturing whatever a closure holds. A
`ChoiceLetter` (`: LetterWithTimeout : Letter`) is the save-safe vessel: `LetterStack` Scribes its letters,
`ChoiceLetter.OpenLetter` rebuilds the `DiaNode` from the abstract `Choices` property each time it opens, so a
subclass that Scribes its own fields survives save/load with no component; `StartTimeout(ticks)` sets
`disappearAtTick`; the last-tick auto-open is skipped while another force-pause window is open, and on timeout
the letter is removed through `Letter.Removed()` — apply the default branch there, never rely on the auto-open.
Vanilla precedents: `ChoiceLetter_RansomDemand`, `ChoiceLetter_AcceptVisitors`, `ChoiceLetter_BetrayVisitors`.

**World pawns** (VERIFIED). `PassToWorld(p, PawnDiscardDecideMode.KeepForever)` adds the pawn to the same
set `Find.WorldPawns.ForcefullyKeptPawns` exposes; vanilla Scribes it, so pins survive save/load. But
`WorldPawns.RemovePawn` — called when a world pawn is pulled out to spawn — **removes the pin**, and a pawn
leaving a map goes back through `Pawn.ExitMap` → `PassToWorld(this)` in `Decide` mode: re-pin on every exit.
`PassToWorld` on a pawn already in world pawns logs an error and does nothing (use `ForcefullyKeptPawns.Add`).
World pawns are ticked, auto-tended and mothballed, so an off-map pawn heals; "scarred" must read a permanent
injury or our own record.

**Quest rewards are a third joiner path** (VERIFIED, review): reward generation weights pawn rewards by
`QuestTuning.PopIncreasingRewardWeightByPopIntentCurve` on `PopulationIntentForQuest`, so any vanilla quest
can offer a person even when its root does not set `rootIncreasesPopulation`. A hard crew cap needs its own
gate on that path (best target UNVERIFIED).

**The qualitative levers on `IncidentParms`** (field list VERIFIED, `RimWorld/IncidentParms.cs`):
`raidStrategy`, `raidArrivalMode`, `attackTargets` (a list of Things the raiders go for),
`canTimeoutOrFlee`, `canSteal`, `canKidnap`, `raidForceOneDowned`, `raidNeverFleeIndividual`,
`pawnKind`, `pawnCount`, `pawnGroupMakerSeed`, `customLetterLabel`/`customLetterText`/`customLetterDef`,
`sendLetter`, `silent`, `inSignalEnd`/`questTag` (quest linkage), `storeGeneratedNeutralPawns`. These change
*what* a raid is without touching `points`.

**IncidentQueue** (VERIFIED): `Add(def, fireTick, parms, retryDurationTicks)`; at fireTick it calls
`TryFire(..., queued:true)`; with a retry window it keeps re-trying about every 833 ticks; it is
Scribed (`queuedIncidents`, `LookMode.Deep`) and purges a removed map's entries. **With no retry window, an entry that fails at its tick is removed silently** — no log; a beat that must happen gets a retry window and our own log line. (Whether every `IncidentParms` field, e.g. `attackTargets`, survives the Deep scribe in the queue: UNVERIFIED — check `IncidentParms.ExposeData` before relying on it.) ⇒ "Something comes in
3-5 days" is one `Find.Storyteller.incidentQueue.Add` call, save-safe, no component of our own.

### 2.1 Raid Protection Fee (`leo.raidprotectionfee`)

Engine checks: `IncidentWorker.TryExecute` VERIFIED (RimSage): `bool flag = TryExecuteWorker(parms); ... Find.Storyteller.RecordIncidentFired(def); return flag;` So the wrapper reports whatever TryExecuteWorker returned, records the fire, and records a tale for the category on success. `IncidentWorker_RaidEnemy.TryExecuteWorker` VERIFIED to be declared on that class (calls `base.TryExecuteWorker` = `IncidentWorker_Raid.TryExecuteWorker`, which generates pawns, sends the letter, makes lords). So the prefix target is the real method for enemy raids only (not friendly-raid, not other attack incidents).
- **Player-facing situation**: when a hostile human faction's raid would fire, the raid does not appear. Instead a dialog (Dialog_NodeTree) pops: "{faction} has contacted you... protection guarantee... cost ${N}. Pay the fee by 'Selling' items in the trade window." Options: Accept (opens a trade window where YOU sell goods to their leader to cover N), Reject (raid proceeds, with a points bonus), and "View related quest" if the raid belongs to a visible quest. Pay and the faction "cuts the signal"; there is a small double-cross chance that the raid happens anyway.
- **Mechanism** (`src/rpf/Leo.RaidProtectionFee/`):
  - `Patch_IncidentWorker_RaidEnemy_TryExecuteWorker.cs`: `[HarmonyPatch(typeof(IncidentWorker_RaidEnemy), "TryExecuteWorker")]` PREFIX that forwards to `ProtectionFee_Raid.Prefix(worker, parms, ref __result)`. Optional second target `Patch_RimWar_WarObjectRaid_TryExecuteWorker.cs` (only if `RimWar.Utility.IncidentWorker_WarObjectRaid` exists, `Prepare()`/`TargetMethod()` pattern).
  - `ProtectionFee_Raid.Prefix` order: (1) `WorldComponent_ProtectionFee.IsProcessingRansom` true -> return true (re-entrancy guard, let vanilla run); (2) `ProtectionFee_ModSettings.IsProtectionFeeEnabled` (per quest script def / quest root chain / incident def toggle; RimWar tag forced; quest sources default FALSE, plain incidents default TRUE); (3) if `parms.faction == null`, resolve points via reflection `ResolveRaidPoints` and faction via reflection `TryResolveRaidFaction` (so the offer can name a faction before the vanilla body runs); (4) faction on extortion cooldown -> pass through; (5) faction must be `HostileTo(Faction.OfPlayer)` and `def.humanlikeFaction`; (6) roll `Rand.Value > factionExtortionChances[defName]` (default 1.0) -> pass; (7) target must be a `Map`; (8) compute fee; (9) build dialog; `__result = true; return false;`.
  - Fee: `t = clamp01(points/10000)^2; pct = min + (max-min)*t` from `factionExtortionRanges[defName]` (default 1%-20%); `fee = max(100, (int)(map.wealthWatcher.WealthItems * pct / 100f) * 100)`. Note the `/100f * 100` rounding, so fee is in units of 100 silver and floors at 100.
  - Accept -> `StartRansomTrade`: picks the best negotiator (free colonist spawned, not dead/downed/mental, `TradePriceImprovement` not disabled, can Talk, highest TradePriceImprovement); none -> 60000-tick cooldown, message, `ResumeRaid` (raid goes ahead, no penalty). Otherwise constructs `ITrader_Ransom` (a fake `ITrader` for the faction leader, ~15 KB, with a "sell colony things to pay" list) and opens `Dialog_Ransom : Dialog_Trade` whose `Close()` invokes a callback.
  - Payment detection: `Patch_TradeDeal_TryExecute` Postfix sets `RansomPaidSuccessfully = true` if `TradeSession.trader is ITrader_Ransom`. Supporting patches: DynamicTradeInterface PreOpen/Close, `Find.HiddenItemsManager`/`IdeoManager` getters, `TradeDeal.UpdateCurrencyCount`, `TradeUtility.AllSellableColonyPawns`, `Tradeable.TraderWillTrade` (trade-window plumbing for a trader with no map presence).
  - Close callback: paid -> (if `doubleCross` setting and `Rand < factionDoubleCrossChances[def]` default 0.05) message + `ResumeRaid`; else success message and, for quest raids, sends `parms.inSignalEnd` and `<questTag>.AllEnemiesDefeated` so the quest completes as if the raid were beaten. Not paid -> 60000-tick cooldown, fail message, `ResumeRaid(applyRejectedPenalty:false)`.
  - Reject -> cooldown, message, `ResumeRaid(..., applyRejectedPenalty:true)` multiplying `parms.points` by `1 + Rand(range)` from `factionRejectedFeeRaidPointsIncreaseRanges` (e.g. Pirate 5-9%, Empire 60-100%).
  - `ResumeRaid`: sets `IsProcessingRansom = true`, calls `worker.TryExecute(parms)` (the public wrapper, so the prefix runs again but exits at guard 1), resets in `finally`.
  - `WorldComponent_ProtectionFee`: `factionCooldowns` Dictionary<int loadID,int tick>, `OnCooldown`/`SetCooldown`, plus static ransom state (`RansomPaidSuccessfully`, `RansomRequiredValue`, `OnRansomFinalize`).
- **WHY fire_incident REPORTS SUCCESS WITH 0 PAWNS** (the load-bearing question):
  - The Prefix sets `__result = true` and returns `false`, which makes Harmony SKIP the original `TryExecuteWorker` entirely. The original is what spawns pawns, sends the letter and makes lords. The prefix only adds a Dialog_NodeTree to `Find.WindowStack`.
  - `IncidentWorker.TryExecute` (VERIFIED) simply returns that `true`, and `Storyteller.TryFire` then stamps the cooldown through `StoryState.Notify_IncidentFired` (`RecordIncidentFired` itself is Anomaly-only), so every observer (storyteller cooldown records, debug fire, a bridge `fire_incident`) sees "fired OK, true". Nothing in the pipeline distinguishes "deferred" from "executed".
  - The real raid is deferred to a UI callback: the pawns are spawned only when the player clicks Reject, or finishes/ cancels the trade window (`Dialog_Ransom.Close` -> `OnRansomFinalize` -> `ResumeRaid`). Until a human clicks, zero pawns exist. An unattended or automated test sees success, 0 pawns, and a stuck modal dialog.
  - The dialog is `new Dialog_NodeTree(node, true, true, null)` (a modal window that force-pauses play but does not prevent saving; VERIFIED in the 2026-10-10 review); stacked incidents (a second raid next tick) can queue further dialogs, and a stale dialog survives; the 60000-tick cooldown is set only AFTER a decision, so two raids fired before the first is answered will both offer fees.
  - Pass-through cases that DO spawn immediately: non-hostile/non-humanlike faction, failed extortion roll (chance defaults vary: Pirate 0.85, OutlanderRough 0.9, TribeCivil 0.05, so civil factions mostly pass), faction on cooldown, mod disabled for that quest/incident, target not a Map (caravan/site raids), recursion guard. So whether `fire_incident` yields pawns depends on RNG per faction plus the settings table.
  - Quest raids: `questSourceEnabledStatus` defaults false for quest script defs, so quest raids pass through unless the user enabled them. If enabled and paid, the quest receives `AllEnemiesDefeated` without any enemy ever spawning.
  - To make a test deterministic: set `factionExtortionChances` to 0 for that faction, or set `IsProcessingRansom` true, or answer the dialog.
- **Data knobs** (`ProtectionFee_ModSettings.cs`): `extortionCooldown` true; `doubleCross` false; `enableRimWar_WarObjectRaid` true; per-faction maps: `factionExtortionChances`, `factionExtortionRanges` (default 1-20%, Pirate 15-30%, Empire 25-45%, OutlanderRough 12-25%, Beggars 1-5%), `factionDoubleCrossChances` (Empire 1%, OutlanderRough 5%, TribeRough 10%, AncientsHostile 15%), `factionRejectedFeeRaidPointsIncreaseRanges`, `incidentSourceEnabledStatus`, `questSourceEnabledStatus`, `factionPolicyAssignments` (a demand-policy database; `DemandPolicy*.cs`, `Dialog_ManageDemandPolicies`). Cooldown constant 60000 ticks (1 day).
- **Conditions checked**: see Prefix order above; fee base is `WealthItems` (items only, not buildings/pawns).
- **Fun vs annoying**: fun: a social alternative that turns wealth into safety, with a real downside (double-cross, bigger raid on refusal) and the diplomatic flavour of a shakedown. Annoying: a modal pop-up that interrupts every raid; play is force-paused while it is up; the "sell to pay" trade UI is clumsy; payment can drain trade goods for a raid you might have beaten for loot.
- **Failure modes**: (a) incident reports success with nothing spawned (above); (b) static `OnRansomFinalize`/`RansomPaidSuccessfully` are process-global and not saved: save/quit while the dialog is open loses the raid entirely (incident was "fired" and recorded, no raid will ever resume); (c) reflection into `ResolveRaidPoints`/`TryResolveRaidFaction` pre-body means parms is mutated before vanilla, and `TryResolveRaidFaction` result may differ from the one used later if re-resolved; (e) if the player closes the trade via Escape the Close callback still fires with unpaid = reject path (good); (f) `Find.AnyPlayerHomeMap ?? CurrentMap` fallbacks; (g) fee ignores whether colony is able to pay.
- **Save footprint**: only `WorldComponent_ProtectionFee.factionCooldowns` (int,int). Mod settings are a ModSettings file. Removal safe.
- **Reusable vs mod-specific**: reusable pattern: "incident interception": a Prefix on a worker's `TryExecuteWorker`, a re-entrancy flag plus re-calling `worker.TryExecute(parms)` to resume the original later (deferred execution via UI choice); a `ParmsOptions` dialog tree with quest linkage; sending the quest's end signals to resolve a quest without combat. Mod-specific: the sell-to-pay `ITrader` fake (heavy, nine supporting patches) and the demand-policy tables.
- **Wisdom for us**:
  - A choice dialog is better built INSIDE our own IncidentWorker (return true after queueing it, or return false and resume), not by patching a vanilla worker; and never return `true` while nothing happened: document it or return after the action resolves.
  - If we want a "pay tribute to avoid a raid", pay with an item-stack check (silver/goods the colony holds) via a simple dialog option rather than faking a trader; ~15 KB of trade plumbing is the cost of the sell UI.
  - Always keep the deferred-resume state on a saved component (store the IncidentParms-equivalent), never in statics, or a save during the dialog erases the raid.
  - Scarcity fits: fee = percent of item wealth with a floor; refusal raises points modestly (qualitative: more raiders) while paying has a double-cross risk.
  - For automated tests give a toggle that disables the interception so tests observe real pawns.

### 2.2 Faction Raid Cooldown (`mlie.factionraidcooldown`)

Engine checks: `IncidentWorker_RaidEnemy.FactionCanBeGroupSource` VERIFIED (RimSage): base check, hostile & not deactivated, earliestRaidDays, arrival-layer lists, any RaidStrategy usable; returns bool, so a Postfix forcing false cleanly removes the faction from candidate selection.
- **Player-facing situation**: killing a hostile faction's people buys a breather: that faction cannot be picked as a raid source while its cooldown is above 0. Optional readout on the Factions tab ("Raid Cooldown: 3 days", coloured). Nothing else visible.
- **Mechanism** (all in `src/frc/MURFactionRaidCooldown/`):
  - `HarmonyPatcher.cs`: `[StaticConstructorOnStartup]`, `new Harmony("rimworld.murmur.factionraidcooldown").PatchAll`.
  - `Faction_Notify_MemberDied.cs`: Postfix on `Faction.Notify_MemberDied`; if faction is in the store and `HostileTo(Faction.OfPlayer)` then `data[faction].ChangeHours(Settings.hoursPerDeath)`. Fires for ANY member death of that faction anywhere (not only killed by the player, not only raiders), so wild death/disease/infighting also pays out.
  - `IncidentWorker_RaidEnemy_FactionCanBeGroupSource.cs`: Postfix; `if (__result && data.ContainsKey(f) && data[f].CurrentCooldown() > 0) __result = false;`.
  - `FactionStorage : GameComponent`: `StartedNewGame`/`LoadedGame` -> `factionCheck()` registers every non-player, non-hidden faction (`FactionData.RegisterFaction`); `GameComponentTick` every 2500 ticks (1 hour) decrements each faction cooldown by 1 hour. Factions created later (quest/world events) are only registered on next load, so they never get a cooldown until then.
  - `FactionData : IExposable`: `Scribe_References faction`, `Scribe_Values cooldown` (in hours). `ChangeHours` clamps to [0, Settings.maxCooldown].
  - `FactionDataStorageComponent`: a STATIC Dictionary<Faction,FactionData> (global state, not on the GameComponent).
  - `FactionUIUtility_DrawFactionRow` Postfix: draws the cooldown line when `Settings.showCooldowns`; colour thresholds are inverted-looking (>=66% of max green, 33-66 blue, <33 red, though "green" means MORE protection).
- **Data knobs** (`Settings.cs`): `hoursPerDeath` 12 (key `extraHoursPerDeath`), `maxCooldown` 360 hours (15 days), `showCooldowns` false, `baseCooldown` 24 (saved, never read: dead setting).
- **Conditions checked**: only the cooldown > 0; hostility only checked at death time.
- **Fun vs annoying**: fun: kills have lasting strategic payoff, hostile factions "learn". Annoying/exploitable: farming cheap deaths (slaughtering a pirate camp, executing prisoners via Notify_MemberDied if it fires) can lock a faction out for 15 days; if every hostile faction is on cooldown the storyteller falls to other factions/mechanoids/infestation or no raid. Hidden mechanic unless the UI option is on.
- **Failure modes**: static dictionary persists across save loads in one session: `LoadedGame` does not clear it (only `StartedNewGame` does), and `Scribe_Collections.Look` with `forceSave true` rebuilds, usually fine but a stale reference can survive quitting-to-menu and loading a different save. Factions not registered until reload (above). UI patch's `drawn` counter is a static modulus hack that desyncs when rows are skipped. Does not touch `FactionCanBeGroupSource` for non-RaidEnemy workers (manhunters, quests, sieges that ignore it), so some attacks bypass it.
- **Save footprint**: GameComponent `factionDataDict` (Faction ref -> FactionData{faction, cooldown}). On removal: orphan GameComponent node is dropped harmlessly.
- **Reusable vs mod-specific**: reusable: "Postfix a boolean eligibility gate so a world-state number removes factions from selection" (non-invasive, no incident defs); per-faction counters on a GameComponent ticking hourly. Dross: static dictionary, UI row hack, dead baseCooldown.

#### Reusable patterns (deeper)
1. **Self-scheduled incident outside the storyteller** (`WorldComponent_MFI_AnnualExpo`): holds `occuringTick` (float, Scribed), and in `WorldComponentTick` calls `incident.Worker.TryExecute(StorytellerUtility.DefaultParmsNow(...))`; success adds `IntervalTicks` (60000 x 60 = 60 days), failure retries in 1 day. First firing is `2700000~3600000` ticks of absolute time. Incident's `BaseChanceThisGame` is 0 so the storyteller never picks it. Use for anything that must happen on a calendar (a once-a-season market, a festival).
2. **Faction interaction pacing outside the storyteller** (`MapComponent_GoodWillTrader`, added to every map): each non-hostile faction gets a Scribed `nextFactionInteraction` tick (`120000~480000` x setting). Every 531 ticks it checks; when due it picks a weighted incident from `allowedIncidentDefs` (spreading outpost, marriage, trade request, bumper crop, lodge, shaman, trader caravan), sets `parms.faction`, `forced`, and enqueues via `Find.Storyteller.incidentQueue.Add(def, tick+30000~180000, parms, 2500)`; next due time from `FactionInteractionTimeSeperator` curve on `PlayerGoodwill` (480000/300000/180000 ticks at goodwill 0/50/100 times a faction-count factor that floors at 10). Reflects into `incidentQueue.queuedIncidents` (Traverse) to prune entries that are stale/hostile. Pattern: "goodwill-curved per-faction timer" = a diplomacy heartbeat.
3. **World-object sites with a timeout and a caravan action**: `WorldObjectDef` with `WorldObjectCompProperties_Timeout`, class overriding `GetFloatMenuOptions(Caravan)` (adds `CaravanArrivalAction_*`), `Notify_CaravanArrived` to run the effect and `Find.WorldObjects.Remove(this)`. Instances: `AnnualExpo`, `MysticalShaman`, `FactionWarPeaceTalks`, `WorldObject_RoadConstruction`. The incident spawns it at a tile found by `TileFinder.TryFindNewSiteTile(min, max, ...)`, starts `TimeoutComp.StartTimeout(days*60000)`, and sends a standard letter with `LookTargets`. Best pawn is chosen via `BestCaravanPawnUtility.FindPawnWithBestStat(caravan, stat)` (Expo: relevantStat; Peace Talks: best diplomat; Shaman: `WorstCaravanPawnUtility.FindSickestPawn`).
4. **Real Site with custom map gen** (Hunters Lodge): `SitePartDef` (workerClass `SitePartWorker_MigratoryHerd`, tag `MigratoryHerd`, `requiresFaction`) + `GenStepDef` with `linkWithSite` (`GenStep_HuntersLodge` order 450; stock `GenStep_Power` 451) + `SymbolResolver`s (RuleDefs `huntersLodgeBase`, kitchen, indoors/outdoors division split/grid). `GenStep_HuntersLodge` gets `RectOfInterest`, tries four 36x36 rects around it, sets `ThingSetMakerParams` (value 200-500, nutrition 20-50) and pushes the symbol `huntersLodgeBase`. 5. **Faction dialogs**: `DiaNode`/`DiaOption` trees inside `Dialog_NodeTreeWithFactionInfo` (shows faction portrait/goodwill) or `Dialog_NodeTree`, with `linkLateBind` to compute an outcome AFTER the player clicks (Expo, Peace Talks); `ArchivedDialog` pushed to `Find.Archive` so the text can be re-read later; disabled option with reason `val.Disable(...)` when the colony lacks silver (`TradeUtility.ColonyHasEnoughSilver`, `NeedSilverLaunchable`).

- **Player-facing situation**: One of the anonymous raiders that survives a raid (reaches the map edge after the raid lost >=50% of its members) is silently promoted to a named "Rimesis" (letter "Rimesis_PromotedLabel", ThreatSmall). - **Mechanism (the scaling curve and the gen hook, end to end)**
  1. Trigger: player enters a settlement map -> vanilla map generation runs genSteps of `MapGeneratorDef` that includes GenStepDef `Settlement` -> patched genStep object is now `LargeFactionBase.GenStep_LargeFactionBase` (`src/lfb/LargeFactionBase/GenStep_LargeFactionBase.cs`, ~490 lines).

  3. **Time curve (all from `GenDate.DaysPassed`, `d`)**:
     - `n = (d/2)^0.45` (diminishing returns power curve). Turrets: `Rand.RangeInclusive(max(1, floor(n/1.5)), floor(n*1.5))` -> `edgeDefenseTurretsCount`. Mortars: `RangeInclusive(max(1, floor(n/2.5)), min(floor(n/1.5), 5))` -> `edgeDefenseMortarsCount` (hard cap 5). Computed by me: d=5 turrets 1-2, mortars 1; d=30 turrets 2-5, mortars 1-2; d=100 turrets 3-8, mortars 2-3; d=200 turrets 5-11, mortars 3-5.
     - Footprint: `getOutpostRect`: `size = floor(min(2, 1 + min(d,120)/300) * 48)` -> 48 cells at d=0 growing to 67 at d>=120 (saturates at 120 days; +40% area-edge). Four candidate rects (W/E/N/S of the rect of interest, offset by `size`), removes any not fully inside the map, picks one at random (falls back to the rect of interest if none fit).
     - Garrison points: `f_time = Max(Rand.Range((d/12)^0.36, (d/12)^0.3*0.6), 1)`; `f_diff = min(threatScale/2.2, 1)` (difficulty slider caps at 1, so only low difficulties reduce); `f_threat = 0.85 + 0.4*x^4/(1+x^4) * m` with `x = StatsRecord.numThreatBigs/20` and `m = min(|sin(d/10*(d/numThreatBigs)/21.2 + persistentRandomValue) * (sin(d/10 + persistentRandomValue/2)+1)|, 0.8)` (a pseudo-random wobble per world seed; saturating sigmoid so the player's *survived big threats* matter from ~10 on, up to +0.32). Final: `settlementPawnGroupPoints = FloatRange(1150,1600).RandomInRange * f_diff * f_time * f_threat` (default range lives in `SymbolResolver_Settlement2.DefaultPawnsPoints`, vs vanilla `SymbolResolver_Settlement.DefaultPawnsPoints`). - **Conditions checked**: faction tech level (turrets/mortars forced to 0 by `SymbolResolver_EdgeDefense2` if `techLevel < 4`... (Industrial = 4)); map must have room for rect (otherwise falls back); `Rand.Bool || techLevel>=4` for edge defence width; guards count default 0.

- **Fun vs annoying**: Fun: base difficulty is *tied to what the player has already survived* (`numThreatBigs`) and game age, so late settlements stay worth the trip; size growth makes sieges feel like campaigns; two-lord split gives a staged fight (calm half joins when the loud half dies); style variety (walls vs IED fields vs spikes) per tile, stable per world. Annoying: a pure power curve with no player-visible warning/scouting; IED rings + sniper/autocannon turrets can one-shot a small crew; 4000+ point garrisons at d=200 are unwinnable for a 3-8 pawn crew; the extra map size with 67-cell footprints can dominate a 250x250 map and stall load/AI; gore/prison props are tone-heavy (check `Rules_Indoors`).

- **Failure modes**: (1) Replaces the vanilla genStep wholesale -> loses vanilla `SettlementRect` map var, `minBuildings/minBarracks`, Empire throne/landing pad minimums, gravcore rooms, and `PostProcessSettlement`/`postProcessSettlementParams`, so Odyssey/Anomaly/Ideology features that rely on those (Empire thrones, Gravcore rooms, Distress call) may silently not appear; also hits quest-spawned settlements that use `GenStep_Settlement` only if they share GenStepDef `Settlement` (Odyssey `GravcoreLocations.xml` and Anomaly `DistressCall.xml` use their own GenStepDefs so are unaffected). (2) Two near-duplicate GenStep classes (`GenStep_LargeFactionBase` vs `...2`) and `*2/*3` copies of resolvers/lords: copy-paste maintenance risk. (3) Unpaused: nothing per tick (map-gen only), but `BaseGen` stack depth is large. (4) `DaysPassed` is game-age not settle-age: a colony that restarts on a late save sees day-100 bases at day 1 of the colony. (5) `RimWar_Large.xml` file name is misleading in 1.6; RimWar variant not active. (6) Persists nothing; trivially removable mid-save (existing maps keep their bases; unvisited settlements regenerate with vanilla gen).

- **Save footprint**: none of its own. No GameComponent/WorldComponent. Only `LordJob_DefendBase2/3.ExposeData` scribe `faction` and `baseCenter` for active lords in a generated map; removal after generation => loaded maps referencing the missing LordJob classes error (UNVERIFIED exact failure: lords with unknown LordJob class are dropped with a log error).

- **Reusable vs mod-specific**:
  Reusable: (A) "difficulty-from-history" curve: `power-law(days) * sigmoid(numThreatBigs) * persistentRandomValue wobble` (stable per world, no save data); (B) "replace the genStep via one PatchOperationReplace on GenStepDef" hook, with BaseGen symbols pushed in reverse; (C) split garrison into a calm lord and an alert lord with different `Trigger_PawnHarmed` thresholds; (D) cap stacks (mortars <=5, footprint saturates at 120 days).
  Dross: copy-pasted `*2/*3` resolvers, 30+ interior room variants, gore props, RimWar variant, power repair step.

- **Wisdom for us**:
  - If we want enemy places to age with the campaign, use `GenDate.DaysPassed` through a concave power curve (exponent ~0.45) + a *history* term (`StatsRecord.numThreatBigs` or our own counter) saturating via `x^4/(1+x^4)`; never linear, always capped (mortars 5, footprint 120 days).
  - For a tiny crew, scale by *qualitative* knobs (more cover, patrols, better turret kind, tripwire/IED fields) with a hard ceiling on points, not by raw pawn-points; the mod's 1150-1600 x up to 2.75 is exactly the stat inflation we reject.
  - Do not replace vanilla `GenStep_Settlement` wholesale: patch parameters (e.g. `ResolveParams.settlementPawnGroupPoints`, `edgeDefenseTurretsCount`) or append a second GenStep after it so vanilla map vars, rooms and post-processing survive.
  - Make the style (walls/IED/spikes) a pure function of tile + world seed so a revisit or reload is stable; keep per-world wobble seeded from `Find.World.info.persistentRandomValue`.
  - Two lords with different provocation thresholds is a cheap way to get a staged assault (tension without a script).
  - Give players a way to *read* the threat (scouting message, letter, or a descriptive label) since the mod gives none.

### 2.9 We Are United (`sl4vp0wer.weareunited`)

(Real packageId in About.xml is `Sl4vP0weR.WeAreUnited`; 1.6 ships `Assemblies/WeAreUnited.xml` docs only, source decompiled to `src/wau/WeAreUnited/`.)
- **Player-facing situation**: Right-click a non-colonist humanlike pawn with a colonist selected and a float-menu entry appears: "Ask to reunite" (target is a relative of the colonist) or "Ask to unite" (not related). The colonist walks over, both stand still 5 seconds with a progress bar, then a chance roll: mote "Convincing/Unconvincing {chance}" and message; success = the target is recruited exactly as a prisoner recruit. If a reason blocks it the entry is greyed with "Cannot ask X (reason)".
- **Mechanism** (end to end):
  - `Patches/PawnPatch.xml`: `PatchOperationAdd` of `<li Class="WeAreUnited.UniteComp_Properties"/>` into `Defs/ThingDef[@Name="BasePawn"]/comps` (every pawn race gets the comp). `UniteComp_Properties` has no fields (`UniteComp_Properties.cs`).
  - `UniteComp.CompFloatMenuOptions(Pawn selPawn)` (VERIFIED RimSage: `ThingWithComps.cs:655` iterates `comps[i].CompFloatMenuOptions(selPawn)` for float menu building and logs exceptions per comp) appends one `FloatMenuOption` from `GetMenuOption(selPawn, parentPawn)`: `JobValidator.TryMakeJob(recruiter, target)`; label key `WeAreUnited_FloatMenu` if `target.relations.RelatedPawns.Contains(recruiter)` else `WeAreUnited_FloatMenu_NotRelated`; priority `MenuOptionPriority` 4 (`DecoratePrioritizedTask`); action = `recruiter.jobs.TryTakeOrderedJob(job, JobTag.Misc)`. If no job but `JobFailReason.HaveReason`, shows disabled "CannotGenericWork" label with the reason; otherwise no entry (that is why the About says the option "sometimes doesn't appear").
  - `JobValidator.Validate()` (`JobValidator.cs`), all must hold: recruiter's `HomeFaction` is player and target's is NOT; recruiter not slave; target not slave unless currently in player faction; `Related` (recruiter.relations.RelatedPawns contains target) OR (`AllowNotRelated` AND target's home faction is null/`Faction.OfAncients`); target `CanReserve`; no enemy within `MinDistanceFromEnemy` (40) of target via `GenAI.EnemyIsNear`; both pass `ValidateCapable` (Talking capacity + social work not disabled, if `ValidateCapability`); `target.guest.Recruitable` OR `AllowLoyal` (else fail reason "Unrecruitable"); not `TrainableUtility.TrainedTooRecently(target)` (reason `WeAreUnited_TooRecently`); not `GenHostility.HostileTo(target, recruiter)`. Pre-filter `IsValid`: alive, not downed, humanlike, non-mechanoid. `JobFailReason.Is` is set in the `Result` constructor when a reason string is passed.
  - `JobDef AskPawnToUnite` (`Defs/Jobs.xml`): `driverClass WeAreUnited.JobDriver_AskToUnite`, reportString "convincing to unite.". Toils: `Toils_Interpersonal.GotoInteractablePosition(TargetIdx)` -> `Toils_General.Wait(WaitTicks=GenTicks.SecondsToTicks(5))` with progress bar and pre-init `ForceTargetToWait` (`PawnUtility.ForceWait(target, 300, actor)`) -> `TryRecruit` -> `Toils_Interpersonal.SetLastInteractTime` -> `EndJobWith(Succeeded)`. Reservation of target in `TryMakePreToilReservations`.
  - **Chance formula** (`JobDriver_AskToUnite`): `Factor = RelationsFactor + OpinionFactor + SkillFactor`, `Rand.Chance(Factor)` (clamped 0..1 by Rand.Chance).
    - `RelationsFactor = sum over PawnRelationUtility.GetRelations(Target, Actor) of (relation.importance / MaxImportance) * RelationsMultiplier`, where `MaxImportance` = the largest `importance` among ALL `PawnRelationDef`s (computed once, lazily via `MaxBy`; spouse in vanilla), `RelationsMultiplier` default 0.25. Several relations stack (e.g. cousin + ex-lover).
    - `OpinionFactor = Target.relations.OpinionOf(Actor) / 100f * OpinionMultiplier` (default 0.5); negative opinion SUBTRACTS.
    - `SkillFactor = Actor.skills.GetSkill(Social).Level / 20f * SkillMultiplier` (default 0.5).
    - Worked example: stranger, opinion +20, Social 10: 0 + 0.10 + 0.25 = 35%; spouse, opinion +60, Social 15: 0.25+0.30+0.375 = 92.5%.
  - `Recruit()`: if target is in a caravan -> `lord.Notify_PawnLost(PawnLostCondition 7)` + `caravan.RemovePawn`; `roping.DropRopes()`; then vanilla `InteractionWorker_RecruitAttempt.DoRecruit(Actor, Target, true)` (VERIFIED RimSage: calls `RecruitUtility.Recruit(recruitee, faction, recruiter)`, letter "LetterLabelMessageRecruitSuccess", `TaleDefOf.Recruited`, `PrisonersRecruited` record, `RecruitedMe` thought, quest signal `Recruited`).
- **Data knobs** (`ModSettings.cs`, scribed through custom Toggle/Numeric elements; keys = names): `ValidateCapability` true, `AllowNotRelated` true, `AllowLoyal` false, `MinDistanceFromEnemy` 40, `RelationsMultiplier` 0.25, `SkillMultiplier` 0.5, `OpinionMultiplier` 0.5. Constants: `WaitTicks` 300, `MaxOpinion` 100, `MaxSkillLevel` 20. No incident, no storyteller involvement at all.
- **Conditions checked**: see Validate list above — notably it NEVER works on a colonist's current prisoner-ness (no prisoner exclusion beyond HomeFaction), and works on any visiting/wild humanlike with no home faction.
- **Fun vs annoying**: Fun: a diegetic, readable social verb with a visible percentage, where relations/opinion/skill all matter (the "Convincing 35% chance" mote); rewards investing in a social specialist and in family ties; failure is cheap (cooldown only). Annoying: the option vanishes with no explanation when conditions fail silently (many `return false` branches have no reason); five-second repeated attempts with the vanilla "trained too recently" cooldown (an animal-training timer, an odd borrow); near-guaranteed recruit of any factionless wanderer by a high-Social pawn means it can be a free-companion exploit; unrelated asks are only allowed for homeless pawns, so factions' people are only recruitable if kin.
- **Failure modes**: (1) Adds a comp to EVERY pawn def via `BasePawn` (all animals included); the float menu builder runs `GetMenuOption` per pawn hover with `RelatedPawns.Contains` (a list scan) — fine at colony scale. (2) `MostImportantRelation` is a static cache of `MaxBy(importance)` across DefDatabase — a mod adding a relation def with higher importance silently rescales every chance. (3) `OpinionOf` can be hugely negative, making `Factor` negative (clamped to 0, never signalled). (4) The mote shows `Factor` unclamped (could print >100% or negative). (5) `TrainedTooRecently` keys off `mindState.lastAssignedInteractTime`, shared with animal training interactions — an interaction elsewhere blocks it. (6) `Result` struct constructor has a side effect (`JobFailReason.Is`), so validating twice overwrites reasons. (7) Recruiting out of a hostile `Lord` (raider group) is not handled except for caravans — the only lord handling is inside the caravan branch.
- **Save footprint**: None of its own beyond mod settings; adds a comp to pawn defs (comp has no saved state). Safe to remove mid-save apart from an in-flight `AskPawnToUnite` job (unknown JobDef / driver; vanilla clears bad jobs).
- **Reusable vs mod-specific**: Reusable pattern: *"ThingComp on the pawn offering a context float-menu verb -> validator that returns a reason string -> custom JobDriver with Goto / Wait-with-progress-bar / Do(roll) toils -> reuse the vanilla `DoRecruit` for the consequences"*. Also the additive, transparent probability formula and the "show the chance in a mote". Dross: relation-importance normalisation by global max, comp on BasePawn.
- **Wisdom for us**:
  - For a tiny crew, recruiting should be an *earned verb*, not an incident: expose the roll (show %), derive it from existing relations/opinion/skill, and reuse `InteractionWorker_RecruitAttempt.DoRecruit` so all vanilla consequences (letter, thought, tale, quest signal) come for free.
  - Always give a `JobFailReason` for every refusal — WAU's silent refusals are its worst UX.
  - Use a narrow Harmony or `FloatMenuOptionProvider` (1.6) instead of putting a comp on every pawn; and clamp/normalise any probability you also display.
  - Make the cooldown our own (a `GameComponent` dictionary pawn-id -> next-allowed-tick) rather than borrowing the animal-training timer.
  - Keep a rule like "target must be kin, or factionless" — it ties recruitment to narrative and stops mass poaching of faction pawns.

(About.xml packageId: `Mlie.SYRMoreSlaves`. Tiny mod: 1 C# class + 1 patch file.)

Nothing happens on screen otherwise; it is trader stock, not an event.

### 2.11 RM_Stranded (`mandrake.rm.strandedquest`) — our reference implementation

- **Player-facing situation.** "Pod down": a neighbouring settlement's transport broke up; one survivor

  reward; recruit, arrest or enslave them and that settlement hears about it.
- **Mechanism.** XML only: one `QuestScriptDef RM_Stranded` + one `HistoryEventDef
  RM_StrandedTravellerTaken` (the goodwill reason shown in the faction tab). Offered through the natural
  random quest pool (Randy's `RandomQuest` comps → `IncidentWorker_GiveQuest` →
  `NaturalRandomQuestChooser`). Node chain: `QuestNode_GetMap` → `QuestNode_GetNearbySettlement`
  (`storeAs settlement`, `storeFactionLeaderAs asker`, `storeCanCaravanAs canCaravan`,
  `maxTileDistance 32`) → `QuestNode_GetFactionOf` → `QuestNode_SubScript
  Util_GetDefaultRewardValueFromPoints` → `QuestNode_Set shelterTicks = randInt(6,10)*60000` →
  `QuestNode_GeneratePawn SpaceRefugee addToList lodgers` → `QuestNode_PawnsArrive RandomDrop
  joinPlayer=false` → `QuestNode_LeaveOnCleanup` → `QuestNode_Delay isQuestTimeout` emitting `PickupDue` →
  success siblings (Letter, GiveRewards, End Success) → one `QuestNode_Signal` per object signal
  (`lodgers.Recruited/.Enslaved/.Arrested/.Destroyed/.LeftMap`) each with its own letter and a priced
  `QuestNode_End` (goodwill −12/−20/−12/−6/none), plus `faction.BecameHostileToPlayer` and
  `map.MapRemoved` fail ends.
- **Knobs.** `rootSelectionWeight 0.6`, `rootMinPoints 0`, `rootMinProgressScore 3`, `minRefireDays 25`,
  `expireDaysRange 1~2`, `everAcceptableInSpace true`; goodwill amounts per branch; shelter 6-10 days.

  branch's possibility; the owner's open card (C07) decides which. NOT seen in game (offline-validated
  only, per its own header).
- **Reusable.** The whole shape: *asker + subject pawn list + shown timer + one priced End per object

### 2.12 Tribute Demand (`geojak.tributedemand`) — the KEEP we already chose for extortion

Studied as the counterpoint to Raid Protection Fee, because the plot-mechanisms wave picked it
(`design/Jawa/proposals/plot_mechanisms_wave.md` line 307) and the owner named it.

- **Situation.** A hostile faction's warband is at the edge and demands goods, animals, or a person.
  Give, and they leave; refuse, and the same warband attacks.
- **Mechanism.** One `IncidentDef TributeDemand_PirateExtortion` (`ThreatBig`, `Map_PlayerHome`,
  `pointsScaleable`, `baseChance 1.25`, `earliestDay 30`, `minRefireDays 15`, `minThreatPoints 300`,
  tale `TributeDemand`) with `TributeDemand.IncidentWorker_Extortion` (source ships in `Source/`). It
  runs the **raid pipeline by hand up to pawn generation** — resolve faction, strategy, arrival mode,
  `TryGenerateThreats`, age restriction, spawn centre, `IncidentWorker_Raid.AdjustedRaidPoints`,
  `PawnGroupMakerUtility.GeneratePawns` — then opens a `Dialog_NodeTreeWithFactionInfo` with Give/Fight
  and returns `true`. Give: demanded pawns are kidnapped by the faction (`faction.kidnapped.Kidnap`),
  items destroyed, attackers discarded to world pawns. Fight: `LongEventHandler.QueueLongEvent` →
  `arrivalMode.Worker.Arrive` + `raidStrategy.Worker.MakeLords` + a hand-built ThreatBig letter.
- **Demand roll.** Of `DemandWeight 1.8`: 0.15 colonist-or-prisoner (only if ≥2 free colonists), 0.15
  animals (up to 60% of them, priciest first), else items: 5-20% of colony value clamped to 300-35,000
  silver, chosen by weight `(value/mass)^2`, ignoring stacks under 50 and worn apparel under 500.
- **Fun.** The *same* pawns either leave or attack, so the choice is honest; the letter names the count.
- **Failure modes.** (1) Same structural flaw as Raid Protection Fee: the worker returns `true` while the
  outcome is still a dialog, so the incident is "fired" (cooldown stamped, debug/bridge sees success)
  even if no pawn ever spawns. (2) The pre-generated attackers live only in the dialog closure; they are
  not on the map, not saved. (The dialog force-pauses play but does not set `preventSave`, so a save can still capture this state; VERIFIED in the review.)
  (3) **It can demand a founder**: with our crew of six, 15% of extortions may ask for a colonist, who is
  then kidnapped. That is a strong beat for us (kidnap → rescue, and `Patch_ColonistKidnapped` in our
  OldFriends already records it) but it must be a deliberate choice, not an accident of a weight.
- **Reusable.** "Pre-generate the threat, show it, let the player choose, then either deliver or discard"
  is the best pattern in this whole set for *qualitative* danger: the player sees what is coming.

Every mod above, stripped of its specifics, is assembled from the same six blocks. Our own
incidents and quests should be assembled from them deliberately, choosing the cheapest
implementation of each.

**Choosing incident vs quest vs component.** A one-shot that happens *to* the player and
resolves in a minute: `IncidentDef` + worker. Anything with a shown timer, a person to protect,
several priced endings, or a reward: `QuestScriptDef` (signals and QuestParts handle cleanup and
save for free; see `skills/rimworld-quests`). Anything that must remember across months (a
grudge, a nemesis, a war state, a debt): one Scribed component that *feeds* incidents and quests
rather than replacing them.

**The single most valuable shape found** is Tribute Demand's: *pre-generate the threat → show it
to the player with a choice → deliver it or discard it.* It turns a raid into a decision, the
player sees exactly what is at stake, and nothing gets bigger. Our version must fix its one flaw
(returning `true` while the outcome is still a dialog; §4 trap 1) by holding the pending choice in a
`ChoiceLetter` subclass that Scribes its own fields, with a timeout whose `Removed()` applies the default
branch, generating the pawns only when they are about to spawn (`skills/rimworld-custom-incidents/references/recipes.md` §2).

## 4. Patterns to copy, traps to avoid

### Patterns to copy

1. **Pre-generate, show, choose, deliver-or-discard** (Tribute Demand). The qualitative-danger beat.
2. **Self-scheduled calendar incident** (MFI `WorldComponent_MFI_AnnualExpo`): `BaseChanceThisGame`
   0 so the storyteller never rolls it; a Scribed `occuringTick`; retry in a day on failure.
3. **Goodwill-curved per-faction heartbeat** (MFI `MapComponent_GoodWillTrader`): friends call
   more often than strangers; enqueue with a retry window rather than firing directly.
4. **Timed choice letter that re-opens itself on expiry** (MFI extortion): "decide or it decides for
   you", never a silent default.
5. **World object / Site with a timeout and a caravan arrival action** (MFI shaman/expo/peace talks;
   BI world infestation with `ExterminateBugsComp` paying goodwill on clearance). The right shape
   for a ship that travels: put a destination on the map instead of a pop-up that pays silver.
6. **State-flag storyline** (MFI war: unrest → war → only then the war incidents can fire). Lets a
   handful of small incidents read as an authored arc.
7. **Escalation by accumulated world state, not points** (BI Swarming Horde gates on 150 nest pawns
   and converts *existing* pawns into one assault lord). Visible, preventable, no inflation.
8. **Telegraph window** (BI tunnel spawner: a ticking placeholder Thing that becomes the threat).
9. **Threat disguised as a rescue** (Space Worms: vanilla refugee pod + a payload hediff; a cure that
   costs research and a risky surgery). One host, one clock, one decision.
10. **Promote on survival, remember, return the same Pawn** (Rimesis; §2.7 and the crew skill).
11. **Boolean-gate postfix** (FRC on `FactionCanBeGroupSource`): the least invasive way to let a
    world fact remove a faction from selection.
12. **Readable social verb with a shown chance and a reason for every refusal** (We Are United),
    ending in the vanilla consequence function (`DoRecruit`) so letters, thoughts and signals come
    free.
13. **Priced endings with a `HistoryEventDef` reason** (RM_Stranded): reputation as the currency.
14. **Two lords with different provocation thresholds** (LFB): a staged fight with no script.
15. **Zero-C# pacing** (Storyteller Enhanced): vanilla comp classes with new numbers; two
    `RandomMain` comps as two "moods"; `acceptPercentFactorPerThreatPointsCurve` to stop small
    threats once the colony is strong.
16. **Stable per-world randomness** (LFB style roll from tile × `persistentRandomValue`): a
    revisit or reload shows the same thing; no save data needed.

### Traps to avoid (each cost one of these mods)

1. 🔴 **Returning success before the outcome exists** (or `requireColonistsPresent` with the crew away, which returns true having done nothing) (RPF prefix `__result = true; return false`;
   TD returning `true` with a dialog open; BI Swarming Horde returning true with no pawn). The
   storyteller stamps the cooldown and resets the ThreatBig clock (`TryFire` → `StoryState.Notify_IncidentFired`), and a bridge or debug fire sees
   success with zero pawns. This is the 2026-10-10 live-pass defect.
2. 🔴 **Pending state in statics or closures** (a modal dialog pauses play but does not prevent saving) (RPF `OnRansomFinalize`, TD's attackers in a lambda,
   BI `accumPoints`, FRC's static dictionary, Space Worms' unsaved `iCounter` and `cause`): lost or
   stale across save/load or quit-to-menu. Scribe it on a component or resolve before the player
   can save.
3. **Worker instance fields between `CanFireNowSub` and `TryExecuteWorker`** (MFI): the worker is a
   shared singleton; another fire in between corrupts it. Pass state through `parms` or recompute. The
   same singleton caches `CanFireNowSub` per tick per def, not per target.
3a. **Bypassing the stamp** — `forced` fires and direct `Worker.TryExecute` calls set no cooldown and no
   ThreatBig clock; a queued incident with no retry window that fails is dropped without a log. Schedule
   through `TryFire` or the queue with a retry window; prefer `bypassStorytellerSettings` to `forced`.
4. **Global stat multipliers on hot paths** (STE `Thing.TakeDamage`, `Thought.MoodOffset`): stat
   inflation by definition, and a per-call cost on the busiest methods in the game.
5. **Mutating defs or the world at runtime** (MFI raises `TraderKindDef` stock forever, edits
   `ThoughtDef` stages, turns sites into settlements and plants squatter settlements on destroyed
   ones): on our hand-made frozen planet this is forbidden outright.
6. **Replacing a vanilla step wholesale** (LFB replaces `GenStep_Settlement` and loses
   `SettlementRect`, Empire thrones, gravcore rooms and post-processing; BI fully replaces
   `InfestationCellFinder.TryFindCell`): append or patch a parameter instead.
7. **A ban that names one def** (our `Infestation_PlanetwideBan.xml` zeroes Core `Infestation`;
   BI's `BI_InsectRaid`/`BI_SwarmingHorde` are other defs) and **a ban written as a generic-gate
   patch** (invisible to `forced`). Bans name every def that produces the effect.
8. **Joiners and people-sellers that skip population intent** (Space Worms' pod sets
   `populationEffect`, good; More Slaves drops `respectPopulationIntent`; RM_Stranded lacks
   `rootIncreasesPopulation`).
9. **Silent threats** (BI's `notificationInf` default false; Space Worms invisible until a Spacer
   research): a threat the player cannot read is a gotcha, not a decision.
10. **Counting the wrong event** (FRC pays out on every faction member's death anywhere).
11. **Unbounded growth** (Rimesis records never shrink; karma events cap 1,000,000; MFI trader
    stock). Every list has a cap and a prune rule.
12. **Heavy scans in gates** (BI whole-map cell scoring in `CanFireNowSub` and in queen think
    nodes; MFI enumerating world objects in `BaseChanceThisGame`).
13. **Two mods, one beat** (RPF and TD both extort). One owner per player-facing beat.
14. **Modal pop-ups as the loop** (MFI, RPF): fine as a rare beat, tiring as the main texture.

## 5. How it fits our rulings

- **Qualitative danger, never stat inflation** [`SCENARIO_BRIEF.md` §1 pillars]. Keep from the
  study: choice (TD), a face (Rimesis), a counter to the colony's real defences (Rimesis
  `ColonyDefenseProfile`), a telegraph (BI), a disguised host (Space Worms), staged defenders
  (LFB). Reject: LFB's day-scaled garrison points (to ~4,400 at day 200), STE's damage and mood
  multipliers, Rimesis' skill/gear ladder and ×1.5 retaliation points, RPF's points bonus for
  refusing, BI's unscaled 150-bug horde.
- **Small fixed crew, 3-8** [§1; card C07 open]. Every joiner path carries the population gate
  (§1, trap 8); recruitment, slave stock and the Stranded recruit branch become *settings* whose
  default the owner sets. Losing a founder (TD demand, kidnap) is a campaign beat with a rescue
  path, not an accident of a 15% weight.
- **Scarcity** [§1, §4 test 3]. Payment is in what is scarce here (water, fuel, ship parts, a
  crew member's time on a journey), not silver; MFI's silver-for-service dialogs are the
  counter-example.
- **Vanilla Randy** [`SCENARIO_SETTINGS_SPEC.md` R-S7 as cited in batch_04]. Custom pacing is
  added as comps patched into `StorytellerDef[defName="Randy"]/comps` or as our own components
  enqueuing into `incidentQueue`; no new storyteller. Whether STE's eight incident-category
  patches are wanted is the open C09 card; this study shows they are cheap to reproduce in our
  own patch if wanted.
- **One frozen hand-made planet; no worldgen** [`CLAUDE.md`]. Anything that creates, upgrades
  or replaces settlements or sites at random (MFI outposts and squatters, BI's world-gen hive
  seeding) is out. Authored sites that *exist* on the planet may carry timeouts, visit actions
  and completion comps.
- **OldFriends** (`mandrake.rm.raidredesigner`, `GameComponent_OldFriends`): already the
  remembering half of Rimesis — Scribed roster, cap 24, prune by notability, `KeepForever`
  pins released on eviction, eight capture hooks (kidnap, escape, fled raider, caravan robbed…).
  What Rimesis adds that OldFriends lacks is the *return*: eligibility + timer + the
  `GeneratePawns` injection + the history letter. That is the next build, and it should read
  the roster rather than duplicate it.
- **Tribute Demand** (KEEP, chosen over RPF): keep its pre-generate-and-choose shape; our own
  Hutt/Empire demands should be our worker in the same shape with the trap-1 fix, a scarce-goods
  demand list, and no founder in the demand pool unless the beat is meant.
- **Aftermath** (`mandrake.rm.aftermath`) already fires follow-ups with `forced = true`; it
  therefore ignores every generic gate (§1) **and stamps no cooldown or ThreatBig clock**, so Randy
  does not space around its follow-ups either. Its own rules must carry the cooldowns and bans it
  needs; `bypassStorytellerSettings` may suit some rules better than `forced`.
- **OldFriends and the pin-clearing trap (checked against its source).** `WorldPawns.RemovePawn` clears a
  pin whenever a world pawn is pulled out to spawn. OldFriends already re-pins on exit for the main case:
  `Patch_FledRaiderAndCaptain` postfixes `Pawn.ExitMap` and calls `RecordEncounter(..., pin: true)`, and
  `WorldPawnPinning.PinForever` correctly uses `ForcefullyKeptPawns.Add` for a pawn already in world pawns.
  The residual gap is a recorded pawn who leaves a map that hook skips (a non-home map such as a site, or a
  pawn whose faction is no longer hostile): he goes back in `Decide` mode while `PinnedByUs` still reads
  true. Worth a line in the return work (nemesis_lifecycle step 3), not a fix in this pass (src/ out of scope).
- **Superb Mod Settings** [`CLAUDE.md`]: every incident gets an on/off and its numbers; a test
  toggle that bypasses dialogs and RNG (RPF lacked one and broke our harness).
