## 2. Reader invariant (`src/RimMandrake/rimflow/model.py`)

- `model.read()` (no path) = `canonical_order(every file)`: identical events (canonical JSON)
  collapse; order is `(ts, tsn, subject id|name|system, VERB_RANK, seat, canonical JSON)` — file
  position and source file never enter it.
- **New field `tsn`** (ns wall clock, stamped by `append()`, added to `UNIVERSAL_FIELDS`). `ts` is
  to the second, and the first cut without `tsn` failed `selftest_cli`: a same-second `game UP` →
  `game DOWN` by one writer sorted DOWN-first by content. Only a content field can carry write order
  once position is meaningless, so new events carry one; older events (no `tsn`) fall to the
  content rules below, which reproduce their history exactly.
- `VERB_RANK` encodes one window's same-second causal order (file < spawn < block/unblock/needs <
  reassign/reclaim < claim < start < note < verify < close/drop/supersede; bridge released < taken).
  **Measured on the live ledger (13,825 events): identical projection to the old
  (ts, file rank, position) order** — every item's state/owner/blocked/sha, bridge, game, and the
  same 7 replay refusals. A first rank (reassign before unblock) did NOT match (2 items flipped);
  the shipped rank is the one that does. Locked in by `selftest_reader_invariant.py`
  (`t_real_ledger_projects_as_before`).
- **Why not "key by id":** an event's `id` is the ITEM id, shared by every event of that item, and
  `spawn` has no `id` at all. Identity is content. Measured: 0 identical duplicate lines today.
- **Concurrent claims:** `World.contested_claims` records a second `claim` landing while the item
  is held, within `CONTEST_WINDOW_S` = 1800 s of the holding claim (earliest ts wins — it is folded
  first). Without the window, 226 routine re-claims of long-held work would be reported; with it, 17
  historical races. `rimflow next` prints `CONTESTED CLAIM` for the seat's open items with a loss
  in the last 24 h, naming both timestamps (two windows of one seat sign identically, so the
  timestamp is how the loser recognises itself).

## 3. ledger_lint.py

`src/RimMandrake/Utils/ledger_lint.py` — MALFORMED, NO_NEWLINE, NOT_APPEND (a base line gone),
FROZEN (`events.jsonl` changed), DUP_DIFFERENT. Run by `run_selftests.py` via
`src/RimMandrake/Utils/selftest_ledger_lint.py` (unit cases + the real ledger vs origin/main), and
before every `git push` by `.claude/hooks/block_ledger_lint.py` (`--rev HEAD`, fails open on error;
registered in `.claude/settings.json` — fires only in sessions started after this lands).

**"Duplicate id with different content" had to be narrowed.** Literal item-id duplicates are every
item's normal history; even (seat, verb, subject, ts) collides legitimately — the owner wrote two
distinct same-second notes on one item twice in the last day (OWNER.jsonl). So DUP_DIFFERENT fires
only for a NEW line whose identity matches a line ALREADY ON THE BASE with different content — the
exact residue an edit-in-place leaves after a union (original + altered twin). Checked clean
against bases HEAD~200 and HEAD~1500; hook proven to deny an in-place edit and pass an append in a
scratch repo.
