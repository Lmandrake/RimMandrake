# The game-health record: metrics beyond TPS

The owner ruled **"Everything at once"** by question card on 2026-10-10. The design is option F from the combined
Opus design and GPT review: evidence first, in small steps, with nothing heavier going always-on until the TPS
full-list overhead test passes (`BRIDGE_TPS_REVIEW2_FIXES_1` MUST 17). The owner also ruled that **every metric must be
evaluable and removable later**. He will judge each one's worth and cost after the fact and switch off whatever does not
earn its keep. So every source has a stable id, its own switch, and a measured cost written into the record. The
metrics ledger below holds that judgement. A delegated judge ruled every row on 2026-11-25
(`HEALTH_METRICS_JUDGE_EARN_THEIR_KEEP`; evidence `design/RimMandrake/game_health_metric_census_2026-11-25.md`), and
the metrics ruled CUT were deleted. `python3 src/RimMandrake/Utils/health_ledger_verdicts.py check` proves that each
row has a verdict and that no CUT metric is left in the code.

The TPS record itself is `design/RimMandrake/tps_record.md`.

## Rules that bind every source

These come from the GPT review. A change that breaks one of them is a defect.

1. **Unavailable is never zero.** Each source reports `ok` (with a value), `unavailable` (with a reason), `failed`
   (with the error) or `off`. A reader prints the word, never `0`.
2. **No automatic mod blame.** Cost and attribution are separate questions. The readers print observations side by
   side and end with "no cause is established".
3. **Process-scoped counters are not reset at a game change.** Process CPU, log suppression and process memory
   accumulate across reloads, and that accumulation is what reload investigations look for.
4. **Merge histograms; never average p99s.** Keep the bucket definitions and their version with the data.
5. **Bulk artifacts go in separate capped files**, never in giant JSONL rows. The main stream holds only a reference.
6. **Label a coincidence as a coincidence.** For example `gcCountChangedDuringGap`, never `gcPauseMs`. A process at
   one core is a process total, not "the main thread spinning".
7. **The Verse.Log cap is 10,000 messages.** This comes from `StopLoggingAtMessageCount = 10000` in decompiled 1.6
   `Verse/Log.cs` (RimSage, 2026-10-10). Every Unity message counts toward it, via
   `Notify_MessageReceivedThreadedInternal`. At the cap the engine sets `Debug.unityLogger.logEnabled = false`. Only
   `Log.Clear` calls `ResetMessageCount`, which is what the debug log window's Clear button does. After the cap, the
   reader must say **"emission suppressed; error activity unknown"**. (`belt_watchdog.py` and a 2026-10-04 lesson both
   said 1,000. Both are corrected.)

## What is built

### 1. External observer (cut 2026-11-25)

`health_observer.py`, its eight sources (`obs.heartbeat`, `game.*`, `sys.memory`, `log.growth`, `log.milestones`) and
its readers (`tps_record.py --health`, `telemetry/ingest.py`, `modaudit/runtime.py`, `modaudit/memory_attribution.py`)
are deleted. It was never installed as a standing task, and its one live use was a full-list audit. The owner,
2026-11-24: "We should only have whatever the most modern tracker installed to monitor the situation, that's IT."
Private bytes now come from the companion's `context` rows (`health.session-check`). Git holds the code.

### 2. Offline forensics (cut 2026-11-25)

`health_forensics.py` (`load-tree`, `save-census`, `content-identity`) is deleted: no program read it, and it was not
used after its build. Git holds the code.

### 3. Standing health check per full-list session: `src/RimMandrake/Utils/game_health_check.py` (`HEALTH_CHECK_MONITOR_MEMORY_TPS_OVER_TIME`)

The owner's C24 (`design/RimMandrake/mod_audit/OWNER_RULINGS.md`): memory and TPS as a function of time are a standing
health check beside "is the game loadable right now?" and "how many errors are we producing in the log?", and "When it
goes worse, we should take it seriously and have hard conversations or debug why."

- **Record.** One row per finished full-list session (session row `mods` >= `full_list_min_mods`), appended to
  `D:\ClaudeWork\rimmandrake\game_health\history.jsonl` (outside git). ops_watch's `tps` family runs
  `game_health_check.py record` on every pass (a phase of `rm-metronome` since the `rm-ops-watch` unit was deleted
  2026-11-23), so no session is missed while that clock runs.
  A session without a shutdown row stays open until a newer session exists on disk or it has been silent 12 h (a hang
  or a machine sleep can recover); `history.jsonl.lock` keeps two recorders from appending the same session.
- **Row.** Load health (reached the menu, a game loaded, load seconds), end (clean shutdown or not), memory curves per
  10 min since the first game load with peak and Theil-Sen growth per hour (managed `heapMB`; private `privateMB`;
  Unity native `unityReservedMB`; GPU driver `gfxMB`), TPS (run-window ratio curve, median, first-vs-last decay at
  the dominant speed, stalls; long-event stalls are reported as `tps.longevent_max_s` and not judged) and log counts
  (`logErr`, `logWarn`, cap). A source a session does not carry is UNMEASURED with its reason.
- **In-game fields** (`JawaBenchSessionHealth.cs`, on every `context` row, once a minute, no hook): psapi private
  bytes and working set (Mono's `Process.WorkingSet64` read 0 on every full-list session 2026-10-26..28), the Unity
  Profiler totals, `upS` (process uptime, giving load seconds at the menu row), Verse.Log's message count and cap
  state, and error/warning entries counted from Verse.Log's own message queue: null until one scan succeeds, and
  `logErrLowerBound` (sticky) when the queue may have evicted entries unseen, and `logEvicted` (this scan's verdict). The owner split the judgment by card 2026-11-09 ("Two limits: load and play"): `log.load_messages` (cold load from the archived Player.log + the load-end scan's count, limit in game_health_thresholds.json) and `log.play_evicted` (an eviction or a 1,000+ rise after the load-end scan); the sticky flag is a fact, not a limit. A release player reads `gfxMB` 0, so GPU memory is UNMEASURED until another
  source exists. The archived Player.log is not used for error counts: it carries no stack traces, so a grep for
  `Verse.Log:Error` reads 0 on a log full of errors.
- **Threshold to debug.** `src/RimMandrake/Utils/game_health_thresholds.json` holds the limits, each with what it
  was set from. The newest row's `breaches` become `tps.health_breaches`; above 0 rings `OPS_GAME_HEALTH_DEBUG`
  through ops_watch's alarm filing. Agents may tighten or add a limit; loosening one is the owner's.
- **Read it.** `python3 src/RimMandrake/Utils/game_health_check.py report --curve` (sessions over time, then the
  newest session's curves). Live proof that the companion fields are populated: `game_health_check.py fields`.
