## 1. DEBUGGING

Static review only; no game assembly or validation script was executed. Line numbers are within the supplied files. Paths below are relative to `Source/`. Ratings are **severity / confidence**.

1. **Recession strands usable stock.** `RM_LiquidStock.cs:377`, `RM_StockMath.cs:150`. With capacity 5, unit cost 1, and recession enabled, a one-cell body supplies one level, leaving stock 4. `SupportedCells` returns zero, so its only source cell dries. The remaining four units cannot supply a canal, and displacement cannot return liquid through that now-dry cell. This applies when the fluid has a usable `recededTerrain`. **Minimal fix:** preserve a supplying cell while stock can afford one debit, or make recorded body outlets supply independently of their current terrain. **[high / high]**

2. **Legacy excavations can return after being filled in.** `RM_MapComponent_Excavation.cs:402`, `:843`. Terrain migration recovers depth but cannot recover the original terrain. Filling such a cell sets D to zero, while `RestoreOriginalTerrain` returns without replacing its channel terrain. If the map’s depth grid is then entirely zero, the next reload reconstructs the supposedly filled excavation from that terrain. **Minimal fix:** distinguish a missing legacy grid from an intentionally empty grid using a saved schema/migration flag; give legacy cells an explicit restoration policy. **[high / high]**

3. **Lake restoration can overwrite a newly dug excavation.** `RM_LiquidStock.cs:451`, `RM_MapComponent_Excavation.cs:835`. If a receded cell is dug before the body refills, `Restore` still pops that cell and writes its original water terrain. D remains nonzero, so terrain and excavation authority disagree. The shared original-terrain entry also serves two different operations: recession and digging. **Minimal fix:** skip or explicitly reconcile excavated cells during restoration, and keep recession restoration state separate from excavation restoration state. **[high / high]**

4. **An intact pit cover does not protect against drowning or poison.** `RM_PitFillEffects.cs:47`, `:62`. These checks use the pawn’s cell and underground F without checking `RM_PitCoverUtility.IsCovered`. A non-flying pawn walking over a covered, flooded pit receives drowning; poisonous fill also affects it. The shooting code explicitly treats that same cover as ground. **Minimal fix:** reject covered cells before applying immersion effects. **[high / high]**

5. **A drill discards extracted liquid when filling is refused.** `Drilling/Building_LiquidDrill.cs:131`, `:140`. The drill extracts reserve, subtracts pending units, then ignores `TrySetDriverFill`’s result. Disabling that fluid makes the driver API return false, so repeated cycles consume the underground reserve without adding liquid. **Minimal fix:** check fluid permission before extraction, and subtract pending units only after a successful fill. **[high / high]**

6. **The legacy flood and excavation engine still compete for the same temporary terrain.** `RM_MapComponent_Excavation.cs:1224`. `Flood_FlowWorks.PlaceFluid` writes temporary terrain without changing F. On a dry excavation, the next pulse sees F=0 and removes that terrain because its def belongs to the fluid. Conversely, temporary-terrain removal scheduled by the legacy flood can remove an engine-rendered fill. Def membership cannot identify which system owns a placement. **Minimal fix:** route releases into the grid through the driver API and retire their direct terrain/removal-queue writes on excavated cells. **[high / high]**

7. **Fill-in displacement bypasses closed sluices.** `RM_MapComponent_Excavation.cs:676`, `:745`. Its traversal accepts every excavated cell without consulting `SealsLiquid`. Filling a brimming cell can deposit liquid inside a shut sluice or push it into cells beyond the gate. **Minimal fix:** apply the same seal predicate to traversal and recipients, including the starting cell’s connection to its neighbours. **[high / high]**

8. **A sourceless, sinkless channel cannot redistribute between equal depths.** `RM_StockMath.cs:342`, `RM_FlowKernel.cs:421`. All source and sink hop values become zero; `MayFlowBetween` then permits only a deeper recipient. A pump-filled shallow channel therefore keeps liquid beside the pump instead of spreading along an otherwise empty shallow run. Equal-depth driver-filled and rain-filled components have the same limitation. **Minimal fix:** define an ordering for externally supplied components, or use a synchronous fill-balancing rule that prevents oscillation without forbidding equal-depth redistribution. **[high / high]**

9. **Visual bubbles consume gameplay randomness.** `RM_LiquidSurface.cs:519`, `:526`. Cell selection, bubble counts, positions, and sizes use `Rand`. The number of draws depends on the current map, camera view, liquid coverage, and visual settings. Discovery and fire also use `Rand`, so visual choices alter later gameplay rolls. **Minimal fix:** use an isolated cosmetic RNG or a deterministically seeded push/pop scope covering the entire bubble operation. **[medium / high]**

10. **A sealed sink still drains.** `RM_FlowKernel.cs:185`. Sink removal checks excavation and sink status but omits `IsSealed`; subsequent recipient and flow-order checks do honour the seal. A wet shut sluice in the sink band therefore loses liquid despite the declared “neither enters nor leaves” rule. **Minimal fix:** exclude sealed cells from sink drainage. **[medium / high]**

11. **The component cap creates permanent artificial flow barriers.** `RM_FlowKernel.cs:159`, `:421`. Capped BFS divides a connected excavation into separately resolved pieces. Non-source donors outside the current piece are rejected, so liquid cannot cross those partition boundaries. Sorted seeds reproduce the same partitions on later pulses. Processing the leftover seeds prevents starvation but does not restore connectivity. **Minimal fix:** retain cross-partition transfers or process one logical component over multiple bounded stages. **[medium / high]**

12. **Fluid-disable enforcement is confined to one input API.** `RM_MapComponent_Excavation.cs:1328`, `:1156`, `RM_FlowKernel.cs:230`. Driver filling checks `FluidAllowed`; natural-source transfers, rain, displacement, and legacy releases do not. The driver’s own comment promises that a disabled liquid never pours into a cut, but those writers can still introduce it. **Minimal fix:** centralize permission checks for new liquid input. Separately define whether existing liquid remains movable. The omitted settings UI’s advertised scope is **UNVERIFIABLE**. **[medium / high]**

13. **The driver API’s ownership contract is now false.** `RM_MapComponent_Excavation.cs:1304`, `:1328`. Its documentation says false means the engine does not own the cell and the client should retain its own behaviour. False also means “owned excavation, disabled fluid” or “owned excavation, foreign liquid.” A client following that contract can fall back to terrain writes on an engine-owned cell. Actual client behaviour is **UNVERIFIABLE**. **Minimal fix:** distinguish unsupported cells from refused transfers with a result enum, or require a separate ownership query before fallback. **[medium / high]**

14. **Queued ignition survives firefoam.** `RM_LiquidFire.cs:148`, `:211`. Smothering is checked when queued, but not when the queued event executes. The extinguishing route removes burning state without cancelling pending ignition; its Harmony postfix also skips an Extinguish blast when there are no burning cells, even if ignition is pending. A queued detonation can therefore ignite and blast after foam was applied. **Minimal fix:** cancel pending ignition on extinguishing and recheck smothering before `Ignite` or explosion generation. **[high / high]**

15. **Liquid-generated explosions can bypass source-fire reach.** `RM_LiquidFire.cs:223`, `:130`. Front propagation carries source-hop counts, but explosion notifications enqueue ignition with hops zero. A detonation’s own blast can consequently create fresh zero-hop seeds deeper in a body. Direct ignition also bypasses the documented “reach 0 means a source never lights” rule. **Minimal fix:** propagate ignition origin/hops through internally generated blasts and enforce source permission at every queue entry. **[medium / high]**

16. **An earlier ignition cannot advance an already queued cell.** `RM_LiquidFire.cs:155`. `pendingSet.Contains` discards every later offer, regardless of due time or hop count. A cell scheduled for a slow fuse remains scheduled for that slow arrival even when a direct flame or explosion reaches it now. **Minimal fix:** update an existing pending event when the new due time is earlier; preserve the appropriate reach information. **[medium / high]**

17. **Moved burn progress is lost on save and can contaminate unrelated later fires.** `RM_LiquidFire.cs:50`, `:250`. `carriedAcc` is intentionally unscribed. Reloading loses the progress retained after liquid leaves a burning cell. During uninterrupted play, those entries have no expiry or fluid identity; later ignition consumes progress from the cell and all four neighbours, even if the original liquid was pumped elsewhere or replaced. **Minimal fix:** carry progress through actual transfers, with fluid identity and persistence, rather than indefinitely caching it by nearby cell. **[medium / high]**

18. **Disabling the depth engine leaves fire producing harm without consuming fuel.** `RM_MapComponent_Excavation.cs:987`, `:1000`, `:1026`. Fire maintenance, heat, and pawn ignition continue before the depth-engine early return. Fuel consumption occurs only inside `DoPulse`, which no longer runs. **Minimal fix:** run burn accounting on an independent cadence, or explicitly disable/extinguish liquid fire with the engine. **[medium / high]**

19. **Exposure stops recovering when the final superdeep cell disappears.** `RM_MapComponent_Excavation.cs:990`. Exposure processing—including severity decay for sheltered pawns—is called only while `superdeepCellCount > 0`. Fill the last pit and existing exposure hediffs stop receiving this component’s recovery updates. **Minimal fix:** continue exposure processing while affected pawns exist, or make recovery an autonomous hediff comp. Whether XML supplies an additional recovery route is **UNVERIFIABLE**. **[medium / high]**

20. **Pump pouring selects a blocked recipient and never tries another.** `LiquidTypes/Building_LiquidPump.cs:178`, `:210`, `:221`. It picks the cell with most room before checking fluid compatibility. A foreign-liquid cell with more room blocks pouring into a compatible cell beside it. It also selects a tank before establishing whether that tank’s liquid has any usable outlet. **Minimal fix:** select a compatible tank/recipient pair; continue searching after a refused candidate. **[medium / high]**

21. **Attack-target filtering occurs too late to select another target.** `RM_Patch_SuperdeepShooting.cs:197`. The postfix turns an already selected forbidden target into null. It neither reruns selection nor lets the original search choose its next candidate. In fallback searches this can produce “no target” despite another acceptable target, and it provides no route towards a legal lip firing position. **Minimal fix:** compose the restriction into candidate validation; handle lip approach separately where required. **[medium / high]**

22. **Look application mutates cached materials without isolating looks.** `RM_LiquidLooks.cs:237`, `:242`. The graphic request contains texture, shader, colour, and render precedence, but no white-texture flag, mask, or flow parameters. Different looks producing the same graphic key then mutate its material differently. The saved “original” is only a graphic reference, so mutation can also undermine reverting. **Minimal fix:** give each applied look an owned graphic/material instance; never mutate a shared cached material. Exact current cache collisions are **UNVERIFIABLE** without the omitted defs. **[medium / medium]**

23. **Live look tuning does not invalidate the surface caches.** `RM_LiquidSurface.cs:134`, `:330`. The terrain-to-look table is built once, and procedural materials are cached by look object. `Tune` can change colour, sharpness, stretch, scale, or sheen without rebuilding those materials. Creating a new look after the table exists also leaves the table unaware of it. **Minimal fix:** expose explicit look-table and per-look material invalidation, called by tuning and relevant settings changes. **[medium / high]**

24. **Repeated look application leaks native materials.** `RM_LiquidLooks.cs:266`. Each water-look application allocates a new `Material`; replacement and reversion do not destroy the allocated instance. Repeated tuning or ApplyAll calls accumulate native allocations. Surface meshes and generated materials also lack visible disposal. **Minimal fix:** track owned resources and destroy them on replacement, reversion, and map disposal. **[medium / high]**

25. **Off-map ingestion loses reusable containers.** `LiquidTypes/IngestionOutcomeDoer_BottleResidue.cs:58`, `:67`. The doer returns when `MapHeld` is null and only attempts inventory insertion when the pawn is spawned. Thus its advertised caravan ingestion route cannot preserve residue for an ordinary off-map caravan pawn. **Minimal fix:** attempt inventory/holder insertion independently of map and spawned status; use map placement only as a fallback. **[medium / high]**

26. **A missing empty-container def duplicates tank contents.** `LiquidTypes/JobDriver_EmptyBottleIntoTank.cs:58`, `:66`. The tank is credited before checking the replacement empty def. If that def is absent, the carried filled container survives while its contents are already in the tank. **Minimal fix:** resolve and prepare the replacement before crediting the tank; make the exchange transactional. The shipped def pairing is **UNVERIFIABLE**. **[medium / high]**

27. **Missing saved tank identity can silently convert existing units.** `LiquidTypes/Building_LiquidTank.cs:46`, `:82`. A removed `LiquidDef` leaves `storedLiquid=null` but preserves `storedUnits`. The tank reads as empty, accepts another liquid, and assigns that identity to both the old orphan units and the new addition. **Minimal fix:** reconcile this state during PostLoadInit: quarantine it or clear it with an explicit loss report. **[medium / high]**

28. **Exactly-at-cap bodies are falsely classified as truncated.** `RM_FlowKernel.cs:469`. The walk sets `truncated=true` immediately upon collecting cell 4000, without proving another source cell remains. A completely explored, enclosed body of exactly 4000 cells therefore becomes limitless when sticky classification is enabled. **Minimal fix:** inspect for additional eligible cells before declaring truncation, or probe one cell beyond the retained footprint cap. **[medium / high]**

29. **Recession counts foreign bodies and does not guarantee connectedness.** `RM_LiquidStock.cs:410`, `:428`. Neighbour scoring counts any natural liquid, including another fluid/body. Furthermore, choosing the lowest-degree cell can remove a narrow connector between two denser lobes; degree is not a connectivity test. **Minimal fix:** count only active cells belonging to this body, and reject articulation-cell removal if non-fragmentation is required. **[medium / high]**

30. **The recession work limit does not bound its scan cost.** `RM_LiquidStock.cs:377`, `:410`. Each of up to 64 removals recomputes the centroid and scans the whole footprint, probing eight neighbours per candidate. A 4000-cell limited body can require millions of probes during one pulse; multiple bodies multiply that cost. **Minimal fix:** cache the centroid, maintain recession candidates incrementally, or budget candidate work across pulses. **[medium / high]**

31. **Overflow totals use the wrong unit.** `RM_MapComponent_Excavation.cs:788`. `NotifyOverflowDestroyed` describes and stores fill-volume units, but `ReportOverflow` passes a count of levels without multiplying by the displaced fluid’s `volumePerTile`. A level costing two stock units is reported as one destroyed fill-unit. **Minimal fix:** pass fluid identity and convert to volume units, or rename and consistently document the counter as levels. **[low / high]**

32. **Bubble density is inflated for small views and truncated for others.** `RM_LiquidSurface.cs:515`. Sixteen samples each represent `max(1, area/16)` cells. A one-cell view therefore represents sixteen cells; a 31-cell view represents sixteen. **Minimal fix:** use `sampleCount=min(16, area)` and floating-point `area/sampleCount`, adapting the math signature accordingly. **[low / high]**

## 2. LIKELY FUTURE COMPLICATIONS

- **Body topology will outgrow sticky footprint records.** `RM_LiquidStock.cs:124` returns an existing body without reconciling new connectivity. Terrain replacement, merged lakes, separated lakes, and another mod changing fluid terrain can leave ownership and physical geography disagreeing. Extra cells indexed through the existing-body branch at `:141` are not appended to the saved footprint, so those aliases disappear on reload.

- **Several settings are historical decisions, not live multipliers.** Body capacity/classification are captured during formation (`RM_LiquidStock.cs:154`); discovery budget is captured by `RM_DigDiscoveryState.Ensure`; subsurface yield is captured at map FinalizeInit. Changing settings affects newly formed state differently from existing state. The UI needs to disclose those scopes; otherwise players will interpret correct persistence as broken settings.

- **A byte palette is a campaign-lifetime ceiling.** `RM_MapComponent_Excavation.cs:240` silently returns key zero once the palette reaches 254 entries. Removed-fluid null entries remain in the palette. Large content packs and repeated campaign upgrades can exhaust it, causing unknown identity, permissive compatibility, or default-fluid conversion. Use a wider key or compact/remap the palette explicitly during migration.

- **Flow ordering is not fluid-specific.** `RM_FlowKernel.ComputeFlowOrder` seeds every supplying source, while donor compatibility is checked later. A foreign source can determine a water cell’s hop ordering even though it cannot supply that cell. Mixed-fluid networks need tests for stalls and gravity transfers around those boundaries.

- **Viscosity does not limit distance travelled within an eligible pulse.** `RM_FlowKernel.cs:230` permits a recipient to become a donor later in the same pulse. A level can traverse a long shallow run on one eligible pulse. Adding longer canals makes “ticks per tile” diverge further from actual front travel time.

- **Patch failure and patch composition need explicit handling.** `RM_Patch_SuperdeepShooting.cs:33` calls assembly-wide `PatchAll`; private-field access in `RM_PitExposure` initializes statically. Target drift or a field mismatch can disrupt startup patching. Another mod’s later postfix can also replace a restricted result. Audit exact signatures and installed patch owners, and report failed features individually.

- **Thread safety is absent if other mods introduce worker-thread calls.** Kernel scratch collections, discovery pools, map caches, and look dictionaries are mutable and unsynchronized. Unity material mutation additionally belongs on the main thread. No actual background caller is visible here, so an existing race is UNVERIFIABLE; document main-thread-only adapter APIs before parallel pathing/rendering integrations arrive.

- **Save validation needs semantic checks, not merely non-null collections.** Loaded grids are not reconciled for D outside 0–4, F>D, invalid palette indices, duplicate body cells, or receded cells outside their footprint. `EnsureGrids` silently replaces wrong-sized arrays. Future migrations should validate, explain repairs, and preserve recoverable data.

## 3. UNLEVERAGED OPPORTUNITIES

- **Make the offline suite test boundaries, not just arithmetic.** Cheap deterministic fixtures should cover: the five-unit one-cell pond; last-pit exposure recovery; filled-in legacy excavation reload; recession followed by digging; covered poisonous/drowning pits; rejected drill output; equal-depth pump-fed channels; closed-sluice displacement; queued ignition followed by foam; and a 6001-cell connected canal. Assert the resulting state, not merely a balanced ledger.

- **Add an adapter test layer.** The pure kernel cannot catch Scribe losses, terrain ownership, container exchanges, Harmony dispatch, or settings callbacks. An offline assembly/def-load check plus real Scribe round trips using old-save fixtures would cover those omissions. A small in-game smoke pass still needs to exercise movement, job completion, rooms, shooting, and rendering.

- **Expose a transfer API with explicit outcomes.** Replace ambiguous bool results with outcomes such as unsupported cell, disabled fluid, incompatible fluid, full destination, and successful transfer. Pumps, drills, containers, and external drivers could then share transactional withdrawal/deposit logic.

- **Extend the ledger across subsystems and fluids.** Existing counters can cheaply report body debits, grid additions, reserve extraction, tank transfers, rain input, burning, sinks, and overflow in consistent units. The current component ledger cannot identify many losses listed above.

- **Make settings explain their operational scope.** Mark controls as immediate, next pulse, new body only, or new map only. Show dependent controls as disabled with a reason, provide per-section resets, and display effective values. In particular, disclose the depth-engine/fire dependency and formation-time stock decisions.

- **Use existing discovery state to report failures honestly.** `RM_DigDiscoveryState.OnCut` spends budget before successful placement. Commit budget after placement or refund it on failure; distinguish a successful roll from a delivered find. The existing first-found set and debug report provide the necessary bookkeeping.

## 4. EXTENSIONS BEYOND THE MOD

- **Other flood mods need an ownership-aware contract.** FloodedCanyon and similar drivers should ask whether FlowWorks owns a cell before applying fallback terrain behaviour, then submit explicit additions/removals through the engine. Driver refusal must preserve excavation ownership.

- **Campaign logistics need one documented volume conversion.** Source stock uses `volumePerTile`, pumps use five tank units per level, and containers use material-dependent units. External pipe systems, converters, tankers, and recipes need a single conversion contract; otherwise individually balanced systems can create or destroy liquid when joined.

- **Thermal content should enter the existing temperature system.** Burning liquid already calls `GenTemperature.PushHeat`. Hot/cold fluids, baths, and industrial machinery should exchange heat through that same system, with exposure affecting vanilla heatstroke/hypothermia where appropriate. The omitted hot-liquid machinery’s compliance is UNVERIFIABLE.

- **Pit policy should be shared by campaign combat and movement content.** Pushes, teleports, flight, swimming, large creatures, custom verbs, and prisoner jobs need common cover, immersion, descent, and escape predicates. Patching one base verb or one path follower will not automatically cover every modded implementation.

- **D=4 must remain separate from sea-floor access.** The excavation grid represents local cell depth; it provides no visible authority for inter-map travel. Sea-floor content should instantiate or use these mechanics only after the campaign’s ship transition has delivered the pawn there. Whether omitted campaign systems currently enforce the ship-only rule is UNVERIFIABLE.
