- Every operation in Patches/Waterline_Lane1.xml is a PatchOperationConditional keyed to the target animal's own race/wildBiomes (or race, or the ThingDef itself, three-deep-guarded for the BMT_*/DA_LeviathanCrab defNames that ship with no wildBiomes container at all) — add-if-missing / replace-if-present, so it no-ops harmlessly on a mod list missing any of these defNames rather than logging or erroring.
- 13 ThingDefs get a Lake and an Ocean commonality: KwazelMaw, Mott, Dianoga, Dragonsnake, Fambaa, Fanback, Blixus (all Lake 0.6/Ocean 0.32 except KwazelMaw Lake 0.6/Ocean 0.32 and Mott Lake 0.67/Ocean 0.36 — Mott is the one outlier among the 7); BMT_MucklurkerCatfish (Lake 0.3/Ocean 0.16), BMT_TaintedTurtle (Lake 0.52/Ocean 0.28), BMT_MutatingTumorfishSpawn (Lake 0.3/Ocean 0.16), BMT_MutatingTumorfishFry (Lake 0.3/Ocean 0.16), BMT_MutatingTumorfishAdult (Lake 0.14/Ocean 0.07); DA_LeviathanCrab (Lake 0.38/Ocean 0.2, re-homed from the retired Megasquid's slot 2026-09-05).
- Megasquid (mlie.beastsoftherim) carries no operations in the current patch file and no modDependency — that mod was retired and this mod no longer needs it.
- 🔴 About.xml's description text (its 3rd paragraph) still claims this mod "zeroes KwazelMaw's ExtremeDesert 0.35 and Mott's LavaField 0.70 placement". The patch file itself does **not** do this — those two pairs of operations were removed 2026-08-31 (inline comment: BiomeCast_Ashkarr.xml already places KwazelMaw/ExtremeDesert and Mott/LavaField on the animal's own wildBiomes dict, and CommonalityOfAnimal throws ArgumentException on a second Add for the same (biome, animal) pair — confirmed via src/RimMandrake/Utils/biome_animal_conflicts.py). The walk below tests the patch file as it actually reads today; a check finding KwazelMaw's ExtremeDesert or Mott's LavaField commonality zeroed would mean the About.xml text somehow came back, not that the mod is working.
