## must be true
- Every patch operation in this mod is wrapped in `PatchOperationConditional`, `PatchOperationFindMod` or a `MayRequire` on the individual `<li>` — a load with any subset of the declared donor mods active produces zero red XML errors from this mod, by construction, never by luck.
- Three Core `BiomeDef`s (`Desert`, `ExtremeDesert`, `AridShrubland`) gain `SW_Sandstorm`/`SW_DrySandstorm` weather commonalities, and several third-party desert/volcanic biomes (`ZBiome_DesertOasis`, `ZBiome_Badlands`, `AB_PyroclasticConflagration`, `Volcano`) gain the same plus `SW_RedFog`/`SW_RedFoggyRain` — these are dictionary-keyed adds (`<SW_Sandstorm>8</SW_Sandstorm>`, NOT `<li>`), the exact shape `SWDesertWeather_Attach.xml`'s own header says a prior version got wrong and had to be rewritten after it silently discarded whole BiomeDefs.
- ~150 third-party weapon `ThingDef`s across many donor mods gain vanilla `weaponTags` (`WeaponTags_Renormalise.xml`, generator output, `weapon_tag_audit.py`) so that PawnKindDefs asking for cut vanilla tags (`SimpleGun`, `AssaultRifle`, etc.) still find real weapons instead of spawning pawns bare-handed — this file is regenerate-only-from-an-offline-dump, and a live/post-patch dump would silently delete entries on regeneration (its own header, in caps).
- Given `mandrake.rsw.starwarsraces` active: the Jawa xenotype used by the player pawnkind is forced to `RSW_MandrakeJawa` (never `RSW_RimMandrakeJawa`, the 24-gene generator-output sibling with the same "Jawa" label) via `JawaXenotype_Repoint.xml`; `RSW_MandrakeJawa`'s combat-incapacitating `Turn_Gene_Terrified` is swapped for a non-fainting `RSW_Jawa_Skittish` via `JawaCombatViability_Tuning.xml`; and three appearance fixes land (true-black `Skin_InkBlack`, no spider-eyes/fangs goblinoid head, orange/amber eye variety, a plain head gene, male-only) via `JawaAppearance_Tuning.xml`.
- Given `mandrake.rsw.starwarsraces` + KotOR content active: `RSW_Jawa` (the live Jawa PawnKindDef) is dressed in `guy762_Robes_jawa` + `guy762_JawaHood` with `apparelMoney 0` so no civilian clutter (jeans, surgical masks) can be added on top (`SpeciesStartingGear_Tuning.xml`); `Jawa_Spawn_Hutt` gets `apparelMoney 0` (Hutts wear nothing, deliberately); two new Gamorrean PawnKindDefs (`Jawa_Gamorrean_Guard`, `Jawa_Gamorrean_Enforcer`) spawn armed off real KotOR gear/weapon tags rather than bare-handed, closing a specific measured bug (`weapon_tag_audit.py`, 2026-08-19) where `HC_gamorreanaxe` was carried by no surviving weapon.
- `RSW_Xeno_Gamorrean`'s custom XenotypeDef (`GamorreanXenotype.xml`) is a fork of `guy762_xenotype_gamorrean` with two deliberate deviations from the donor: `Ears_Pig` added, `Headbone_MiniHorns` removed (commented, restorable by uncommenting one line).
- `Jawa_NamerPetSW` (`Jawa_PetNames.xml`, a 132-name RulePackDef, 2:1 lore:humour weighted `r_name(p=6)`/`r_name(p=3)`) repoints every ThingDef whose `race/nameGenerator` currently equals vanilla-donor `SWAnimalNamerMale`/`SWAnimalNamerFemale` (`PetNames_Ashkarr.xml`) — selection is BY EXISTING NAMER VALUE, not a def list, so it tracks whichever animal-donor mod supplies that namer.
