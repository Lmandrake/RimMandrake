## must be true
- `NoDroidManufacture.xml` clears `OuterRim_DroidFactory`'s `designationCategory` (removes
  it from the architect menu) and replaces its `description`, only when "Outer Rim - Droid
  Depot" is present (`PatchOperationFindMod`); recipes, repair and upgrading are untouched
  — the building has zero attached RecipeDefs, droid creation is driven entirely by its
  `CompProperties_AutoCrafter` in C#, so clearing the designation category is the only lever.
- `DroidsAreMachines.xml` sets `FleshTypeDef Asimov_Automaton`'s `isOrganic` to `false`
  (19 Outer Rim droid races) and `FleshTypeDef ABF_FleshType_Synstruct_Base`'s `isOrganic`
  to `false` (22 KotOR/Synstructs droid races), each behind `PatchOperationFindMod` +
  `PatchOperationConditional` (Replace if the field exists, Add if it doesn't — both
  frameworks leave `isOrganic` at its C# default and declare no XML node for it).
- `MegafaunaYield.xml` (generated by `Source/gen_megafauna_yield.py`, "Do not hand-edit")
  rewrites `statBases/MeatAmount` and `statBases/BoneAmount` to `unit * bodySize` (so the
  engine's own `StatPart_BodySize` multiply lands the final value at `unit * bodySize²`)
  for 424 unique defNames across 35 `PatchOperationFindMod` groups — including base-game
  and DLC animals (`Core`, `Biotech`, `Odyssey`, `Anomaly` groups) that need no third-party
  mod at all. `LeatherAmount` is deliberately left untouched (already linear in bodySize).
- `JawaDoctrineCoreMod`'s static constructor installs one Harmony instance
  (`"mandrake.jawadoctrine.core"`) and calls `DoctrinePatches.Apply`, which Harmony-postfixes
  `PawnComponentsUtility.CreateInitialComponents` to allocate `pawn.relations` for any
  Humanlike pawn whose `RaceProps.IsFlesh` is false — vanilla only allocates it when
  `IsFlesh` is true, and every droid patched non-organic by `DroidsAreMachines.xml` is
  Humanlike, so this closes DROIDWORKS_ISFLESH_RELATIONS_CRASH_1 (an NRE the moment anything
  reads `pawn.relations` on such a pawn).
- A failed patch install or a reflection miss on `CreateInitialComponents` logs an explicit
  `Log.Error` (quoted below) instead of crashing or failing silently.
